> Багатопроєктний генератор коду для **Spring Boot + Vue**: починаючи зі структури таблиць бази даних, він продукує **компільований, запусканий, готовий до меню та прав доступу** фронтенд- і бекенд-код бізнес-логіки, і забезпечує весь цикл доставки: запис на диск, резервне копіювання, ведення журналу та відкат.

GitHub: https://github.com/hustxia/CodeGen

## 1. Що це таке

CodeGen — це «керована таблицями» фабрика коду. Принесіть свої бізнес-таблиці (через імпорт бази даних або вставивши DDL), налаштуйте поля та перемикачі генерації, потім натисніть «Згенерувати» — він продукує бекенд Entity/Mapper/Service/Controller/DTO/VO, фронтенд `api.js` і сторінки Vue, меню та маршрути, навіть сторінки друку A4 і каркаси інтеграційних тестів, і безпечно записує їх у цільовий проєкт.

Це не просто «випльовування коду» — це **конвеєр доставки з контрольними воротами якості та можливістю відкату**:

```
Table intake (DB import / DDL)
   → Field & switch configuration (with AI recommendations)
      → One-click generation: self-check → backup → write to disk → compile/validate → register menu → rebuild routes
         → Ledger bookkeeping → rollback-capable
```

## 2. Хто користувачі та як вони використовують платформу
| Користувач | Типова потреба | Шлях, який пропонує платформа |
| --- | --- | --- |
| Бекенд-розробник | Є набір таблиць (або DDL) і потрібно швидко підняти CRUD | Сторінка конфігурації таблиць: імпорт → налаштування полів → генерація в один клік |
| Фулстек / незалежний розробник | Хочеться з нуля підняти цілу систему (з логіном, правами, словниками) | Сторінка конвеєра: побудуй систему одним реченням |
| Керівник команди | Хоче уніфікувати стиль коду, стандарти та структуру каталогів | Керування системою: одна система = одна конфігурація виводу, пакетне застосування |
| Супроводжувач платформи | Хоче змінювати шаблони, не чіпаючи код | Керування шаблонами: онлайн-редагування, збережене набуває чинності миттєво, підтримується відкат версій |

## 3. Які проблеми він вирішує

| Проблема | Що робить CodeGen |
| --- | --- |
| Пекло повторюваного CRUD — купа шаблонного коду для кожної таблиці | Перемикачі на рівні таблиці продукують повний фронтенд і бекенд в один клік, включно з CRUD, пагінацією, валідацією, імпортом/експортом |
| Невідповідності полів і API фронтенду/бекенду, що спричиняють нескінченні виправлення інтеграції | Ті самі метадані таблиці керують і бекенд-API, і фронтенд-сторінками — нульовий семантичний дрейф |
| Командні конвенції важко уніфікувати; у кожного свій стиль | Шаблони — це конвенція: 22 шаблони FreeMarker під централізованим керуванням, редагуються онлайн з відкатом версій |
| Генератори «перезаписують і втрачають» написану вручну логіку | Механізм злиття на основі маркерних блоків: рукописний код зберігається, замінюються лише згенеровані ділянки |
| Згенерований код не викликає довіри до моменту компіляції | Самоперевірка компіляцією в пам'яті (справжній `javac`), структурні перевірки контрактів, попередній перегляд відмінностей на диску — ніщо не потрапляє на диск, доки не скомпілюється |
| Створення нової системи з нуля забирає багато часу | Конвеєр «побудуй систему одним реченням»: створи БД → каркас → згенеруй → запакуй → зареєструй меню, повністю автоматизовано |

## 4. Ландшафт можливостей

- **Прийом таблиць**: розбір DDL, прямий імпорт бази даних, майстер пакетного прийому, автоматично виведена конфігурація стовпців (елементи керування / валідація / словники / зв'язки).
- **Форми таблиць**: одиночна таблиця, дерево-таблиця (дерево-API + дерево-сітка), головна-деталь (збереження в одній транзакції + вкладки деталей), з'єднувальні таблиці «багато-до-багатьох».
- **Згенеровані артефакти**: Entity / Mapper / Service / Controller / DTO / VO + `api.js` + сторінки Vue + сторінки друку A4 + каркаси інтеграційних тестів.
- **Покращення бізнес-логіки**: випадні списки зв'язків, переклад словників, маскування даних, перевірки унікальності, зв'язування форм, права доступу за обсягом даних, імпорт/експорт Excel, робочий процес затвердження, пакети можливостей оплати / файлів / мобільного.
- **Ворота якості**: самоперевірка компіляцією в пам'яті (справжній `javac`), структурні перевірки контрактів, перевірки узгодженості прав доступу, попередній перегляд відмінностей на диску, реальна валідація артефактів фронтенду.
- **Безпечне приземлення**: запис на диск + пакетні резервні копії `.gen-backup`, злиття маркерних блоків для збереження рукописного коду, чотиристановий журнал `gen_output` (створено / злито / пропущено / не вдалося), історичний відкат.
- **Ізоляція кількох систем**: кожен цільовий проєкт — це «конфігурація системи» (шляхи фронтенду/бекенду, імена пакетів, префікс шлюзу, клас-шлях залежностей, типові значення перемикачів генерації) — кілька проєктів обслуговуються паралельно.
- **Покращення штучним інтелектом**: побудуй систему одним реченням (AI-моделювання), AI-покращення початкових даних, рекомендована конфігурація на рівні таблиці (попередній перегляд відмінностей + застосування з відміткою).

## 5. Типові сценарії

| Сценарій | Опис |
| --- | --- |
| Дерево-таблиця | Ієрархічні дані, як-от категорії товарів — автоматично згенероване дерево-API, дерево-сітка та випадний список вибору батьківського елемента |
| CRUD одиночної таблиці | Клієнти, товари тощо — випадні списки зовнішніх ключів + переклад словників + імпорт/експорт з коробки |
| Головна-деталь | Замовлення продажу + позиції замовлення — збереження в одній транзакції, шухляда деталей із двома вкладками (інформація про головне / деталі) |
| Лише читання / статистика | Рух запасів тощо — перемикачі запису вимкнено, лише запит і експорт |
| Друк документів | Позначте перемикач «друк», щоб згенерувати сторінку друку A4 і маршрут із заголовком + таблицею деталей |
| Побудова системи одним реченням | Опишіть бізнес-домен — AI створює БД і таблиці + каркас + повну генерацію + реєстрацію меню за один раз |

> Для всіх сценаріїв є запускні демо (`demo_admin` проєкт) зі скріншотами — див. `docs/典型场景操作指南-演示后台demo.md` (китайською).

## 6. Основний робочий процес

```
┌─────────────┐   ┌───────────────────┐   ┌──────────────────────────────────────────────────┐
│ Table intake │ → │ Field/switch conf. │ → │ One-click generate (self-check→backup→write→     │ → │ Ledger · Rollback │
│              │   │                    │   │ compile→menu→route)                              │   │                   │
└─────────────┘   └───────────────────┘   └──────────────────────────────────────────────────┘
  DB import/DDL     controls/validation     Lands on disk only after all quality gates pass;      Batch-level traceability
                    /dictionaries           hand-written code is preserved
```

- **Попередній перегляд відмінностей**: згенеровані артефакти порівнюються файл за файлом із поточним станом на диску; ви підтверджуєте, перш ніж щось буде записано, уникаючи випадкових перезаписів.
- **Журнал генерації**: кожен файл фіксує свою дію, кількість байтів, MD5 і місце резервної копії; цілий пакет можна відкотити.

## 7. Побудуй систему одним реченням (Конвеєр)

Можливість високого рівня, спрямована на «створення бекенду з нуля». Після того, як ви опишете бізнес-домен, конвеєр автоматично просувається через 5 етапів:

| Етап | Значення |
| --- | --- |
| `CHECK` | Перевірити конфігурацію цільового проєкту та клас-шлях залежностей |
| `WRITE` | Створити базу даних і таблиці, записати каркас і згенеровані артефакти |
| `COMPILE` | Бекенд `mvn package` / збірка фронтенду, самоперевірка компіляцією в пам'яті |
| `MENU` | Згенерувати та зареєструвати права меню (два виходи: SQL артефакту / прямий внутрішній запис) |
| `ROUTE` | Перебудувати фрагменти маршрутів фронтенду |

Будь-який збій на етапі негайно переривається зі зрозумілою помилкою для легкого локатування.

## 8. Архітектура системи

Фронтенд і бекенд розділені, два репозиторії працюють разом:

| Репозиторій | Роль | Стек |
| --- | --- | --- |
| `codegen-server` | Бекенд: рушій генерації, шаблони, валідація, журнал, конвеєр | Java 21 · Spring Boot 3.2.5 · MyBatis-Plus 3.5.5 · FreeMarker · JWT · MySQL 8 · springdoc-openapi |
| `codegen-web` | Фронтенд: консоль (конфігурація таблиць / шаблони / журнал / керування системою) | Vue 2.7 · Element UI · axios · Vue Router (режим history) |

Шарування бекенду:

```
controller/    API layer (Gen* generation chain / Sys* system management / pipeline)
service/impl/  Core implementations (generation chain, template engine, merge, validation, pipeline execution)
util/          Template engine, model assembly, marker-block merge, self-check compilation
config/        Output config, self-check config, template seeder
common/        Result / BaseEntity / exceptions / audit
resources/gen-templates/   22 FreeMarker templates (backend / frontend / shared / test groups)
```

**Базові можливості, які має надати цільовий проєкт** (генератор продукує лише бізнес-код; відсутня база мовчки зазнає невдачі):

1. Плагін пагінації MyBatis-Plus (`PaginationInnerInterceptor`)
2. Базові класи, як-от `Result` / `BaseEntity` / `PageQuery` (префікс пакету має збігатися з `root-package`)
3. Фронтенд `utils/request.js` із `toPageData` (перетворює `Page{records,total}` у `{list,total}`)
4. Залежності `springdoc-openapi-starter-webmvc-ui` (згенерований код використовує `@Operation`) та `poi-ooxml` (Excel)

## 10. Швидкий старт

### 1. Створіть базу даних (13 платформних таблиць + обліковий запис за замовчуванням admin/admin123)

```bash
mysql -uroot -p -e "CREATE DATABASE gen_platform DEFAULT CHARSET utf8mb4;"
mysql -uroot -p gen_platform < docs/sql/V1.0__init.sql
```

### 2. Налаштуйте цільовий проєкт

Скопіюйте шаблон конфігурації та підкоригуйте під свої локальні шляхи:

```bash
cp src/main/resources/application-local.yml.example src/main/resources/application-local.yml
```

`application-local.yml` виключено з `.gitignore` і не буде закомічено. Ключові налаштування:

```yaml
gen:
  output:
    backend-root: /path/to/your-target-project      # write-to-disk base for artifacts
    frontend-root: /path/to/your-target-project
    frontend-path: demo-web                          # frontend subdirectory for monorepos
    backend-path: demo-server/src/main/java/com/demo
    package-name: com.demo
    root-package: com.demo                           # prefix for foundation-class imports in artifacts
  selfcheck:
    classpath: /path/to/your-target-project/demo-lib/*
```

Експортуйте каталог залежностей для самоперевірки так:

```bash
cd your-target/demo-server
mvn dependency:copy-dependencies -DoutputDirectory=../demo-lib
```

### 3. Запустіть бекенд

```bash
mvn package -DskipTests
java -jar target/codegen-server.jar
```

Служба за замовчуванням використовує порт **8120**; документація API за адресою `/swagger-ui/index.html`.

### 4. Запустіть фронтенд

```bash
cd ../codegen-web
npm install
npm run serve
```

Фронтенд за замовчуванням використовує порт **9530**, проксуючи `/dev-api` до бекенд-порту 8120. Обліковий запис за замовчуванням `admin / admin123`.

### 5. Ключові елементи конфігурації

| Налаштування | Опис |
| --- | --- |
| `gen.output.*` | Шляхи запису артефактів, імена пакетів, відображення модулів |
| `gen.selfcheck.classpath` | Клас-шлях залежностей для самоперевірки компіляцією в пам'яті, підтримує `dir/*` |
| `gen.menu.outlet` | `artifact` продукує лише SQL меню та фрагменти маршрутів; `internal` також записує власне `sys_menu` платформи |
