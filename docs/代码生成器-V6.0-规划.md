> 前置：V5.5 多模块工程生成收尾（契约用例 + S8 验证）先落地，本版在其产物结构上工作

**问题**：平台只会「从 0 建新」。V2/V3 时代生成的存量工程（demo-target、财务、人事等）配置不在库里或已漂移——升了生成器（打印页、多模块、级联删除）却**不敢对老工程重新生成**：不知道配置对不对、不知道哪些文件被人改过、覆盖了算谁的。

## 二、主题与理由

**主题：逆向工程——扫描存量工程反推配置，漂移检测，安全接管后重新吃到新模板能力。**

为什么是现在：

1. **推迟了三次的理由都消失了**。V3.1/V4.2/V4.5 三轮规划都把逆向排到「下一版」，理由分别是测试基建、台账、基线未稳——现在 92 例护栏 + 备份回滚 + 唯一实现全部就位。
2. **V6.0 编号早已预留**（V4.5 规划明文「逆向工程 V6.0 后再说」）。
3. **CLI 已被 pipeline 稀释**。原计划 V4.5 做的 CLI，其能力被 V5.0 流水线 9 步执行器内部实现，单独做 CLI 增量价值小。
4. 产品能力跃迁：V5.0 解决「新系统从 0 到 1」，逆向解决「存量从 1 到平台」——接管量越大，前面六个版本的基础设施回报越高。

## 三、范围

### P0-1 工程扫描器（只读，不写库）

扫目标工程目录（单模块/多模块都认，多模块按 V5.5 结构逐模块扫）：

- 识别 entity：`@TableName` 注解（缺失时按类名驼峰转下划线推导，标注「推导」置信度）
- 识别 mapper（xml + 接口）、controller（`@RequestMapping` 推导菜单路径）、service/serviceImpl
- 产出**候选表清单**：表名 / 类名 / 模块归属 / 已在 gen_table？（库中有记录则标记「已接管」）/ 置信度

验收：对 demo-target 实测扫描，候选清单与实际表集一致，零写库。

### P0-2 反推配置预览

对选中的候选表反推 gen_table / gen_table_column 配置：

- 字段来源优先级：`@TableField` → 实体字段名驼峰转下划线 → 数据库实际列（可连库时交叉验证）
- 复用 `importTables` 的预览 VO 形态：每张表列出反推出的列集，用户勾选后入库
- **不可反推的字段如实标空**（如字典绑定、查询开关），入库后走表配置弹窗人工补——逆向不做猜测性填充

验收：反推配置 + 人工补齐后，重新生成的产物与原工程结构一致（AC2）。

### P0-3 漂移检测

对已接管表：

- **模板漂移**：用当前配置重新渲染，与磁盘产物逐文件 md5 对比 → 「落后于当前模板」清单（如没有打印页、serviceImpl 还是旧单模板）
- **人工改动**：渲染产物 md5 ≠ 磁盘 md5 且不是模板原因 → 标「人改过」，**只报告不覆盖**
- 报告三类：`SAFE_TO_REGENERATE` / `HUMAN_EDITED` / `STRUCT_DRIFTED`（配置与磁盘的列集不一致）

验收：对一个被手工改过的 demo 文件，报告准确落到 HUMAN_EDITED；对未动过的落到 SAFE_TO_REGENERATE。

### P0-4 接管落库与重生成

- 勾选候选表 → 批量入 gen_table（`source='reverse'` 标记，与正向导入区分）→ 表配置弹窗补齐 → 正常 apply
- apply 走既有备份批次 + 台账 + 回滚，HUMAN_EDITED 文件默认 SKIPPED 不覆盖（用户显式 force 才覆盖）
- 系统级入口：系统列表行加「扫描接管」按钮（选 backendRoot → 扫描报告 → 勾选 → 导入）

### P1（本版尽力，不做门禁）

- 产物头注释写入生成器版本号（`@generated V6.0`），逆向扫描用它区分老版本产物，置信度更高
- 生成前自检标准列告警 + 非 id 主键支持（速查平台待办；模板 7 处 `getId()` 参数化）
- 打印合计行排除 ID 数值列的小瑕疵修复

### P2（明确不做，下版再说）

- 合并用户手改（three-way merge）——只报告
- 从代码反推前端路由/菜单配置
- 微服务设施（Nacos/gateway/Feign，V5.5 已留）
- V5.0 M2/M3（双进度条并行、全自动模式）

## 七、风险

1. **反推准确率**：老代码无 `@TableName`/注释缺失时只能推导，靠「置信度标注 + 不做猜测性填充 + 人工确认页」三道闸兜底，宁可让用户补也不猜错。
2. **漂移误报**：模板非确定性输出（时间戳注释之类）会造成假漂移——先审计现有模板确认无时间戳输出，有则在 P1 加版本注释时一并消除。
3. **接管边界**：扫描器只读、导入走确认页、覆盖走备份批次——三道防线保证逆向链路任何一步失败都不污染存量工程。
