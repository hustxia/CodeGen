## 一、表结构（平台库 gen_platform）

仅加 1 个系统级开关列，遵循三态可空约定（**NULL=关，绝不 NOT NULL DEFAULT**，否则回落层被杀死）：

```sql
-- docs/sql/V9.15__chart_enabled.sql（平台库 + schema-test.sql 同步）
ALTER TABLE sys_project ADD COLUMN chart_enabled tinyint DEFAULT NULL COMMENT '数据可视化图表 NULL/0=关 1=开';
```

生成侧 `gen_table` **不加列**：图表是工程级能力包，与 pay/mobile/file 一致（系统级开关，无表级开关）。每张表是否出图由列元数据自动推导。

产物库无需新表：聚合接口只读业务表，不新增统计表（避免口径漂移与数据同步负担）。

> 门禁：DDL 在 `gen_platform` 与 `gen_platform_test` 双库执行，`SELECT chart_enabled FROM sys_project LIMIT 1` 有返回。

## 二、回落唯一实现

`GenTemplateModel.resolveChart(Integer projectVal)`：
```
projectVal == null || projectVal == 0  → false（默认关，产物零 diff）
projectVal == 1                        → true
```
- 与 `resolvePay/resolveMobile/resolveFile` 同语义，放在同一工具类相邻位置。
- 调用点共 3 处，全部调它：模板模型 `renderShared` 开关、scaffold 注入判断、写盘文件清单计算（防「预览有、落盘无」历史事故）。
- `SysProjectServiceImpl` 三态 set 子句、`schema-test.sql`、**平台库 DDL** 三处同步加列。

### 3.1 推导规则（`GenChartDeriver`，纯函数，可单测）

| 列元数据条件 | 图表类型 | 接口参数 | 默认标题模板 |
|---|---|---|---|
| `hasEnum || hasDict` | `pie` | `metric=count&field=<javaField>` | `${commentLabel}分布` |
| `isDatetime || isDate` | `line` | `metric=count&field=<javaField>&range=30d` | `${commentLabel}趋势` |
| `isNumber && !isId` | `bar` | `metric=sum&field=<javaField>` | `${commentLabel}排行` |
| `status` 枚举列（默认约定） | `gauge` | `metric=count&field=status` | `办理状态` |

- 每表最多出 4 张图（pie/line/bar/gauge 各一），超过按列顺序截断，防看板爆炸。
- 无匹配列时只出 KPI（COUNT），F-06 空态兜底。
- 图标题取 `commentLabel`（已剥冒号/枚举后缀），不裸显 `xxxID`。

### 3.2 聚合接口契约（生成期固定 SQL）

```
GET /{table}/stats?metric=count&field=status&range=30d
```
- `field` 必须是该表生成期枚举出的合法列之一（模板内联 `Set.of(...)` 白名单），否则 400。
- `metric` 仅 `count|sum|avg` 三值；`sum/avg` 仅允许数值列。
- `range` 仅 `7d|30d|90d|365d|all`，日期列按 `DATE_FORMAT` 分组；大跨度拒绝。
- 返回 `{code, msg, data:{ labels:[], values:[], total: n }}`，Long 值按产物既有约定转字符串下发。

## 五、全局约束（每个任务都受它约束）

1. **开关默认关**：NULL/0 时产物与 V9.7 逐字节一致——基线测试用现有一场景跑 chart-off，diff 必须为 0。
2. **单一实现**：三态回落只 `resolveChart` 一处；路径只 `GenPathResolver` 一处；图推导只 `GenChartDeriver` 一处。禁止在模板里再写一遍判断。
3. **防注入**：SQL 表名/列名全部生成期固化进 Java 常量 + 白名单 Set；运行时只接收枚举值，绝不拼接用户输入。
4. **Long→字符串**：`data.labels/values` 中的 Long 用 `String.valueOf`，沿用 V6.4 教训（Map 里的 Long 不受 POJO 全局序列化配置覆盖）。
5. **try/catch 不静默吞**：前端图卡请求失败必须 `ElMessage.error` 提示，禁止空 catch（坑 75/78 直接教训）。
6. **ECharts 生命周期**：`ResizeObserver` + `dispose` 成对；`setOption(opt, true)` 全量替换；主题色走 `--app-primary`，不新增硬编码色值（产物主题审计约定）。
7. **模板双写**：classpath 的 ftl 改了，若 `gen_template` 库表有同名记录必须同步更新，否则生成仍读库版（历史坑）。
8. **commit 需用户同意**：本版为规划，S6/S7 实现与提交均待用户确认后执行。

> 核心命题：一套能力包服务所有生成系统。判据——**换一套异构业务系统，图表相关代码零改动**。
> 本章是「五、全局约束」在跨系统维度的展开；T1-T7 每个任务都受它约束。

### 6.1 七层通用性契约

| 层 | 通用机制（唯一实现） | 复用的现成设施 | 禁止 |
|---|---|---|---|
| 开关 | `sys_project.chart_enabled` 系统级三态，`resolveChart` | 同 `resolvePay/Mobile/File`（`GenTemplateModel.java:242-263`）；前端 `triStateDefs` 加一项 | 表级开关、按 `projectCode` 分支 |
| 推导 | `GenChartDeriver` 纯函数，输入列元数据 map | `GenTemplateModel.toModel()` 的 `isNumber/isDate/isDatetime/hasEnum/hasDict/enumJs/commentLabel/tableComment`（`:1244-1360`） | 领域关键词规则表（见 6.2） |
| 配色 | 系列色 = `var(--app-primary)` + `color-mix` 派生 N 档 | `scaffold/web/layout.vue:198-208` 的主色 token（单一占位符 `__THEME_COLOR__`） | 硬编码色值、手写渐变/阴影（见 6.3） |
| 路径 | 前端取数用 `${apiBase}` / `${apiRoot}` | `GenTemplateModel.build():427-439` 计算 + `GenPathResolver.moduleOfTpl/moduleRelPrefix` | 硬编码 `/api`、假设单模块 |
| 接口 | 每表统一 `/{table}/stats`，白名单生成期固化 | 与 `payApi.ftl` / `routerSnippet.ftl` 同构的 ftl 出口 | 为某表定制 Controller/SQL |
| 数据 | 通用边界（空表/无图列/slug 表名/Long 转字符串） | V9.18 坑 78 教训、`String.valueOf` 约定（§五.4） | 只对某套系统数据特判 |
| 验收 | ≥3 套异构系统实测 + 领域词零命中契约测试 | 现有 demo 产物（村务紫 / 警务蓝 / 仓储自定义色） | 只拿警务一套系统验收即宣称通用 |

### 6.2 反面案例：菜单分组的领域耦合（图表推导必须规避）

`GenMenuGroup.RULES`（`com/codegen/util/GenMenuGroup.java:35-91`）把 11 条警务规则（接处警 / 案件 / 治安 / 巡逻…）与仓储规则（出库 / 入库…）**硬编码在 Java 静态常量里**，按表注释/表名 `contains` 子串命中分组。这是为特定项目反复手工加规则形成的领域耦合——新增领域只能改代码重编译，注释自曝规则顺序是人工权衡（「警务域关键词必须整词优先」「出库必须在库存之前」）。

**图表推导绝不能复用这个模式**：`GenChartDeriver` 的输入只有列结构元数据（`javaType/htmlType/columnComment/dictType`），输出只有通用图元（pie/line/bar/gauge + count/sum/avg）。判断"这列出什么图"靠类型语义，不靠"这列是不是叫'警情'"。任意新行业模板克隆出的表，只要列类型正确就自动出图。

### 6.3 反面案例：换肤只通用了主色 token（图表不得重蹈）

现有 `layout.vue` 只有主色是 token（`--app-primary: __THEME_COLOR__`，浅深梯度用 `color-mix()` 实时推导），装饰色（渐变 `#60a5fa`、阴影 `rgba(37,99,235,.28)`、浅底 `#eff6ff`）仍是硬编码——警务从红换蓝时这些是手工改的。

图表能力包从一开始就把**所有系列色**做成 `var(--app-primary)` + `color-mix(in srgb, var(--app-primary) X%, white/black)` 分档，零硬编码色值。效果：任何系统改 `appThemeColor`，看板颜色自动跟随，不碰图表代码。纳入 §五.6 主题审计。

### 6.4 通用性护栏（写进 T2/T3/T5/T6 完成判据）

1. **领域词零命中契约测试**：对 `GenChartDeriver.java` / `chartStats.ftl` / `dashboardPage.ftl` / `ChartCard.vue` 源码 grep `警|村|仓储|订单|police|village|warehouse|<具体表名>`，命中数必须为 0；标题只来自 `commentLabel`/`tableComment` 变量。
2. **异构系统验收矩阵**：chart-on 对 ≥3 套不同主色、不同表结构的系统生成 + 打开看板（村务紫 / 警务蓝 / 仓储自定义色），断言 0 console error、四图渲染、系列色随主色变化。
3. **开关对所有系统零 diff**：chart-off 基线不只跑一套，至少两套系统产物与 V9.7 逐字节一致。
4. **无新增分支**：代码评审检查推导器与模板里没有 `projectCode.equals(...)` 之类系统特判。

### 6.5 P2 配置器阶段的通用性预留

演进到 F-09 拖拽配置器时，`gen_chart_config` 按 `project_id + table_name` 存配置——**配置属于某个系统的数据，不写进能力包代码**。图型/指标仍只用通用原语（pie/line/bar/gauge × count/sum/avg），禁止把"警情处置率"这类领域指标塞进生成器主干；确有领域指标需求，走行业模板随表结构克隆，不进能力包。
