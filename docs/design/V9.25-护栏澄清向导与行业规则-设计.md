## 一、表结构

DDL：`docs/sql/V9.25__guardrail_rule_clarify.sql`（幂等 `CREATE TABLE IF NOT EXISTS`，已在本地 gen_platform 执行）。

```sql
-- 1) 行业护栏规则：4 行业 × 7 条 = 28
CREATE TABLE IF NOT EXISTS gen_guardrail_rule (
  id            bigint       NOT NULL COMMENT '雪花ID',
  rule_code     varchar(32)  NOT NULL COMMENT '规则编码:GOV-B01',
  industry      varchar(32)  NOT NULL COMMENT 'gov_affairs/cm_city/agr_crop/park_park',
  category      varchar(20)  NOT NULL COMMENT 'BLACKLIST/WHITELIST/CONFLICT/BOUNDARY/CLARIFY',
  severity      varchar(16)  NOT NULL DEFAULT 'WARN' COMMENT 'BLOCK/WARN/INFO',
  trigger_type  varchar(20)  NOT NULL DEFAULT 'KEYWORD' COMMENT 'KEYWORD/MISSING/COMBO/ANSWER/CLARIFY',
  trigger_expr  varchar(512) NOT NULL DEFAULT '' COMMENT 'KEYWORD用|分隔;其余JSON',
  title         varchar(200) NOT NULL,
  reason        varchar(1000) NOT NULL DEFAULT '' COMMENT '为什么拦',
  suggestion    varchar(1000) NOT NULL DEFAULT '' COMMENT '怎么做才对',
  sort_no       int          NOT NULL DEFAULT 0,
  enabled       tinyint      NOT NULL DEFAULT 1,
  create_time   datetime     DEFAULT CURRENT_TIMESTAMP,
  update_time   datetime     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  create_by     bigint       DEFAULT NULL,
  update_by     bigint       DEFAULT NULL,
  deleted       tinyint      NOT NULL DEFAULT 0,
  PRIMARY KEY (id), UNIQUE KEY uk_guardrail_code (rule_code),
  KEY idx_guardrail_industry (industry, category, enabled)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='行业护栏规则(28条,可启停)';

-- 2) 问题库：4 通用 + 4 行业专属，向导取 4+1=5 问
CREATE TABLE IF NOT EXISTS gen_clarify_question (
  id            bigint       NOT NULL,
  question_code varchar(64)  NOT NULL COMMENT '答复幂等键',
  industry      varchar(32)  NOT NULL DEFAULT '' COMMENT '空串=通用',
  sort_no       int          NOT NULL DEFAULT 0,
  question      varchar(500) NOT NULL,
  options_json  varchar(1000) NOT NULL DEFAULT '',
  hint          varchar(500) NOT NULL DEFAULT '',
  enabled       tinyint      NOT NULL DEFAULT 1,
  [审计四列 + deleted] ...
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='澄清向导问题库';

-- 3) 会话：answers_json / hits_json / overridden_codes 全部留痕
CREATE TABLE IF NOT EXISTS gen_clarify_session (
  id               bigint NOT NULL,
  project_id       bigint NOT NULL,
  industry         varchar(32) NOT NULL,
  system_name      varchar(200) NOT NULL,
  system_desc      text,
  module_names     text COMMENT '候选模块JSON数组',
  answers_json     text COMMENT '{questionCode:answer}',
  hits_json        text COMMENT '命中记录JSON',
  overridden_codes varchar(1000) NOT NULL DEFAULT '',
  advanced_mode    tinyint NOT NULL DEFAULT 0,
  question_index   int NOT NULL DEFAULT 0,
  status           varchar(20) NOT NULL DEFAULT 'CLARIFYING',
  spec_id          bigint DEFAULT NULL,
  [审计四列 + deleted] ...
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='澄清向导会话';
```

**关键设计决定**：规则与问题是数据，判定引擎只解释 `trigger_type/trigger_expr` 四类表达式，不写任何行业业务词。改规则改 SQL 或页面，不改 Java。

## 二、功能设计

| 编号 | 功能点 | 页面/位置 | 字段与操作 | 状态流转 | 验收标准 |
|---|---|---|---|---|---|
| F-01 | 规则库列表 | 护栏规则页/上表 | 行业、类别、级别、触发条件、标题、建议、启停 | 启用↔停用 | 28 行；行业/类别筛选生效 |
| F-02 | 开始澄清 | 澄清向导页/Step1 | 项目、行业、系统名、描述、候选模块 | →CLARIFYING | 建会话并返回第 1 问 |
| F-03 | 一次一问答复 | 澄清向导页/对话区 | 问题、选项/自由文本、跳过 | question_index+1 | 同题重复答不推进；最多 5 问 |
| F-04 | 护栏检测 | 澄清向导页/右侧拦截区 | 系统名/描述/模块/答案 → 命中解释 | →READY | BLOCK/WARN 分类展示含"为什么拦+怎么做" |
| F-05 | 拦截修正/高级模式 | 澄清向导页/拦截卡片 | 修改答案重跑；高级模式勾选忽略 | overridden_codes 追加 | 有未处理 BLOCK 时确认按钮禁用 |
| F-06 | 确认写 SPEC | 澄清向导页/底部 | 确认按钮 | →CONFIRMED | SPEC 草案含"## 非目标"，重复确认幂等 |
| F-07 | 会话历史 | 澄清向导页/左侧列表 | 项目筛选、状态、问答数 | — | 列表可见演示会话 |

### 页面结构
- 澄清页：左栏会话列表（新建按钮）→ 中栏对话气泡（AI 问/我答，当前问题高亮）→ 右栏拦截记录（BLOCK 红/WARN 橙）→ 底部确认条
- 规则页：行业下拉 + 类别下拉 + 规则总数 28 + 表格（编码/行业/类别/级别/触发条件/标题/建议/启停）
- 表单校验：系统名必填、行业必选；答案跳过记「已跳过」不推进异常

## 三、接口设计

统一响应 `{code,msg,data}`，HTTP 恒 200；错误 body.code=400；雪花 ID 字符串下发；无 `/api` 前缀。

| 接口 | 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|---|
| F-01 规则列表 | GET | `/gen/guardrail/rules` | `?industry=&category=` | `List<GenGuardrailRule>` |
| F-01 规则计数 | GET | `/gen/guardrail/rules/count` | — | `{total, byIndustry, byCategory}` |
| F-04 独立检测 | POST | `/gen/guardrail/evaluate` | `{industry,systemName,systemDesc,moduleNames,answers}` | `GuardrailEvalVO` |
| F-02 开始澄清 | POST | `/gen/guardrail/clarify/start` | `{projectId,industry,systemName,systemDesc,moduleNames}` | `ClarifyStepVO` |
| F-03 答复 | POST | `/gen/guardrail/clarify/answer` | `{sessionId,questionCode,answer}` | `ClarifyStepVO` |
| F-04 会话检测 | POST | `/gen/guardrail/clarify/evaluate/{id}` | — | `GuardrailEvalVO` |
| F-06 确认写 SPEC | POST | `/gen/guardrail/clarify/confirm/{id}` | `{advancedMode,overriddenCodes}` | `{specId,specVersion,overridden}` |
| F-07 会话详情 | GET | `/gen/guardrail/clarify/{id}` | — | `GenClarifySession` |
| F-03 进度恢复 | GET | `/gen/guardrail/clarify/step/{id}` | — | `ClarifyStepVO`（会话 + 当前问题） |
| F-07 会话列表 | POST | `/gen/guardrail/clarify/sessions` | `{projectId}` | `List<GenClarifySession>` |

### 触发表达式契约（引擎只读这四类）

| trigger_type | trigger_expr 形式 | 命中条件 |
|---|---|---|
| KEYWORD | `词A\|词B\|词C` | 系统名+描述+模块文本包含任一关键词 |
| MISSING | `{"moduleKeyword":"事件中心"}` | 文本不含该关键词 |
| COMBO | `{"questionCode":"Q_DEVICE","answer":"含直连设备","keyword":"水肥\|灌溉"}` | 答复等于 answer 且文本含 keyword |
| ANSWER | `{"answerCode":"Q_MASTER","expect":"X"}` | 答复等于 expect |
| CLARIFY | 空 | 不参与检测，只提供问题 |
