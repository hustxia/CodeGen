# V9.26 代码生成器菜单按功能域重构 — 设计

## 一、背景与问题

菜单由两段拼接：后端 `/auth/routers` 下发 11 项（`/gen` 目录 7 子项 + `/system` 3 子项 + 监控/测试/验证），前端 `permission.js` 静态注入 11 个平铺入口。侧边栏近 20 项顶层无分组，且：

| 问题 | 实例 |
|---|---|
| 标题重名 | `/gen/project` 与 `/system` 都叫「系统管理」；`/gen/table` 与父目录 `/gen` 都叫「代码生成」 |
| 版本号入标题 | 「V9.5 AI 建表」 |
| 中英混杂 | 「MCP Server」 |
| 无功能分组 | 澄清向导 / 护栏规则 / 规格工件链 / 规格对账 四个 SDD 能力平铺 |
| allPaths 漂移 | 静态路径硬编码仅 6 条，漏 spec / converge / industry-pack 系列 |

## 二、规划原则（按系统功能相关）

按「从需求到交付」链路，把 18 个代码生成器入口归为 5 个功能目录：

1. **项目与数据**：项目管理、数据表管理、文案翻译
2. **规格与质量**（SDD / M2）：澄清向导、护栏规则、规格工件链、规格对账
3. **模板与范式**：代码模板、模板市场、模板影响面、行业范式（范式市场 / 范式安装 / 我的安装）
4. **生成作业**：一句话建系统、AI 智能建表、批量接管、生成台账
5. **集成服务**：MCP 服务

非代码生成器目录（系统管理 / 系统监控 / 测试中心 / 验证中心）保持后端下发结构不变。

## 三、命名规范

| 路径 | 原名 | 新名 |
|---|---|---|
| `/gen/project` | 系统管理 | 项目管理 |
| `/gen/table` | 代码生成 | 数据表管理 |
| `/gen/aibuild` | V9.5 AI 建表 | AI 智能建表 |
| `/gen/mcp` | MCP Server | MCP 服务 |
| `/gen/industry-pack` | 行业范式市场 | 范式市场（归入「行业范式」子目录） |

仅在前端覆盖展示名（`TITLE_OVERRIDES`），不改 `sys_menu` 数据；可选同步脚本见 `V9.26__menu_rename.sql`。

## 四、落地方式

`permission.js` 的 `generateRoutes`：

1. 拆出后端 `/gen` 目录子项，与 11 个静态入口合并成按 path 索引的 Map；
2. 按 `FUNCTION_GROUPS.order` 归类为 5 个 `type=1` 功能目录；后端新增但未登记的 `/gen` 子项保底挂到「项目与数据」，避免菜单丢失；
3. 「行业范式」作为 `type=1` 子目录，`buildRoutes` 自动摊平孙节点为绝对路径路由，`SidebarItem` 递归渲染三级；
4. `allPaths` 改为 `collectPaths(menus)` 自动生成，消除硬编码漂移；
5. 保留隐藏 `/gen` redirect 兼容老书签。

## 七、V9.26.1 修复：点击「行业范式」落 404

**现象**：侧边栏「模板与范式」flyout 里的「行业范式」点击后落到 404 页。此前 18 叶子走查全过却漏掉此问题——走查是**直接导航叶子 URL**，没有真实点击 flyout 链接。

**根因**：真正渲染侧边栏的是 `layout/index.vue` 的自定义 flyout（只支持两级），不是 `SidebarItem.vue`（遗留未使用）。`regroupMenus` 造的三级目录 `/gen-industry` 被 flyout 当作普通叶子渲染成 `<router-link :to="/gen-industry">`，但 `buildRoutes` 只把三级孙节点摊平挂到父路由，**从未注册 `/gen-industry` 路由** → 点击必落 404。另：三级叶子 `/gen/industry-pack*` 与父组 key `/gen-template` 不同源，导致访问叶子时一级组不高亮。

**修复**（仅前端两个文件）：
1. `layout/index.vue` `navItems`：flyout 子节点保留孙节点数组（`children`），模板用 `flyout-group-title`（不可点击的分组标题）+ `flyout-item-grand`（缩进子项）渲染三级；
2. `layout/index.vue` `isGroupActive`：分组记录 `leafPaths`（含三级叶子），叶子路径也能点亮一级组；
3. `permission.js` `buildRoutes`：三级目录补隐藏 redirect 路由（`path: child.path → 第一个孙节点`），直接访问 `/gen-industry` 或旧书签有兜底。

**验证（2026-11-28 实机）**：
- 复现脚本 `D:/workspace/tmp-v925/industry_404_repro.mjs` 修复前稳定复现 404（截图 `industry-404-before.png`）；
- 修复后 `industry_404_verify.mjs`：flyout 显示 `行业范式` 分组标题 + 3 个缩进子项，逐一点击 `范式市场 /gen/industry-pack`、`范式安装 /gen/industry-pack/install`、`我的范式安装 /gen/industry-pack/installed` 三个叶子 `is404:false`；直接访问 `/gen-industry` 自动 redirect 到 `/gen/industry-pack`；console/page errors 全零；截图 `industry-404-after.png` / `industry-flyout-after.png`；
- lint：`src/layout/index.vue` + `src/store/modules/permission.js` → No lint errors found。

## 九、V9.27.1：主题设置入口恢复（非代码缺陷）

**现象**：用户报"主题色切换又没有"——侧边栏系统管理下无「主题设置」，但主题引擎（`utils/theme.js`，240 套 = 24 色相 × 2 明暗 × 5 形态）、页面（`views/system/theme/index.vue`）、API（`api/theme.js`）、后端 `PUT /user/theme` 全部完好。
**根因**：本地库从未执行 `V4.0__user_theme.sql`。查库确认 `sys_menu` 只有 id=2000 父节点、缺 id=2040「主题设置」，而 `sys_role_menu` 里 `role_id=1,menu_id=2040` 授权仍在（孤儿授权）。后端 `/auth/routers` 按菜单表下发，故前端菜单静默少一项。组件映射 `require.context('@/views')` 自动收集，无需改前端。
**修复**：执行幂等脚本 `docs/sql/V4.0__user_theme.sql`，补 `sys_user.theme_id` 字段与菜单行。前端零改动。
**验证（2026-11-28 实机）**：
- `/auth/routers` 立即下发 `/system/theme`（系统管理 7 子项：主题设置/用户/角色/菜单/系统监控/测试中心/验证中心）。
- CDP 真实点击「主题设置」→ `/system/theme` 打开、`is404:false`、页面标题「主题设置 - CodeGen 平台」、console/page errors 零。
- 全链路实测：选绯红 → 保存成功（后端 `themeId=scarlet-light-rounded`）→ 重新登录 → 全站 `--cg-primary` 从 `#3d6df5` 变 `#ec5a3c`，侧边栏高亮/按钮/链接全部跟随，无残留蓝色（截图 `codegen-web/ui-theme-crimson.png`）。
- 测完已把 `sys_user.theme_id` 恢复为 NULL（默认蓝），不留副作用。
**注意**：主题切换设计为「保存后需重新登录生效」，点色相只局部预览、不立即改全站 —— 这是产品约定，不是 bug。已沉淀坑库 `mysql.md` N+6。
