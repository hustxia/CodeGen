## 4. 四个能力实现细节

### 4.1 横版（`print_landscape = 1`）

- `@media print { @page { size: A4 landscape; margin: 14mm 12mm; } }`（`printPage.ftl:632`）。
- 屏幕预览适配：工具条与 `.sheet` 宽度 794px → 1123px（A4 横向 297mm 等比），`.sheet` 最小高度 1000px → 794px（`:476,482-483`）。
- 默认仍为 portrait / 794px；字段网格、明细表、签名栏版式不变。

### 4.2 金额大写（`printRmb`）

- 判定唯一实现 `GenTemplateModel.isMoneyColumn`：**仅 BigDecimal** 且列名命中金额词表（amount/money/price/fee/total/…）或注释含金额词（金额/单价/总价/…）。刻意排除 Long/Double/Integer，避免把数量、编号误翻成人民币。
- 主表：`formColumns` 中每个金额列下补 `X大写：人民币{{ rmbUpper(master.X) }}`（`:71-74`）。
- 明细/孙表：`tfoot` 合计行下补大写行，取**最后一个金额列**的合计，复用 `colSum` 的「分」整数求和（`:120-123,171-174`）。
- 转换函数 `rmbUpper` / `rmbCore`（`:333-400`）为生成物内联纯 JS：字符串按位转「分」绕开万亿级浮点丢分，万进制四位分组，零角零分「整」收尾，超 `Number.MAX_SAFE_INTEGER` 返回空串。

### 4.3 print_title

- `${printTitle}` 替代 V4.5 的 `${comment}`（`:16`）。模型侧回落链：表级覆盖（trim + 空串归一）→ 表注释 → `className`。
- 覆盖范围仅打印页抬头；列表页标题、路由名不受影响。

### 4.4 条码 / 二维码

- **CODE128-B 真实实现**：`code128Bars` 生成条宽数组，SVG `<rect>` 绘制。START B=104，字符值 = `charCode - 32`，check digit = `(104 + Σ(i+1)·v) % 103`，STOP=106；图案宽度表 107 项（106 个 11 模块数据图案 + 13 模块 STOP），2px/模块，左右各 10 模块静区，底部回显原文。
- **二维码占位**：静态 `<svg>` 虚线框 + “QR” 字样 + `<div>{{ qrText }}</div>` 显示待编码内容，并在生成物中留 HTML 注释说明调用约定。
- 两键独立开关，可单开、可共存，共存时与金额大写函数同时内联互不干扰。

## 5. 条码 / 二维码方案取舍

| 方案 | 取舍 | 理由 |
|---|---|---|
| CODE128-B 纯 JS（107 项宽度表 + 校验位） | **采用** | 约 35 行逻辑 + 1 行数据表，无纠错分支，无第三方依赖；自校验保证结构正确 |
| SVG 画条（`<rect>`）而非 Canvas / 图片 | **采用** | 打印矢量清晰、`v-for` 数据驱动、无 DOM 外副作用 |
| 二维码纯 JS 极简 QR | **未采用** | 需 GF(256) Reed-Solomon 纠错 + 掩码评分 + 版本选择，约 800~1200 行；编码错误表现为「扫不出的码」而非编译错误，测试难拦截，与「代码量克制」冲突 |
| 引入 `qrcode` / `qrcode-generator` 依赖 | **未采用** | 破坏「A4 打印零第三方依赖」红线（V4.5 需求 §二） |
| 二维码 SVG 占位 + 接入说明 | **采用** | 保留渲染位与内容取数口径，将来替换为 `buildQr()` 生成的 `<rect>` 矩阵即可，模板其余部分零改动 |

条码内容仅支持 ASCII 32~126：业务单号/编号走英文数字；含中文时函数返回 `null`，条码区自动隐藏（不输出错码）。

## 6. 零 diff 契约与验证方法

1. **打印能力关闭**：`genPrint` 无效 → 引擎根本不挂 `printPage`，模板改动对产物零影响。
2. **默认配置**：`printLandscape=0`、`printTitle` 空、`printRmb=false`、无 `printBarcode`/`printQr` → 所有新增块被守卫裁掉，且空行已对齐，产物与已提交 V4.5 基线逐字节一致。
3. **本批验证方式（未跑 mvn）**：
   - 用独立 FreeMarker 2.3.32 渲染器（严格模式）对同一模型分别渲染当前模板与 `git show HEAD:.../printPage.ftl` 导出的 V4.5 基线模板，`String.equals` 比对通过；
   - 双向断言：默认无 `landscape` / `rmbUpper` / `CODE128` / `qr-svg`；开横版有 `@page ... landscape` 且无 `portrait`；开条码有宽度表、`<rect v-for>`、取数调用；开二维码有占位 SVG；
   - Node 对渲染产物中真实内嵌的 `code128Bars` 做算法冒烟：表长 107、数据图案各 11 模块、STOP 13 模块、`12345678` 宽 286px / 34 条、非 ASCII 返回 null、校验位复算模块数 123，全部通过。
4. **中央验证建议**：`mvn -o test`（V917PrintEnhanceTest + 基线 52 份 + 契约 `printPageContainsA4Layout`）、preview/落盘路径集合 diff、print-to-pdf A4 MediaBox 断言。

## 7. 示例

默认（竖版、无码）：

```html
<div class="doc-title">测试单据</div>
...
@page { size: A4 portrait; margin: 14mm 12mm; }
```

开横版 + 标题覆盖 + 条码（`printTitle=销售出库单`、`print_landscape=1`、`printBarcode=orderNo`）：

```html
<div class="doc-title">销售出库单</div>
<div class="code-zone">
  <div class="code-item">
    <div class="code-cap">条码（CODE128-B）</div>
    <svg class="barcode-svg" :viewBox="'0 0 ' + barcodeWidth + ' 48'">
      <rect v-for="(b, i) in barcodeBars" :key="i" :x="b.x" y="0" :width="b.w" height="34" fill="#000"></rect>
      <text :x="barcodeWidth / 2" y="45" text-anchor="middle">{{ barcodeText }}</text>
    </svg>
  </div>
</div>
...
@page { size: A4 landscape; margin: 14mm 12mm; }
```

金额大写（明细含 BigDecimal 金额列）：

```html
<tr class="rmb-row">
  <td colspan="4" class="rmb-cell">金额大写：人民币{{ rmbUpper(colSum('demoOrderItem', 'feeAmount')) }}</td>
</tr>
```

## 8. 未尽事项与风险

- `printBarcode` / `printQr` 的 DB 列与模型接线不在本批文件白名单内；模板侧守卫已就绪，未接线前两能力不会出现在任何产物中（这是刻意的安全缺省）。
- 二维码为占位实现，不可扫码；文档已写明替换入口与约束。
- `isMoneyColumn` 只认 BigDecimal：Long 型金额列（如支付基线 `total_amount`）不生成大写行，属既定取舍。
- CODE128-B 不支持中文内容与超过 ASCII 126 的字符；条码区在数据不合规时自动隐藏，不会输出错误条码。
- 本批未跑 mvn（中央统一验证）；独立渲染/算法校验使用 FreeMarker 2.3.32 严格模式与 Node 22，结论见 §6。
