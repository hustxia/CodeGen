# 三仓库整体流量增长方案（Gitee + GitHub）

> 制定日期：2026-11-23。基于实测数据制定，每条建议都可追溯到数据依据。
> 核心判断：**不缺流量来源，缺「承接结构」**——CSDN 每周有几百阅读、14 天 286 人克隆，但 star 0、Gitee 长期没人看。

## 一、仓库定位与用力分配（先定战略再动手）

| 仓库 | 定位 | 资源分配 | 理由 |
|---|---|---|---|
| GitHub `hustxia/CodeGen` | **旗舰**（唯一主推） | 70% | 有 286 克隆者/14 天、Pages 演示、CI 徽章、V9.15 看板，是唯一有转化潜力的仓库 |
| Gitee `hustxiayuhong/CodeGen` | **国内快车道**（镜像+承接） | 20% | CSDN 读者是国内流量，GitHub 无代理时克隆慢；Gitee 负责接住被速度劝退的人 |
| Gitee `code-survivor-frontend` | 配套（跟随旗舰） | 10% | 独立引流价值低，保持与后端同步、README 可看即可 |
| joy-collection-mall | 案例素材 | 0%（不单独推） | 只在文章里当「生成器产物案例」引用，反向为旗舰导流 |

**原则：所有动作最终都把流量导向 CodeGen 的在线演示页或仓库页，不分散火力。**

## 二、当前资产盘点（方案的地基）

已有（做完不再动）：
- CSDN 20 篇文章、总阅读 7,719，唯一有量的渠道，发文日 = GitHub 浏览峰（实测强相关）
- 286 个克隆者（14 天），GitHub 侧 star 转化 0%，钩子已埋（启动 banner、verify 提示）
- 在线演示 `hustxia.github.io/CodeGen/`（国内可直连），首屏加载 9.6s 偏慢
- HelloGitHub 投稿 #4439、#4462 等待月度收录
- 每日 9 点自动复盘（GitHub+CSDN 数据对比、断点检查、3 个当日动作）
- 文章钩子模板（GitHub + Gitee 双链接 + 国内 clone 命令）

缺口（方案要补的）：
- Gitee 两仓库描述含错别字/太弱、homepage 空（需网页手动改）
- CSDN 20 篇旧文没有钩子（star 引导和 Gitee 链接都没挂）
- 演示页加载慢，首屏体验劝退
- 除 CSDN 外零渠道：掘金/V2EX/知乎/OSChina 全空白
- Gitee dev 旧分支未删、Gitee Insights 流量数据无人看
