# V9.15 数据可视化图表——需求

> 版本：v1.0　日期：2026-11-22　提出人：用户（WorkBuddy 对话）　规划人：WorkBuddy

## 背景与目标

代码生成器 V2.1 起有主子表、V4.5 有打印、V6.6 有文件能力包，但**生成出来的系统没有真正的数据可视化**：

- 模板目录 22 个 ftl，无任何 chart/dashboard/ECharts 痕迹；产物首页要么是脚手架占位，要么是各系统人工手写的静态 SVG/CSS（智慧警务 `views/index.vue` 就是手写折线 + CSS 环形图，后端无对应统计接口）。
- 枚举列、日期列、数值列的元数据其实已经在模板模型里（`isNumber/isDate/isDatetime/hasEnum/hasDict/enumJs`），却只用于表单控件和表格显示，没有用于图表推导。
- 结果：每个新系统上线后都要人工补一遍看板，重复劳动、口径不一，且常见「前端拉全量数据在浏览器聚合」的性能坑。

V9.15 的目标：**把数据可视化做成生成器的一个能力包**——开启后自动生成「能跑的看板页面 + 后端聚合接口 + 图表组件」，零配置开箱即用；列元数据推导图表，口径在生成期固化，不靠运行时拼 SQL。

## 通用性目标（跨系统硬约束）

V9.15 是**生成器能力包**，不是某一个业务系统的看板。通用性判据只有一条：**换一套完全不同的业务系统（村务 / 仓储 / ERP / 任意行业模板），图表能力代码零改动即可工作**。任何"为某系统写死"的实现都算不合格。

| 维度 | 通用性要求 | 不合格反例（必须避免） |
|---|---|---|
| 开关 | 系统级三态开关，所有系统同有；默认关 → 产物零 diff | 按 `projectCode` 判断只对某系统生效 |
| 推导 | 只依赖列元数据（类型 / 日期 / 枚举 / 注释），代码零领域词 | 抄 `GenMenuGroup` 的"接处警 / 出库"关键词规则表 |
| 配色 | 只消费 `--app-primary` + color-mix 派生，换肤自动跟随 | 写死 `#2563eb` 或装饰色硬编码（警务红换蓝手工改色教训） |
| 路径 | 沿用 `${apiBase}` / `${apiRoot}`，交给 `GenPathResolver` | 硬编码 `/api`、假设单模块 |
| 接口 | `/{table}/stats` 契约对所有表一致，白名单生成期固化 | 为某表写专用 SQL / 专用 Controller |
| 标题 | 只用 `commentLabel` / `tableComment` 动态生成 | 写死"接处警趋势""库存排行"等中文业务词 |
| 边界 | 空表 / 无图列 / 随机表名 / Long 值对所有系统一视同仁 | 只对某套系统数据做过测试 |

## 功能点

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F-01 | 系统级三态开关 `chart_enabled` | P0 | NULL/0=关（默认，产物与旧版逐字节一致），1=开；回落唯一实现 `GenTemplateModel.resolveChart` |
| F-02 | 列元数据推导图表类型 | P0 | 枚举/字典列→饼图（分类分布），日期列→趋势折线（按日/月分组），数值列→排名柱图（SUM/AVG），状态列→环形进度 |
| F-03 | 生成后端聚合接口 `/{table}/stats` | P0 | 每表一个，参数 `metric/field/range/groupBy`，SQL 列名生成期固定（白名单），禁用户输入直拼 |
| F-04 | 生成前端图表基座 | P0 | `scaffold-chart/`：ECharts 依赖、`ChartCard.vue` 通用卡、按需引入、主题色走 `--app-primary` token |
| F-05 | 生成仪表盘页 `views/dashboard/index.vue` | P0 | KPI 卡 + 分类饼图 + 趋势线 + 排名柱 + 明细下钻；路由与菜单自动注册为「数据看板」 |
| F-06 | 统计口径随种子数据自洽 | P0 | 演示数据落库后看板有真实数字，不是 0/占位；空表时图表显示「暂无数据」而非报错 |
| F-07 | 图表权限接入 | P0 | `/stats` 接口挂 `:list` 权限点，纳入产物 `ApiPerms` 生成；无权限时前端隐藏看板入口而非显示空白 |
| F-08 | 平台侧图表配置预览 | P1 | 生成前在平台「图表配置」页看到将生成哪些图（依据列元数据），可单图关闭——只影响生成结果，不写业务库 |
| F-09 | 可视化拖拽配置器 | P2 | 平台拖拽选表/维度/指标/图型，配置落 `gen_chart_config` 表，生成时按配置渲染（替代 F-02 自动推导） |
| F-10 | 导出/打印图表 | P2 | 看板导出 PNG、随 A4 打印单据带图（依赖 F-04 的 SVG renderer 选项） |

## 边界与异常

| 场景 | 期望行为 |
|---|---|
| `chart_enabled` 关闭（默认） | 产物与 V9.7 逐字节一致，不生成任何 chart 文件、不引入 echarts 依赖、无 `/stats` 接口 |
| 表无日期/枚举/数值列 | 只生成 KPI 卡（COUNT），图表区显示「该表暂无可图表化的列」，不生成空图 |
| 无权限访问 `/stats` | 同产物既有约定：HTTP 200 + body.code=403；前端 `v-hasPermi` 隐藏入口 |
| 传入未白名单的 field/metric | 后端 400，错误信息不回显 SQL 片段；参数以生成期枚举常量校验 |
| 日期跨度超阈值（默认 365 天） | 拒绝并提示收窄范围，防止大扫描；趋势按日最多 366 点、按月最多 36 点 |
| 数据量为 0 | 图表组件渲染空态文案，KPI 显示 0，不抛异常、不出现 NaN |
| 含随机 slug 表名 | 图表标题用 `tableComment`，接口路径用实体类名，不依赖表名反推驼峰（沿用 V9.18 坑 78 教训） |
| 多系统/微服务工程 | 看板落 bootstrap 模块，聚合接口落对应业务模块，`apiBase` 沿用 `GenPathResolver` 单一实现 |
| 改了 classpath 模板但库里 `gen_template` 有旧版 | 生成仍读库版——变更须知里明确「模板与库同步」，不悄悄绕过（历史坑） |

## 验收标准

- [ ] F-01 `chart_enabled` 三态：NULL/0 关闭时产物零 diff（基线测试加 chart-off 场景）；1 开启时新增文件清单精确可数。
- [ ] F-02 用智慧警务 84 表实测：状态列→饼图、创建时间→趋势线、金额列→柱图，推导结果与列元数据一致。
- [ ] F-03 每表 `/stats` 接口 code=200，非法 `field` 返回 400，SQL 日志里无用户输入拼接痕迹。
- [ ] F-04 `npm run build` 通过；产物未开启图表时 `package.json` 无 echarts 依赖。
- [ ] F-05 真浏览器打开看板：0 console error，四块图表都渲染出 DOM/canvas，点击柱子能下钻到对应列表页。
- [ ] F-06 种子数据下每个 KPI > 0；清空一张表后该图显示空态而非报错。
- [ ] F-07 无权限账号访问 `/stats` 返回 code=403；前端菜单不显示看板入口。
- [ ] 通用性：≥3 套异构系统（村务 / 仓储 / 警务，主色与表结构均不同）chart-on 生成 + 看板打开全部通过；能力包源码（推导器 + 3 个模板/组件）grep 业务系统名 / 领域关键词 = 0 命中。
- [ ] 换肤通用：同一能力包在两个不同主色系统（蓝 / 紫）下，图表系列色自动跟随 `--app-primary`，无需改图表代码。
- [ ] F-08/F-09/F-10 本版本不实现，验收不计入。

## 明确不做（本版本）

- 不做运行时拖拽配置器（P2）；本版图表类型由列元数据推导，生成后固定。
- 不做跨表 JOIN 图表、自定义 SQL 图表（防注入 + 口径不可控）。
- 不做实时推送/WebSocket 刷新，刷新靠手动按钮或页面进入时拉取。
- 不做大屏 3D/地图（地图合规另行处理，不并入本版）。
- 不改动 V9.x 已有 17 开关与三态回落语义；`chart_enabled` 属系统级能力包开关，与 `pay/mobile/file` 同款。
- 不做按 `projectCode` / 系统名分支的图表逻辑；不做领域关键词规则表（通用性硬约束，见上）。
