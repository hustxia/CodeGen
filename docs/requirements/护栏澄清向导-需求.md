# M2.1 护栏澄清向导与 28 条行业规则 需求

> 版本：v1.0　日期：2026-11-28　对应版本：V9.25（M2.1 护栏）
> 规划依据：`代码生成器三版本规划-日期版.md` M2.1、`GitHub热点-代码生成器10期项目规划.md` 第 4 期
> 效果图依据：`代码生成器10期-完整UI效果图.html` 屏 6（用户已确认的 10 期全量 UI）

## 背景与目标

V9.4.1 的领域护栏只在「AI 模块清单」结果侧做语义相关性判定（领域词零命中 + 通用模板占比 ≥1/3 才阻断，坑库 `spring-boot-3.md` 坑 70），解决的是"生成结果和输入无关"，**没有解决"用户自己就没想清楚"**：用户说"做个城管系统"，到底挂不挂事件中心、渣土车 GPS 是直出还是外接、考核指标是否全配置化，全靠猜。猜错的代价在建表之后才暴露。

本期把"先澄清再生成"做成产品能力：

1. 一次只问一个影响生成结构的关键问题，最多 5 问，答完或跳过后信息足够；
2. 28 条行业规则做确定性拦截/告警，命中时解释"为什么拦 + 怎么做才对"，不是简单拒绝；
3. 澄清结论与拦截修正写进 SPEC 工件的"非目标"章节，与 V9.21 工件链联动，形成人工卡点。

不做：不做 LLM 追问生成（本地 7B 一次推理 3-5 分钟，追问体验不可接受）、不做自动重试、不改生成流水线本身、不碰 V9.24 质量门禁（M2.2）与 V9.23 MCP。

## 功能点

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F-01 | 行业规则库列表 | P0 | 28 条规则按行业/类别筛选，展示编码、级别、触发条件、建议；支持启停 |
| F-02 | 澄清会话开始 | P0 | 选项目 + 行业 + 系统名/描述，创建会话，返回第 1 问 |
| F-03 | 一次一问答复 | P0 | 提交答案→返回下一问；最多 5 问，可跳过；答案落会话 JSON |
| F-04 | 护栏命中检测 | P0 | 对系统名/描述/模块/答案跑规则，返回 BLOCK/WARN 命中列表与解释 |
| F-05 | 拦截修正与高级模式 | P0 | BLOCK 时不可确认；高级模式可显式忽略并记录 overridden，审计可查 |
| F-06 | 确认写 SPEC | P0 | 会话确认后创建/更新 SPEC 工件草案，`yamlMeta.guardrailPassed` + `content_md` 追加"非目标"章节 |
| F-07 | 澄清会话详情/历史 | P1 | 按项目列会话、查看问答记录与命中记录、状态机 |

### 28 条规则来源（不是凭空编写）

从本会话已产出的四行业落地方案 + 第 4 期规划逐条提炼，每行业 7 条：

| 行业 key | 黑名单 2 | 白名单 2 | 冲突 1 | 边界 1 | 澄清 1 |
|---|---|---|---|---|---|
| `gov_affairs` 村务治理 | 基座 15 表单独生成；单库 >100 表不拆分 | 网格/人口主数据先行；数据分类分级与脱敏 | GIS 直出 vs 外接 | GIS/视频/算法不承诺直建 | 国产库与密评要求 |
| `cm_city` 城市管理 | 基座单独生成；GPS 轨迹入库 | 必须挂事件中心；考核指标全配置化 | 渣土车台账直出 vs GPS 外接 | 视频会商/单灯控制/SCADA 必须外接 | 15 域范围裁剪 |
| `agr_crop` 智慧种植 | 基座单独生成；AI 识别结果直接下发 | 农事挂种植季；面积口径只有一份 | 水肥直驱 vs 处方下发+人工确认 | 不直接驱动阀门/不承诺农机自动驾驶 | 水肥机协议是否开放 |
| `park_park` 智慧园区 | 基座单独生成；租区变更不留历史 | 空间主数据先行；统一身份/一卡通账户先行 | 消防联动自研 vs 消防主机联动 | 人脸/门禁/停车/BA 不自研 | IoT 平台与厂商协议 |

规则是**数据**（`gen_guardrail_rule` 表，可启停/改文案），判定引擎是**代码**，业务知识不硬编码进 Java。

## 边界与异常

| 场景 | 期望行为 |
|---|---|
| 系统名为空 | 400「系统名称不能为空」 |
| 行业不在四包内 | 400「暂不支持该行业的护栏规则」 |
| 问题答完仍不足 5 问 | 正常结束，允许确认；不强制凑满 |
| 有 BLOCK 未处理就确认 | 400「存在 N 条未处理拦截，请先修正或开启高级模式」 |
| 高级模式忽略 BLOCK | 允许，但会话记 `overriddenCodes`、SPEC yamlMeta 记 `guardrailOverridden: true` |
| 同一会话重复 confirm | 幂等：返回已生成的 SPEC 工件，不重复建版本 |
| 规则被停用 | 该规则不参与检测；历史会话命中记录保留 |
| 并发答复同一会话 | 按 `questionCode` 幂等：同题重复答覆盖答案，不推进游标 |
| 无 CONFIRMED SPEC | 不影响本案；流水线启动前的规格一致性护栏由 M2.2 的 `PipelineSpecGuard` 负责，两者不互相调用 |

## 验收标准

- [ ] `gen_guardrail_rule` 28 行，四行业各 7 行，类别齐全，`COUNT(*)` 有真实输出
- [ ] 选「生成一套用户管理系统」→ 命中 GOV/CM/AGR/PARK 通用黑名单，BLOCK 文案含"基座"与正确做法
- [ ] 选「智慧种植 + 水肥一体化」，答"厂商提供 Modbus 接口"→ 命中水肥冲突规则，提示"处方下发 + 人工确认 + 回读对账"
- [ ] 澄清 5 问一次一问，答完进入检测；跳过也进入检测
- [ ] 确认后 SPEC 工件 `content_md` 含"## 非目标"章节，`yamlMeta.guardrailPassed=true`
- [ ] 接口边界（空系统名/未知行业/未处理 BLOCK/重复确认）均返回 body.code=400 或幂等结果
- [ ] UI 两页 console 零 error，截图可见对话气泡、拦截解释、规则计数 28

## 待确认（已按既有规划闭合，不阻塞开发）

- 28 条规则的具体文案：从四行业方案提炼，落表后可随时改；代码不绑定具体条目。
- 「高级模式」是否开放给所有用户：本期只做开关参数 `advancedMode`，不做角色权限，正式权限沿用 sys_menu 静态入口方案。
- 与流水线卡点联动：本期只写 SPEC 工件，不嵌入流水线；流水线卡点已有 V9.24 `PipelineSpecGuard`（M2.2），避免两处卡点打架。
