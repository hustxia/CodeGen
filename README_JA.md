# 碼匠（マージャン）· コードジェネレーター（CodeGen）— プロジェクト紹介

> 言語: [中文](README_ZH.md) · [English](README.md) · **日本語** · [Português](README_PT.md)

---

> **Spring Boot + Vue** 向けのマルチプロジェクト対応コードジェネレーター。データベースのテーブル構造を出発点として、**コンパイル可能・そのまま実行可能・メニュー権限付き**のフロントエンド／バックエンド業務コードを生成し、ディスクへの書き込み、バックアップ、台帳記録、ロールバックまでの完全なデリバリーループを担います。

GitHub: https://github.com/hustxia/CodeGen

## 1. これは何か

CodeGen は「テーブルを源とする」コード工場です。業務テーブルを取り込むだけ（DB 接続インポート、または DDL を貼り付け）で、フィールドと生成スイッチを設定し、「生成」ボタンを押せば、バックエンドの Entity／Mapper／Service／Controller／DTO／VO、フロントエンドの `api.js` と Vue ページ、メニューとルーティング、さらには A4 印刷ページや結合テストのスケルトンまでをすべて生成し、安全にターゲットプロジェクトへ書き込みます。

単に「コードを吐き出す」だけでなく、**品質ゲートとロールバック能力を備えたデリバリーパイプライン**です：

```
テーブル取込（DB インポート / DDL）
   → フィールド／スイッチ設定（AI レコメンド対応）
      → ワンクリック生成：セルフチェック → バックアップ → ディスク書込 → コンパイル／検証 → メニュー登録 → ルート再構築
         → 台帳記録 → ロールバック可能
```

## 2. どんな問題を解決するか

| 課題 | CodeGen のアプローチ |
| --- | --- |
| 繰り返しの CRUD 地獄 — テーブルごとに大量のボイラープレート | テーブル単位のスイッチでフロント・バック完全セットをワンクリック生成（CRUD・ページング・バリデーション・入出力込み） |
| 前後間のフィールド／API の不整合で結合テストが何度も手戻り | 同一のテーブルメタデータがバックエンド API とフロントエンド画面の両方を駆動 — 意味のズレはゼロ |
| チームの規約を統一しにくい | テンプレート＝規約。FreeMarker テンプレート 22 本を一元管理、オンライン編集とバージョン ロールバック対応 |
| 生成器が「上書きして消す」— 手書きコードが消える | マーカーブロック統合機構：手書きコードは保持され、生成領域だけが置換される |
| コンパイルするまで生成物を信用できない | メモリ内コンパイル セルフチェック（本物の `javac`）、構造コントラクト検査、ディスク diff プレビュー — コンパイルが通らなければディスクに書き込まない |
| 新規システムをゼロから足場構築するのは時間がかかる | パイプライン「一言でシステム構築」：DB 作成 → 足場 → 生成 → パッケージ → メニュー登録を全自動 |

## 3. コア機能の全体像

- **テーブル取込**：DDL パース、DB 直結インポート、一括取込ウィザード、列設定の自動推論（コントロール／バリデーション／辞書／リレーション）。
- **テーブル形態**：単一テーブル、ツリー テーブル（tree API ＋ツリーグリッド）、マスター・ディテール（同一トランザクション保存＋ディテールタブ）、多対多の中間テーブル。
- **生成物**：Entity／Mapper／Service／Controller／DTO／VO ＋ `api.js` ＋ Vue ページ ＋ A4 印刷ページ ＋ 結合テスト スケルトン。
- **業務強化**：リレーション ドロップダウン、辞書変換、マスキング、一意性チェック、フォーム連動、データ権限、Excel 入出力、承認ワークフロー、決済／ファイル／モバイル能力パック。
- **品質ゲート**：メモリ内コンパイル セルフチェック（本物の `javac`）、構造コントラクト検査、権限整合性チェック、ディスク diff プレビュー、フロントエンド生成物の実検証。
- **安全な着地**：ディスク書込 ＋ `.gen-backup` バッチ バックアップ、マーカーブロック統合による手書きコード保持、`gen_output` の 4 状態台帳（新規／統合／スキップ／失敗）、履歴ロールバック。
- **マルチシステム分離**：各ターゲットプロジェクトは 1 つの「システム設定」（前後のパス、パッケージ名、ゲートウェイ プレフィックス、依存 classpath、生成スイッチの既定値）であり、複数プロジェクトを並行運用できます。
- **AI 強化**：一言でシステム構築（AI モデリング）、シードデータの AI 強化、テーブル単位の AI 推奨設定（diff プレビュー＋チェックして適用）。

## 4. 典型的なユースケース

| シナリオ | 説明 |
| --- | --- |
| ツリー テーブル | 商品カテゴリなど階層データ — tree API、ツリーグリッド、上位選択ドロップダウンを自動生成 |
| 単一テーブル CRUD | 顧客・商品など — 外部キー ドロップダウン＋辞書変換＋入出力をすぐ使える状態で提供 |
| マスター・ディテール | 販売注文＋注文明細 — 同一トランザクション保存、詳細ドロワーに 2 タブ（マスター情報／明細） |
| 参照専用／集計 | 在庫フローなど — 追加・変更・削除スイッチをオフ、照会と出力のみ |
| 印刷伝票 | 「印刷」スイッチをチェックすると A4 印刷ページとルートを生成、ヘッダー＋明細テーブル対応 |
| 一言でシステム構築 | 業務ドメインを記述するだけで、AI が DB・テーブル作成＋足場＋全量生成＋メニュー登録まで一気に実行 |

> 上記シナリオはすべて実行可能なデモ（`demo_admin` プロジェクト）とスクリーンショットを用意しています。詳細は `docs/典型场景操作指南-演示后台demo.md`（中国語）を参照してください。

## 5. コア ワークフロー

```
┌──────────────┐   ┌────────────────────┐   ┌────────────────────────────────────────────────────┐
│ テーブル取込  │ → │ フィールド／スイッチ │ → │ ワンクリック生成（セルフチェック→バックアップ→書込→  │ → │ 台帳 · ロールバック │
│              │   │ 設定               │   │ コンパイル→メニュー→ルート）                        │   │                    │
└──────────────┘   └────────────────────┘   └────────────────────────────────────────────────────┘
  DB取込／DDL        コントロール／検証／      品質ゲート全通過でのみディスク着地、                     バッチ単位の追跡
                     辞書                     手書きコードは保持
```

- **差分プレビュー**：生成物とディスク上の現状をファイル単位で diff、確認後に書き込むため誤上書きを防止。
- **生成台帳**：各ファイルのアクション、バイト数、MD5、バックアップ位置を記録し、バッチ全体のロールバックが可能。

## 6. 一言でシステム構築（Pipeline）

「ゼロからバックエンドを作る」ための高機能モードです。業務ドメインを記述すると、パイプラインが 5 段階を全自動で進行します：

| 段階 | 意味 |
| --- | --- |
| `CHECK` | ターゲットプロジェクトの設定と依存 classpath を検証 |
| `WRITE` | DB・テーブル作成、足場と生成物の書き込み |
| `COMPILE` | バックエンド `mvn package`／フロントエンド ビルド、メモリ内コンパイル セルフチェック |
| `MENU` | メニュー権限の生成と登録（二重出口：artifact SQL／internal 直書き） |
| `ROUTE` | フロントエンド ルート断片の再構築 |

いずれかの段階が失敗すると即座に中断し、読み取り可能なエラーを返します。

## 7. システム アーキテクチャ

フロントエンドとバックエンドを分離し、2 つのリポジトリが連携します：

| リポジトリ | 役割 | 技術スタック |
| --- | --- | --- |
| `codegen-server` | バックエンド：生成エンジン、テンプレート、検証、台帳、パイプライン | Java 21 · Spring Boot 3.2.5 · MyBatis-Plus 3.5.5 · FreeMarker · JWT · MySQL 8 · springdoc-openapi |
| `codegen-web` | フロントエンド：コンソール（テーブル設定／テンプレート／台帳／システム管理） | Vue 2.7 · Element UI · axios · Vue Router（history モード） |

バックエンドのレイヤー構成：

```
controller/    API 層（Gen* 生成チェーン／Sys* システム管理／パイプライン）
service/impl/  コア実装（生成チェーン、テンプレート エンジン、統合、検証、パイプライン実行）
util/          テンプレート エンジン、モデル組み立て、マーカーブロック統合、セルフチェック コンパイル
config/        出力設定、セルフチェック設定、テンプレート シーダー
common/        Result／BaseEntity／例外／監査
resources/gen-templates/   FreeMarker テンプレート 22 本（backend／frontend／shared／test グループ）
```

**ターゲットプロジェクトが自前で備えるべき基盤能力**（生成器は業務コードのみ生成。基盤が欠けると静かに故障します）：

1. MyBatis-Plus ページネーション プラグイン（`PaginationInnerInterceptor`）
2. `Result`／`BaseEntity`／`PageQuery` などの基盤クラス（パッケージ接頭辞は `root-package` と一致させること）
3. フロントエンド `utils/request.js` の `toPageData`（`Page{records,total}` を `{list,total}` に変換）
4. 依存関係 `springdoc-openapi-starter-webmvc-ui`（生成物は `@Operation` を使用）と `poi-ooxml`（Excel）

## 9. クイック スタート

### 1. DB 作成（プラットフォーム テーブル 13 枚 ＋ 既定アカウント admin/admin123）

```bash
mysql -uroot -p -e "CREATE DATABASE gen_platform DEFAULT CHARSET utf8mb4;"
mysql -uroot -p gen_platform < docs/sql/V1.0__init.sql
```

### 2. ターゲットプロジェクトの設定

設定テンプレートをコピーし、ローカルのパスに合わせて修正：

```bash
cp src/main/resources/application-local.yml.example src/main/resources/application-local.yml
```

`application-local.yml` は `.gitignore` で除外されており、コミットされません。主な設定項目：

```yaml
gen:
  output:
    backend-root: /path/to/your-target-project      # 生成物のディスク書込基準パス
    frontend-root: /path/to/your-target-project
    frontend-path: demo-web                          # monorepo の場合のフロントエンド サブディレクトリ
    backend-path: demo-server/src/main/java/com/demo
    package-name: com.demo
    root-package: com.demo                           # 生成物が基盤クラスを import する際の接頭辞
  selfcheck:
    classpath: /path/to/your-target-project/demo-lib/*
```

セルフチェック用の依存ディレクトリは次のようにエクスポートします：

```bash
cd your-target/demo-server
mvn dependency:copy-dependencies -DoutputDirectory=../demo-lib
```

### 3. バックエンド起動

```bash
mvn package -DskipTests
java -jar target/codegen-server.jar
```

サービスの既定ポートは **8120**、API ドキュメントは `/swagger-ui/index.html`。

### 4. フロントエンド起動

```bash
cd ../codegen-web
npm install
npm run serve
```

フロントエンドの既定ポートは **9530**、`/dev-api` はバックエンド 8120 にプロキシされます。既定アカウントは `admin / admin123`。

### 5. 主要な設定項目

| 設定 | 説明 |
| --- | --- |
| `gen.output.*` | 生成物の書込パス、パッケージ名、モジュール マッピング |
| `gen.selfcheck.classpath` | メモリ内コンパイル セルフチェックの依存 classpath、`dir/*` 形式対応 |
| `gen.menu.outlet` | `artifact` はメニュー SQL とルート断片のみ出力。`internal` はプラットフォーム自身の `sys_menu` にも書き込む |
