# 码匠 · CodeGen —— 项目介绍（前端视角）

> 一句话：**给它一张表，它给你一套能跑的前后端代码；给它一句话，它给你一个能登录进去用的系统。**  
> 本文从「打开页面能看到什么、点什么、得到什么」的角度介绍这个平台，不涉及后端实现细节。

---

## 一、它解决什么问题

写一套后台管理功能，90% 的代码是重复的：实体、Mapper、Service、Controller、列表页、表单弹窗、路由、菜单、按钮权限…… 真正有业务差异的只有那 10%。

这个平台把这 90% 固化下来，并且**不满足于「生成一堆文件让你自己拷」**——它一路做到「生成 → 编译 → 注册菜单 → 重建路由 → 打开就能用」。前端在这里承担的使命很明确：**把一条有 5 个阶段的长链路，变成几个按钮和一张进度表。**

---

## 二、用户是谁，会怎么用                        

| 使用者     | 典型诉求                     | 平台给的路径                  |
| ------- | ------------------------ | ----------------------- |
| 后端开发    | 手上有一批表（或 DDL），想快速拉起 CRUD | 表配置页：导入 → 配字段 → 一键生成    |
| 全栈/独立开发 | 想从零起一个完整系统（含登录、权限、字典）    | 流水线页：一句话建系统             |
| 团队负责人   | 想统一代码风格、代码规范、目录结构        | 系统管理：一套系统 = 一套输出配置，批量生效 |
| 平台维护者   | 想改模板而不改代码                | 模板管理：在线编辑，保存即生效，支持历史回滚  |

## 三、界面导览（8 个页面）

侧边栏为「一级点击、二级右滑」的自定义导航，非 Element 默认菜单。列表页统一是「筛选卡 + 数据卡」两段式，首屏就是可用的筛选条件，不用先点展开。

| 页面         | 组件位置                    | 做什么                                          | 关键操作                                                 |
| ---------- | ----------------------- | -------------------------------------------- | ---------------------------------------------------- |
| **表配置**    | `views/gen/table`       | 主战场。表的接入、字段配置、生成开关、一键生成                      | 从数据库导入 / 粘贴 DDL / 字段配置 / 一键生成 / 生成自检 / 差异预览 / 下载 ZIP |
| **批量接管向导** | `views/gen/wizard`      | 一次处理多张表，四步走完                                 | ①勾选多张表 → ②预览/差异 → ③写盘策略 → ④校验/菜单/台账                  |
| **一句话建系统** | `views/gen/pipeline`    | 从零起整个系统，全程不碰数据库、不开 curl                      | ①录入与建模 → ②表结构确认 → ③构建进度                              |
| **系统管理**   | `views/gen/project`     | 一个系统 = 一套输出配置（前后端工程路径、根包名、网关前缀、依赖 classpath） | 新增 / 编辑 / 设为默认                                       |
| **模板管理**   | `views/gen/template`    | 22 个 FreeMarker 模板在线编辑                       | 编辑 / 复制为表级 / 历史 / 回滚 / 恢复默认                          |
| **生成台账**   | `views/gen/output`      | 写盘的文件级账本，能回滚                                 | 批次摘要 / 健康检查 / 真校验 / 回滚 / 清理过期备份                      |
| **接口目录**   | `views/gen/api-catalog` | 按表聚合已生成的接口与权限编码                              | 关键字查询 / 只看已生成                                        |
| **系统设置**   | `views/system/*`        | 用户、角色、菜单、字典、主题                               | 标准 CRUD + 主题切换                                       |

### 3.1 表配置页：一条链路收在一屏

页面顶部是一句操作路径提示，不是装饰——它决定了按钮怎么排：

> 从数据库导入（或粘贴 DDL）→ 配置字段与生成开关 → 一键生成（自检→备份写盘→编译→注册菜单→重建路由）

按钮按「用户在什么时候会用到」分三组，而不是按功能清单平铺：

- **入口组**：从数据库导入、粘贴 DDL
- **主操作组**：一键生成、生成自检（日常真正反复点的）
- **更多组**：生成预览、差异预览、注册菜单、下载 ZIP（低频操作收进下拉）

> 取舍记录：定稿前试过平铺 10 个按钮，1366 宽屏下会换行，把「下载 ZIP」挤到第二行 —— 这版分组就是为了不换行。

筛选区除了表名/功能名，还有两个很实用的维度：

- **生成状态**：已生成过 / 从未生成 / 结构有漂移 / 已注册菜单
- **所属系统**：包含一个「未绑定系统」哨兵项，用来捞迁移前的存量表

配套四个弹窗，各自只干一件事：`DictDetectDialog`（字典识别）、`GenCheckDialog`（自检明细）、`GenDiffDialog`（差异预览）、`RelationDialog`（关系推断）。

### 3.2 一句话建系统：把 40 分钟压缩成一次等待

三步步进器，第一步只有四个输入框：系统名称、一句话描述、数据库名、建模方式（AI 生成 / 手动粘贴 DDL）。

- 选 AI 时给出**规模选项**：精简（3–5 张，约 4 分钟）/ 完整系统（50 张+，逐模块约 40 分钟）——把耗时不藏着，让用户自己决定等多久
- 服务端没配 LLM key 时，AI 选项**置灰并给出原因**，而不是点了报错
- 选手动时，DDL 输入框的 placeholder 就写明「缺审计列会由服务端自动补齐：只增不改，补齐明细随后如实展示」

建库建表后进入表结构确认：可加列、删列、删表、一键补齐，确认后「开始构建」。构建阶段是 SSE 流式进度，每步有状态，可「停止」。成功后直接「打开系统」。

### 3.3 生成台账：生成的代码可以后悔

这是很多代码生成器缺的一环。三个入口（写盘、一键 apply、批量向导）的每次写盘都逐文件记账，批次号格式 `GEN+yyyyMMddHHmmss`，ZIP 下载不记账（没落盘，无从回滚）。

- **批次摘要**：一次生成了多少文件、多少新增、多少覆盖
- **健康检查**：台账与实际磁盘的偏离情况
- **真校验**：勾选表后真实比对一个批次，不是只看账本
- **回滚**：按批次恢复到写盘之前

### 3.4 模板管理：改模板不用重启

在线编辑 22 个模板，保存即生效。表级覆盖优先于全局模板，「恢复默认」= 删除表级覆盖、回落到全局。每次保存进历史，可回滚到任一版本。产物分组（backend / frontend / shared）与归属（全局 / 表级）两个维度筛选。

## 四、两条典型路径

### 路径 A：我有一批表（最常用）

```
表配置页 → 从数据库导入（勾选 schema 下的表）
        → 字段配置（字典/枚举/脱敏/唯一校验/联动规则/多图/数据权限标记）
        → 一键生成（默认策略：同名跳过）
        → 弹窗展示 5 个阶段结果：自检 / 备份写盘 / 编译 / 注册菜单 / 重建路由
        → 侧边栏立刻多出一个菜单，点进去就是能增删改查的页面
```

「一键生成」结果弹窗不是一句「成功」，而是**阶段级明细表**：写入 N 个、跳过 N 个、失败 N 个、耗时多少 ms，失败的阶段单独标红。五个阶段码固定为 `CHECK → WRITE → COMPILE → MENU → ROUTE`，未勾选的阶段显示 `SKIPPED` 而不是直接藏掉——「为什么没编译」这个问题应该在界面上回答。

### 路径 B：我要一个完整系统

```
一句话建系统 → 录入名称/描述/库名 → AI 建模（或粘 DDL）
            → 表结构确认（可改） → 开始构建（SSE 进度）
            → 构建完成 → 打开系统 → 直接用账号登录
```

生成的不是一个裸 CRUD 工程，而是带**登录、权限、字典、素材上传、品牌配置**的基座，加上业务表的 CRUD。

## 五、前端在生成链路上做的几个关键决定

这些是纯前端的判断，直接影响用户会不会把自己的代码搞丢。

### 5.1 写盘策略只有三档，且未知值一律按最保守处理

抽成纯函数 `utils/genStrategy.js`，与后端 DTO 严格对应：

| 策略        | 行为                 | 请求参数                                            |
| --------- | ------------------ | ----------------------------------------------- |
| 同名跳过（推荐）  | 只写新增文件，已存在的一律不写    | `overwrite:false`                               |
| 覆盖，但跳过已手改 | 覆盖，但磁盘相对上次生成被改过的不动 | `overwrite:true, skipDrifted:true`              |
| 强制覆盖      | 全量覆盖，连「受保护文件」也覆盖   | `overwrite:true, skipDrifted:false, force:true` |

> 为什么单抽一个文件：规则原来散在两个页面的 computed 与模板表达式里，改一次策略只能靠手点页面确认。抽成纯函数后可以单测，**未知策略按 skip 处理——宁可少写，也不能因为参数写错把整个工程覆盖掉。**

「受保护文件」指磁盘上存在但台账没有快照的文件（不是平台写的，或台账丢了）。只有「强制覆盖」这一档传 `force=true`，另两档必须保留保护语义，否则手写代码会被静默吃掉。

### 5.2 越权给 403，不是 404

路由守卫里区分两种「进不去」：

- 路径在系统菜单里存在，但不在当前用户菜单树里 → **403**（有页面，你没权限）
- 路径本身不存在 → 404

用户看到 403 知道是权限问题，会去找管理员；看到 404 只会以为链接错了。

### 5.3 生成自检的结果要能定位到行

自检弹窗（`GenCheckDialog`）按严重级别分组展示：占位符残留、Vue/JS 结构、javac 真实编译、字典绑定、实体列契约、权限码一致性。编译错误直接给文件+行号，而不是「自检失败」四个字。

### 5.4 前端产物本身也要过关

生成的 `api.js` 和 `.vue` 是最容易出坏代码的地方（门控开关组合多）。所以产物质量有专门的护栏：

- 1024 种开关组合全量渲染，2048 个 JS 段做语法校验，**0 坏组合**
- 反向验证：故意把模板里的逗号门控改坏，校验脚本精确报出 **192 种**坏组合，恢复后归零

这意味着你在页面上随便勾开关，生成的 JS 都不会是语法错误的。

## 六、前端工程本身

```
codegen-web/
├── src/
│   ├── api/          9 个模块，按后端域拆分（gen/genOutput/genTpl/pipeline/system/...）
│   ├── views/        28 个 .vue，vue+js 合计约 1.25 万行
│   │   ├── gen/      代码生成 7 个页面 + 5 个专用弹窗
│   │   ├── system/   用户/角色/菜单/字典/主题
│   │   └── login, error-page
│   ├── layout/       自定义侧边栏（一级点击、二级右滑）
│   ├── utils/        request（token 注入 + 401 统一处理）、genStrategy（纯函数策略）、theme
│   ├── store/        vuex 模块：user / permission / settings
│   ├── permission.js 路由守卫：动态路由注册 + 403 判定
│   └── styles/       主题变量
└── docs/             本文
```

- **技术栈**（平台控制台）：Vue 2.7 + Element UI 2.15 + Vuex 3 + Vue Router 3 + axios；构建 vue-cli 5；单测 vitest。**注意**：V9.0 起生成物（目标项目）已是 Vue 3 + Element Plus + Vite，与本控制台不同
- **路由全动态**：`constantRoutes` 只有登录、403、404 与兜底，业务路由按角色从 `/auth/routers` 拉菜单树后 `router.addRoute` 注册。登出时 `resetRouter()` 重建 matcher，避免权限残留
- **请求层**：统一注入 `Bearer token`；401 时用「重登录标记」保证多请求并发只弹一次确认框，并带上当前地址，登录后回原位
- **主题引擎**：不是 240 份 CSS，而是**一组参数**——24 色相 × 2 明暗 × 5 形态 = 240 套皮肤，运行时算出 50 多个 CSS 变量注入 `:root`。包体积与主题数量无关，新增色相只多一行配置；非法主题 ID 一律回落默认，不白屏
- **兼容旧代码成本为零**：单文件页面最大 2166 行（表配置页），没有拆成组件树——这个页面的复杂度来自「配置项多」而非「交互深」，拆开反而让「一键生成」的上下文跨文件跳转

## 七、它不做什么

明确划出的边界，避免期待错位：

- **不做逆向工程**：不对存量工程做接管改造，只从数据库/DDL 正向生成
- **不做 C 端商城交易闭环**：做后台管理，不做订单状态机/库存扣减/优惠券核销
- **不做图片压缩/缩略图服务**
- **生成物零重依赖**：不引入运行时代码生成库，产物就是普通 Spring Boot + Vue 代码，随时可以脱离平台继续手写

## 九、30 秒上手

```bash
# 后端（Spring Boot 3.2.5 / Java 21 / MySQL 8）
cd codegen-server && docs/sql 按文件名顺序执行（或用空库冒烟脚本）
mvn spring-boot:run

# 前端控制台（Vue 2.7；生成物 V9.0 起为 Vue 3 + Vite）
cd codegen-web && npm install && npm run serve
```

登录后默认落在**表配置页**。想立刻看到效果，最快的路径是：

1. 「从数据库导入」勾一张表
2. 直接点「一键生成」，策略用默认的「同名跳过」
3. 看结果弹窗 5 个阶段全绿
4. 侧边栏刷新，新菜单出现，点进去就是能用的增删改查
