## 1. Что это такое

CodeGen — это «кодовая фабрика, управляемая таблицами». Достаточно подключить бизнес-таблицы (импорт из БД или вставка DDL), настроить поля и флаги генерации, нажать «Сгенерировать» — и система создаст за вас бэкендные Entity/Mapper/Service/Controller/DTO/VO, фронтендные `api.js` и страницы Vue, меню и маршруты, а также страницы печати A4 и каркасы интеграционных тестов, и безопасно запишет всё это в ваш целевой проект.

Он не просто «выплёвывает код», а представляет собой **конвейер поставки с контролем качества и возможностью отката**:

```
Приём таблиц (импорт из БД / DDL)
   → Настройка полей и флагов генерации (включая AI-рекомендации)
      → Генерация в один клик: самопроверка → резервная копия → запись на диск → компиляция/проверка → регистрация меню → перестройка маршрутов
         → Ведение реестра → возможность отката
```

## 2. Кто пользователи и как они используют платформу
| Пользователь | Типичная потребность | Путь, предлагаемый платформой |
| --- | --- | --- |
| Бэкенд-разработчик | Есть набор таблиц (или DDL) и нужно быстро поднять CRUD | Страница конфигурации таблиц: импорт → настройка полей → генерация в один клик |
| Фулстек / независимый разработчик | Хочется с нуля поднять целую систему (с логином, правами, словарями) | Страница конвейера: создание системы одной фразой |
| Руководитель команды | Хочет унифицировать стиль кода, стандарты и структуру каталогов | Управление системой: одна система = одна конфигурация вывода, пакетное применение |
| Сопровождающий платформы | Хочет менять шаблоны, не трогая код | Управление шаблонами: онлайн-редактирование, сохранение вступает в силу сразу, поддерживается исторический откат |

## 3. Какие проблемы решает

| Проблема | Что делает CodeGen |
| --- | --- |
| Ад повторяющегося CRUD: для каждой таблицы приходится вручную писать гору шаблонного кода | Флаги на уровне таблицы одним кликом создают полный бэкенд и фронтенд, включая CRUD, пагинацию, валидацию, импорт и экспорт |
| Поля и интерфейсы фронтенда и бэкенда не совпадают, интеграция требует бесконечных правок | Одна и та же метаинформация таблицы управляет и бэкендными API, и страницами фронтенда — нулевое расхождение семантики полей |
| Командные стандарты трудно унифицировать, у каждого свой стиль | Шаблон и есть стандарт: 22 шаблона FreeMarker централизованно управляются, поддерживают онлайн-редактирование и откат версий |
| Генератор «перезаписывает и теряет» написанную вручную логику | Механизм слияния по маркерным блокам: рукописный код сохраняется, заменяются только генерируемые области |
| Сгенерированному коду нет доверия, проблемы всплывают только на компиляции | Самопроверка компиляцией в памяти (настоящий `javac`), проверка структурных контрактов, предварительный diff по диску — без успешной компиляции запись на диск не выполняется |
| Развёртывание каркаса новой системы с нуля отнимает много времени | Конвейер «система одной фразой»: создание БД → каркас → генерация → сборка → регистрация меню, всё автоматически |

## 4. Обзор ключевых возможностей

- **Приём таблиц**: разбор DDL, прямое подключение и импорт таблиц из БД, мастер пакетного подключения, автоматический вывод конфигурации колонок (контролы / валидация / словари / связи).
- **Формы таблиц**: одиночная таблица, древовидная таблица (tree-API + дерево-таблица), мастер-деталь (сохранение в одной транзакции + вкладки деталей), промежуточные таблицы «многие ко многим».
- **Генерируемые артефакты**: Entity / Mapper / Service / Controller / DTO / VO + `api.js` + страницы Vue + страницы печати A4 + каркасы интеграционных тестов.
- **Бизнес-расширения**: выпадающие списки связей, перевод по словарям, маскирование данных, проверка уникальности, связывание полей формы, права на данные, импорт и экспорт Excel, процесс согласования, пакеты возможностей «платежи / файлы / мобильные».
- **Контроль качества**: самопроверка компиляцией в памяти (настоящий `javac`), проверка структурных контрактов, проверка согласованности прав, предварительный diff по диску, реальная валидация фронтендных артефактов.
- **Безопасная запись**: запись на диск + пакетные резервные копии `.gen-backup`, слияние по маркерным блокам с сохранением рукописного кода, четырёхсостояточный реестр `gen_output` (создан / объединён / пропущен / ошибка), откат к истории.
- **Изоляция нескольких систем**: каждый целевой проект — это «конфигурация системы» (пути бэкенда и фронтенда, имена пакетов, префикс шлюза, classpath зависимостей, значения по умолчанию флагов генерации); можно параллельно обслуживать несколько проектов.
- **AI-расширения**: система одной фразой (AI-моделирование), AI-обогащение seed-данных, AI-рекомендации конфигурации на уровне таблицы (предпросмотр diff + применение по галочкам).

## 5. Типичные сценарии

| Сценарий | Описание |
| --- | --- |
| Древовидная таблица | Иерархические данные, например категории товаров: автоматически создаются tree-API, дерево-таблица и выпадающий выбор родителя |
| CRUD одной таблицы | Клиенты, товары и т. п.: выпадающий список по внешнему ключу + перевод по словарю + импорт/экспорт «из коробки» |
| Мастер-деталь | Заказ на продажу + строки заказа: сохранение в одной транзакции, в панели деталей две вкладки (данные мастера / детали) |
| Только чтение / статистика | Движения склада и т. п.: флаги изменения выключены, остаются только запросы и экспорт |
| Печатные документы | Включение флага «печать» создаёт страницу печати A4 и маршрут, поддерживается шапка + таблица деталей |
| Система одной фразой | Описание бизнес-домена: AI создаёт БД и таблицы + каркас + полная генерация + регистрация меню — всё за один проход |

> Для всех перечисленных сценариев есть работающие демонстрации (проект `demo_admin`) и скриншоты — см. `docs/典型场景操作指南-演示后台demo.md` (китайский).

## 6. Основной рабочий процесс

```
┌──────────────┐   ┌────────────────────┐   ┌──────────────────────────────────┐
│ Приём таблиц │ → │ Настройка полей и  │ → │ Генерация в один клик:           │
│              │   │ флагов генерации   │   │ самопроверка → бэкап → запись    │
│              │   │                    │   │ → компиляция → меню → маршруты   │
└──────────────┘   └────────────────────┘   └──────────────────────────────────┘
  Импорт БД / DDL    контролы/валидация/      Запись на диск только после
                     словари                 прохождения всех проверок;
                                             рукописный код сохраняется
```

- **Предпросмотр различий**: каждый сгенерированный артефакт сравнивается файл за файлом с текущим состоянием диска; запись выполняется только после подтверждения, что исключает случайную перезапись.
- **Реестр генерации**: для каждого файла фиксируются действие, размер в байтах, MD5 и место резервной копии; пакет можно откатить целиком.

## 7. Система одной фразой (Pipeline)

Высокоуровневая возможность для «поднять бэкенд с нуля». После описания бизнес-домена конвейер автоматически проходит 5 стадий:

| Стадия | Смысл |
| --- | --- |
| `CHECK` | Проверка конфигурации целевого проекта и classpath зависимостей |
| `WRITE` | Создание БД и таблиц, запись каркаса и сгенерированных артефактов |
| `COMPILE` | Бэкенд `mvn package` / сборка фронтенда, самопроверка компиляцией в памяти |
| `MENU` | Формирование и регистрация прав меню (два выхода: SQL-артефакт / прямая запись через `internal`) |
| `ROUTE` | Перестройка фрагментов маршрутов фронтенда |

Сбой на любой стадии немедленно прерывает процесс и выдаёт читаемую ошибку для быстрой локализации.

## 8. Архитектура системы

Фронтенд и бэкенд разделены, два репозитория работают совместно:

| Репозиторий | Роль | Технологии |
| --- | --- | --- |
| `codegen-server` | Бэкенд: движок генерации, шаблоны, валидация, реестр, конвейер | Java 21 · Spring Boot 3.2.5 · MyBatis-Plus 3.5.5 · FreeMarker · JWT · MySQL 8 · springdoc-openapi |
| `codegen-web` | Фронтенд: консоль (конфигурация таблиц / шаблоны / реестр / управление системой) | Vue 2.7 · Element UI · axios · Vue Router (history) |

Слои бэкенда:

```
controller/    Слой API (цепочка генерации Gen* / управление системой Sys* / конвейер)
service/impl/  Основные реализации (цепочка генерации, движок шаблонов, слияние, валидация, выполнение конвейера)
util/          Движок шаблонов, сборка модели, слияние по маркерным блокам, самопроверка компиляцией
config/        Конфигурация вывода, конфигурация самопроверки, инициализатор шаблонов
common/        Result / BaseEntity / исключения / аудит
resources/gen-templates/   22 шаблона FreeMarker (группы backend / frontend / shared / test)
```

**Базовые возможности, которые обязателен целевой проект** (генератор создаёт только бизнес-код; при отсутствии базы отказ происходит молча):

1. Плагин пагинации MyBatis-Plus (`PaginationInnerInterceptor`)
2. Базовые классы `Result` / `BaseEntity` / `PageQuery` и т. п. (префикс пакета должен совпадать с `root-package`)
3. `toPageData` во фронтендном `utils/request.js` (преобразует `Page{records,total}` в `{list,total}`)
4. Зависимости `springdoc-openapi-starter-webmvc-ui` (в артефактах используется `@Operation`) и `poi-ooxml` (Excel)

## 10. Быстрый старт

### 1. Создание базы данных (13 таблиц платформы + учётная запись по умолчанию admin/admin123)

```bash
mysql -uroot -p -e "CREATE DATABASE gen_platform DEFAULT CHARSET utf8mb4;"
mysql -uroot -p gen_platform < docs/sql/V1.0__init.sql
```

### 2. Настройка целевого проекта

Скопируйте шаблон конфигурации и измените пути под свою машину:

```bash
cp src/main/resources/application-local.yml.example src/main/resources/application-local.yml
```

`application-local.yml` исключён в `.gitignore` и не попадёт в коммит. Основные параметры:

```yaml
gen:
  output:
    backend-root: /path/to/your-target-project      # база записи артефактов на диск
    frontend-root: /path/to/your-target-project
    frontend-path: demo-web                          # подкаталог фронтенда в monorepo
    backend-path: demo-server/src/main/java/com/demo
    package-name: com.demo
    root-package: com.demo                           # префикс импорта базовых классов в артефактах
  selfcheck:
    classpath: /path/to/your-target-project/demo-lib/*
```

Каталог зависимостей для самопроверки выгружается так:

```bash
cd your-target/demo-server
mvn dependency:copy-dependencies -DoutputDirectory=../demo-lib
```

### 3. Запуск бэкенда

```bash
mvn package -DskipTests
java -jar target/codegen-server.jar
```

По умолчанию сервис слушает порт **8120**, документация API — `/swagger-ui/index.html`.

### 4. Запуск фронтенда

```bash
cd ../codegen-web
npm install
npm run serve
```

По умолчанию фронтенд слушает порт **9530**, запросы `/dev-api` проксируются на бэкенд 8120. Учётная запись по умолчанию `admin / admin123`.

### 5. Ключевые параметры конфигурации

| Параметр | Описание |
| --- | --- |
| `gen.output.*` | Пути записи артефактов, имена пакетов, сопоставление модулей |
| `gen.selfcheck.classpath` | Classpath зависимостей для компиляции в памяти при самопроверке, поддерживает `dir/*` |
| `gen.menu.outlet` | `artifact` — только SQL меню и фрагменты маршрутов; `internal` — дополнительно запись в собственную `sys_menu` платформы |
