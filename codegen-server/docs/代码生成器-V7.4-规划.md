# 代码生成器 V7.4 规划 —— 可重复交付：空库能部署、每次提交都保证能跑

> 日期：2026-11-07　状态：**规划待过目**
> 盘点基准：`master` `40e7a25`（第五轮走查收口）、`audit-2026-11-06.md` 五轮台账、`docs/代码生成器-V7.3-功能盘点与规划.md`。
> 定位：**不新增任何能力包**，把五轮走查反复暴露的两笔债一次性结清——「换台机器就炸」和「验证体系跟不上开关组合爆炸」。

## 一、主题与理由

平台的功能密度已经不是瓶颈。V7.3 把「交付可信度」推到了流水线内部（自检编译产物测试、统一 SQL 交付出口、表级 AI 推荐），但**平台自身**的交付可信度还停在「靠人记得」：

1. **空库部署必炸**（F-07 / F-08）：`sys_oper_log` 缺 4 个审计列、`gen_pipeline` / `gen_pipeline_step` 根本没有建表脚本。现在能跑，是因为开发库被手工 `ALTER` 过。
2. **240 例测试全绿，仍漏到第五轮才抓到 P0 白屏**：黄金基线是「固定场景快照」，而生成器的输出空间是 2^N 个开关组合。第五轮枚举 1024 种组合发现 192 种会产出语法错误的前端页面——这次是人工枚举，没进仓库。
3. **两仓 0 个 CI 配置**：`mvn -o test`、`npm run build`、模板三副本 MD5 校验全靠本地手动跑；`pom.xml:155` 还留着 `failIfNoTests=false`。

所以 V7.4 的验收口号是二值的：**在一台全新的机器、一个空的数据库上，一条命令跑完全部检查并全绿。**

**为什么不是别的**

| 候选 | 不选的理由 |
|---|---|
| V6.9 平台文档中心收尾 | 已有独立 160 行规划文档，后端 1283 行在制品未完成前端；属于「把已有版本做完」，不是「规划一个新版本」。但它的在制品必须在本版前置处置，见 P0-0 |
| V8.0 能力大版本（C 端商城 / 交易闭环 / 新 AI 特性） | 每加一个能力包就多一批开关组合，在验证体系升级之前继续加功能，等于继续放大第五轮那个「元问题」 |
| V7.5 鉴权改造版（C-01 + E-06） | 台账三次建议合并成独立版本做集成测试自证，不宜夹带在部署/构建批次里 |
| 拆 `GenScaffoldServiceImpl`（4917 行） | 纯内部重构、无用户可见收益，需要产物测试等价证明，继续顺延 |

本版编号取 V7.4 而非 V8.0：不新增用户可见能力，是对 V7.3「交付可信度」的补完，属维护性小版本。

### P0-2 CI 门禁（W-01 / W-03 / W-09 + 模板三副本）

- 新增 **`scripts/verify.sh`** 作为唯一入口，本地与 CI 跑同一份命令：
  1. `mvn -o clean test`（`clean` 清掉 `target/surefire-reports` 幽灵报告）；
  2. 按 **`<testcase>` 节点数**统计而非 `tests` 属性，低于阈值即失败（修 W-01 计数失真）；
  3. 模板三副本 MD5：源码 `.ftl` / jar 内 `BOOT-INF/classes/gen-templates/` / DB `gen_template`；
  4. `cd ../codegen-web && npm run build`；
  5. `scripts/smoke-fresh-db.mjs`（需 MySQL 的 profile 可开关）。
- `pom.xml:155`：`failIfNoTests=false` → **`true`**。
- **W-03 优先**：把数据库 URL 守卫前移到 `EnvironmentPostProcessor`，在 `schema-test.sql` 的 `DROP TABLE` **之前** fail-fast。现在测试启动就会 DROP 7 张表，误连生产库的后果不可逆。
- CI 配置：给一份 GitHub Actions 示例 `.github/workflows/verify.yml`，并注明 Gitee Go 直接复用 `verify.sh`（不臆造 Gitee 语法）。
- 打首个 tag **`v7.4.0`**（当前 tag 数 0）。

### P0-3 生成物级组合验证（本版技术核心）

把第五轮「人工枚举 1024 组合」固化成仓库里的常驻能力：

- `GenCombinationMatrixTest`：枚举生成开关 ≥1024 种组合（`genAddApi` / `genEditApi` / `genDeleteApi` / `genPageApi` / `genTree` / `hasFlow` / `hasExcelImport` / `hasSingleUnique` / `hasRef` / `fileEnabled` 等），渲染 `vuePage.ftl` / `apiJs.ftl` / `controller.ftl`，产物落 `target/gen-matrix/`。
- `scripts/check-generated-js.mjs`：Node 侧对产物 `<script>` 段做 `new Function` 语法校验，输出坏组合清单。Node 已在工具链里（`scripts/*.mjs`、前端构建均依赖），**缺 Node 时报明确错误，不静默跳过**。
- **反向验证（必须）**：临时回退 `vuePage.ftl:579` 的 `|| hasFlow` → 矩阵必须报出 **192 种**坏组合（第五轮 F-01 实测值），证明校验不是摆设；验证后恢复。
- 5 个共享模板纳入 `GenTemplateBaselineTest.TEMPLATES` 空模型场景（第四轮建议 1），补 `hasFlow`-only / `hasExcelImport`-only 等单开关组合。
- 生成的 Java 产物复用 `GenSelfCheckTestCompileTest` 的独立 classpath 编译做语法级校验，不污染主编译。
- **规模控制**：开关继续增加时改用 pairwise（成对组合）+ 必测组合白名单，单次 CI 预算 ≤3 分钟，避免 2^N 膨胀到跑不动。

### P0-4 公共异常映射收敛（W-08 / C-03 局部）
