# 代码生成器 V6.9 规划 —— 平台文档中心：Word / PDF 在线预览（双引擎）

> 日期：2026-10-30　状态：**规划待过目**
> 定位：给 **codegen 平台自己**加「文档库 + 在线预览」——需求单、验收单、设计稿的 Word/PDF 直接在页面上看，不用下载再打开。
> 前置事实：V6.6 文件能力包只做进**产物工程**（scaffold 写 `sys_file` + `/file` 端点），平台侧至今没有上传、存储、预览任何一块基座。

## 一、现状核对（2026-10-30 实测）

| 项 | 现状 | 位置 |
|---|---|---|
| 平台上传能力 | **无**：`application.yml` 没有 `spring.servlet.multipart` 配置，全仓没有一个接收 `MultipartFile` 的端点（只有 `LogAspect` 引用了该类型做日志脱敏） | `application.yml`、`com/codegen/**` |
| 平台文件表 | **无** `sys_file` / `sys_doc`；`sys_file` 只存在于 `scaffold-file/`（写给产物） | `docs/sql/`、`src/main/resources/scaffold-file/` |
| 平台前端上传组件 | **无**：`codegen-web` 只有 `theme.css` 里两条 `el-upload` 暗色样式 | `src/styles/theme.css:586` |
| 平台静态资源映射 | **无** `addResourceHandlers` / `WebMvcConfigurer` 子类 | `com/codegen/config/` |
| 平台鉴权 | `AuthContextFilter` 单层：只校验 Bearer token，**无方法级权限码校验**；白名单 7 个前缀 | `AuthContextFilter.java:43-51,156-168` |
| 前端技术栈 | Vue 2.7.16 + Element UI 2.15.14 + vue-cli 5（webpack 5） | `codegen-web/package.json` |
| 文档资产 | 需求/设计/效果图以 md + html 存在 `docs/`，Word/PDF 只能本地打开 | `docs/` |
| 菜单机制 | `sys_menu` 带 `perms` 字段，每版一条菜单 SQL（V2.1/V3.1/V4.0 有先例） | `docs/sql/V*.sql` |

**结论**：这不是「加个预览按钮」，而是要在平台侧补齐「上传 → 存储 → 元数据 → 预览 → 权限 → 菜单」整条链路，预览只是最后一环。

## 二、主题与理由

**为什么是它**：

1. **只有平台自己在用**：需求/设计/验收单是 Word/PDF 场景的真实载体，产物工程里 `file` 字段（V6.6）反而很少放 Word。先给平台补，收益立刻可见。
2. **风险面可控**：不碰产物模板、不碰生成链路、不碰三态开关体系——改的是平台独占的 controller / 页面 / 一张新表，回归面只是平台自身（现有 175+ 例测试不受影响）。
3. **复用已有约定**：产物 V6.6 已经把「白名单 + uuid 落盘 + 相对路径 + 双保险防穿越 + 按 id 查库」踩平，平台侧照搬即可，不需要重新设计存储。
4. **为产物侧留扩展位**：前端预览组件（PDF / DOCX）做成独立组件，V6.6 的 `FileUpload.vue` 后续可直接引用，不必重写。

**为什么不是别的**：

- C 端只读商城生成（V6.8 规划里原定 V6.9）：依赖 V6.8 的素材/品牌/字典地基，且体量大；本版完成后顺延为 **V7.0**。
- 交易闭环（订单状态机/库存）：接 V6.3 支付，量级更大，留 V7.x。
- 拆 `GenScaffoldServiceImpl`（4,800+ 行）：纯内部重构，无用户可见收益，继续顺延。

## 三、范围

### P0-1 平台文件存储基座

- 新表 `sys_doc`（`docs/sql/V6.9__sys_doc.sql`，幂等）：`id / original_name / storage_name / relative_path / ext / content_type / file_size / md5 / create_by / create_time / update_by / update_time / deleted / remark`。**不存公开 URL**——平台预览一律走鉴权接口，不开放免登录直链（见 P0-5）。
- 落盘：`{doc.upload-dir}/{yyyyMM}/uuid.ext`，默认 `./uploads/doc`；上传只取扩展名，落盘名与原名完全解耦。
- 平台 `application.yml` 补 `spring.servlet.multipart`（单文件 30MB / 请求 35MB）+ `doc` 配置块（`upload-dir / allowed-exts / max-size-mb`）。
- `DocController`：`POST /doc/upload`、`POST /doc/page`（名称/类型过滤，分页钳位）、`DELETE /doc/{id}`（逻辑删）、`GET /doc/download/{id}`（attachment）。
- 白名单默认 `pdf,doc,docx,xls,xlsx,ppt,pptx`；**刻意不含 svg/html/md**（平台不做富文本渲染，避免再次引入 V6.6 那类同源 XSS）。

**验收**：上传 5MB PDF 与 2MB DOCX 各一，`sys_doc` 两行记录；列表分页、名称过滤正确；下载响应头带原始中文名；扩展名白名单外（如 `.exe/.svg`）被拒且提示明确。

### P0-2 PDF 在线预览

- `GET /doc/preview/{id}`：认证后返回 `Content-Type: application/pdf`、`Content-Disposition: inline`、`X-Content-Type-Options: nosniff`；原件即 PDF 时直接流式返回，不复制。
- 前端 `PdfViewer.vue` 用 `pdfjs-dist`（**锁 `2.16.105` legacy 构建**，webpack 5 兼容最稳）渲染到 canvas：上一页/下一页/页码跳转/缩放（50%~300%）/适宽；worker 通过 `GlobalWorkerOptions.workerSrc` 指向打包后的 worker 文件。
- 取流方式：**axios `responseType:'arraybuffer'` 后喂给 pdf.js**，绝不用 iframe/`?token=`——避免 token 落到日志、Referrer 与浏览器历史（V5.0 为 SSE 开的 `access_token` 查询参数只用于 EventSource，不扩大使用面）。

**验收**：30 页 PDF 打开首屏 ≤2s（本地），翻页/缩放/跳页正常；未登录访问 `preview` 返回 401；把 id 改成不存在的值返回 404。

### P0-3 Word 在线预览（双引擎可切）

- 配置 `doc.preview.engine: auto | browser | libreoffice`，默认 `auto`：
  - `auto`：启动时探测 `soffice`（`doc.preview.soffice-path` 或 PATH）→ 有则服务端转 PDF，无则浏览器渲染。
  - `browser`：只走前端 `docx-preview`（零服务端依赖，`.docx` 可看，老 `.doc` 仅下载）。
  - `libreoffice`：强制服务端转换，探测不到 soffice 时**启动即告警并在接口返回明确错误**，不静默降级（避免「以为开了高保真、其实一直没转」）。
- 转换链路：`soffice --headless --norestore --convert-to pdf --outdir <cache> <src>`；**每次转换用独立 `-env:UserInstallation` 临时 profile**（LibreOffice 单实例锁，并发会互相打死）；信号量限 2 并发；单次超时 60s。
- 缓存：`{doc.upload-dir}/.preview/{id}-{fileSize}-{mtime}.pdf`，命中直接返回；`sys_doc` 行不可变（重传即新行），无需失效逻辑。
- 失败兜底：转换失败/超时 → 接口返回 `code=400` + 原因；前端弹提示，并自动切回浏览器引擎（`.docx` 可降级，`.doc` 提示下载）。
- `GET /doc/meta/{id}` 返回 `{previewMode: pdf | browser-docx | unsupported, engine}`，前端据此选择渲染器；`GET /doc/raw/{id}` 供浏览器引擎取原件字节（认证 + inline）。

**验收**：同一份 20 页含表格合并/页眉的 DOCX —— `browser` 模式能渲染可滚动；切 `libreoffice` 后返回 PDF 且版式与原文件一致；第二次预览走缓存（耗时 <100ms）；停掉 soffice 后 `engine=libreoffice` 接口报错文案明确。

### P0-4 文档中心页面（codegen-web）

- 新页面 `/doc/index`：表格（名称/类型/大小/上传人/上传时间/预览方式）、顶部搜索、上传（`el-upload` 拖拽 + 进度）、行操作（预览/下载/删除）。
- 预览弹窗 `DocPreviewDialog.vue`：按 `previewMode` 路由到 `PdfViewer` / `DocxViewer`；PDF 支持翻页缩放，Word 支持滚动阅读；弹窗宽 80vw、高 85vh，`append-to-body`。
- 上传组件走平台统一 `request` 封装（带 Authorization），**不复用产物里 `ImageUpload/FileUpload`**（那是给产物产出的，形态不同：产物是 v-model 回填 URL，平台是独立文档实体）。
- 预览器按需加载：`pdfjs-dist` / `docx-preview` 全部 `() => import()` 动态引入，不进首屏包。

**验收**：上传 → 列表出现 → 点预览出 PDF/Word 内容 → 下载文件名正确 → 删除后列表消失、库中 `deleted=1`；首屏包体增幅 <5KB（预览器为异步 chunk）。

### P0-5 安全与权限

- **不开免鉴权直链**：平台不注册 `/uploads/**` 静态映射，所有文件访问经 `DocController` 校验 token。理由：V6.6 的 `/uploads/**` 是为了产物前端 `<img>` 直显；平台没有这个需求，不应背同一类风险（svg 白名单收紧就是这么来的）。
- 路径安全：`relative_path` 只由服务端生成（uuid），读时 `base.resolve(...).normalize()` 后校验仍在 `upload-dir` 内，双重防穿越（照搬 V6.6）。
- 权限码 `doc:list / doc:upload / doc:remove`：菜单 SQL `docs/sql/V6.9__doc_menu.sql` 注册；后端**在 controller 上新增校验**（平台此前只有登录态、无方法级校验，不能只靠前端 `v-hasPermi` 藏按钮）；超管 `*:*:*` 直通。
- 上传侧：扩展名白名单 + 大小上限 + `StringUtils.cleanPath`；响应头补 `nosniff`；PDF 预览响应加 `Content-Security-Policy: sandbox`（现代浏览器内置 PDF 阅读器对 CSP 不敏感，但可挡住被当作 HTML 解析的降级路径）。

**验收**：普通角色无 `doc:remove` 时接口直接 403（不是只隐藏按钮）；构造 `relative_path=../../etc/passwd` 的库记录无法读出；上传 `.svg/.html` 被拒。

### P0-6 降级与运维

- `doc.preview.enabled=false` → 预览按钮变下载，页面无报错（纯配置级降级）。
- 缓存目录与清理：`.preview` 下按 30 天未访问清理（启动时一次 + 每日一次定时，`@Scheduled` 需开启 `@EnableScheduling`，若平台未开启则只在启动时清理，写进 README）。
- 启动自检日志：探测到的引擎、soffice 版本、缓存目录、上传目录可写性，各打一行；探测失败打 WARN 并说明如何配置。
- 运维手册段落写进生成器 README 的「平台部署」：装 LibreOffice 的命令（Windows/macOS/Linux 各一行）、路径配置、不装的后果。

**验收**：不装 LibreOffice 时平台启动有 WARN、预览 DOCX 正常（浏览器引擎）；装上后重启自动切高保真且日志打印版本号。

## 四、明确不做

- **产物工程的文档预览**：V6.6 已给产物 `file` 字段下载能力；把预览器接入产物是另一件事（要改 `vuePage.ftl` + 产物 `package.json` 依赖 + 基线快照），留 V7.x。
- 在线编辑 / 批注 / 协同（OnlyOffice、金山文档）：要额外文档服务器，量级完全不同。
- Excel / PPT 的**内容级**预览：`libreoffice` 引擎开启时转 PDF 顺带可得，但不列入验收（表格渲染质量不作为本版承诺）。
- md / html 文档浏览（`docs/` 目录只读浏览）：与 Word/PDF 是两套东西，需求另议。
- 对象存储、分片上传、断点续传、病毒扫描。
- 移动端适配：平台是桌面工作台，窄屏仅做不崩（不做专门布局）。

## 八、风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 浏览器引擎渲染失真（表格合并 / 页眉页脚 / 嵌入对象） | 用户以为文件坏了 | 预览弹窗顶部提示「简易渲染，如需高保真请启用 LibreOffice」；`.doc` 直接提示下载 |
| LibreOffice 单实例锁 / 并发互杀 | 转换随机失败 | 每次独立 `-env:UserInstallation` + 信号量 2 + 60s 超时 + 失败重试一次 |
| LibreOffice 首次转换慢（3~8s 冷启动） | 首次预览体验差 | 缓存 + 弹窗 loading + 启动可预热一次 `--version` |
| 大 PDF 在 canvas 渲染吃内存 | 30 页以上卡顿 | pdf.js 逐页渲染只渲染可视页；上限 100 页提示分页下载；单文件 30MB 上限 |
| 平台无方法级权限先例，新增校验点可能影响其他接口 | 误伤 | 只在 `DocController` 加校验，不动全局 filter；超管直通；用测试覆盖 |
| pdf.js worker 在 webpack 5 下路径错 → 预览白屏 | 返工 | 固定 `pdfjs-dist@2.16.105` legacy，worker 用 `CopyWebpackPlugin`/`require` 静态拷到 `public/`；S8 必须实测 production build |
| 平台内网部署时 LibreOffice 打开恶意文档 | 安全 | `--norestore`、独立 profile、转换进程超时可 kill；服务端不解析宏（默认不执行） |
| 预览接口被换成 iframe 直开导致 token 进 URL | 泄漏 | 代码里禁用 iframe 方案，统一 axios arraybuffer；code review 检查点 |
