# 代码生成器 V6.4 规划 —— 权限、安全与配套：产物安全基线闭环

> 日期：2026-10-25　状态：规划待过目
> 与 V6.1（工作流）/V6.2（交付面）/V6.3（支付）无强耦合，可任意排序；但**建议 V6.4 优先**——安全欠账是四版中唯一「已产生真实用户伤害」的（token 内存态导致的重启掉线）。
> 定位：产物安全从「能挡陌生人」升级到「权限闭环 + 密码学合格 + 登录设防」。

## 一、现状核对（2026-10-25 实测）

| 项 | 现状 | 位置 |
|---|---|---|
| 登录鉴权 | TokenStore（**内存 ConcurrentHashMap**）签发/校验 UUID token，AuthContextFilter 白名单（/auth/login）+ 有效性校验 | `GenScaffoldServiceImpl:205,2784-2864` |

**问题**：产物「能挡住没登录的人」，但挡不住「登录了的低权限的人」——接口级越权全通；密码哈希是不合格但明知未修的欠账；token 内存态是唯一已造成真实用户困扰的点。

## 二、主题与理由

**主题：产物安全基线四件套——① token 持久化（重启不掉线）；② 密码 BCrypt 升级（SHA-256 平滑迁移）；③ 接口权限点后端强制（权限闭环）；④ 登录防护（验证码 + 失败锁定 + 登录日志）。**

理由：

1. **token 持久化优先级最高**：不是理论风险而是已发生的用户伤害（10-24「服务异常」工单），修复成本低（一张 sys_session 表）；
2. **权限闭环是「权限」二字的应有之义**：perms 生成链路（V3.0 五级回落）与前端 v-perm 都已就位，唯独后端校验缺失——补上即闭环，改动集中在 AuthContextFilter 与角色查询，模板面改动小；
3. BCrypt 与登录防护是脚手架注释里**自认的欠账**（:2944），技术方案无争议，纯执行；
4. 数据权限雏形已有，本版只做 UI 化收尾（P1），不重复造轮子。

## 三、范围

### P0-1 Token 持久化（重启不掉线）

- 产物新增 `sys_session` 表（token/user_id/login_ip/login_time/expire_time/deleted，进 db.sql 与自检标准列）；TokenStore 改为「内存缓存 + DB 落盘」双层：签发写库、校验先查内存（TTL 60s）miss 回源查库——**内存加速、重启不丢**
- 过期策略：默认 24h 滑动续期（yml 可配 `auth.session-hours`）；启动时惰性清理过期行 + @Scheduled 每日清理
- 登出同步删行；单用户多端在线默认允许（P1 可加互踢开关）

### P0-2 密码 BCrypt 升级（平滑迁移）

- 依赖 spring-security-crypto（仅 crypto 模块，**不引入 Spring Security 全家桶**——与 AuthContextFilter 自研体系不冲突）
- `sys_user.password` 列扩至 varchar(72)（BCrypt 60 位）+ `password_algo` 标记列（sha256/bcrypt）；新用户与改密一律 BCrypt（强度 10，yml 可配）
- **无感迁移**：登录校验按 algo 分派——旧 SHA-256 命中后立即用 BCrypt 重哈希写回并更新 algo 标记；全量用户在自然登录中完成迁移，无需停机刷库
- 平台侧 scaffold 的 seedSql（admin 初始密码）同步改为 BCrypt 预生成值

### P0-3 接口权限点后端强制（权限闭环）

- `sys_role_menu.perms` 已由 V3.0 五级回落生成——本版把校验接上：
  - AuthContextFilter 升级两级：第一级登录校验（现状保留），第二级**权限点校验**——登录后加载用户 perms 集（sys_user_role→sys_role_menu.perms，60s 缓存随 P0-1 同模式），请求按「HTTP 方法 + 路径→perms」映射比对
  - 映射来源：controller.ftl 生成接口时同步产出**接口-perms 映射清单**（编译期常量类 `GenApiPerms`，查询类 read/list/export、写类 add/edit/delete 逐端点挂 perms，缺省 read:* 兜底）
  - 无权返回 403「无该操作权限」；perms 为空的存量接口按只读放行、写操作拒绝（安全缺省）
- 前端零改动（v-perm 已对齐同一 perms 值）；角色管理页已有（复用 sys_role_menu 授权 UI）
- 超管角色（id=1 或 code=admin）直通不校验

### P0-4 登录防护三件套

- **验证码**：算术验证码（服务端生成图，答案存 sys_session 同表或独立 cache，60s 有效一次性）——零第三方依赖，比图形字符库简单可靠
- **失败锁定**：同用户名 5 次失败锁 10 分钟（计数落库防重启清零），锁定期间登录返回明确提示；成功登录清零
- **登录日志**：`sys_login_log`（username/ip/归属地/结果/fail_reason/时间），复用 V4.3 IP 归属地组件；管理页只读列表（复用 vuePage 模板）

### P1（本版尽力，不做门禁）

- 数据权限 UI 化：角色上配 data_scope（all/dept/self），部门树勾选联动（拦截器与 Holder 已有，纯前端+配置落库）
- 文件上传安全约定模板：白名单后缀 + 大小限制 + 存储路径隔离（给用户自加上传功能时的标准件）
- 接口限流：AuthContextFilter 内简单令牌桶（登录/导出类敏感端点优先）
- 密码复杂度策略（长度≥8 + 字符种类，yml 可配）与改密页模板
- 安全响应头基线（X-Content-Type-Options 等 Filter 一行件）+ HTTPS 部署引导文档

### P2（明确不做，下版再说）

- SSO / OAuth2 / LDAP 对接（企业级场景，等真实需求）
- 双因素认证（短信/OTP）
- 审计日志外发（SIEM/Syslog）
- 字段级加密存储（身份证/银行卡号）

## 四、关键设计决策

| 决策点 | 定案 | 理由 |
|---|---|---|
| token 方案 | DB 落盘 + 内存缓存，**不改 JWT** | JWT 无状态看似优雅但「强制下线/改密踢出」做不到，且产物已是 UUID token 体系，改 JWT 动静大收益小；DB 层同时天然支持登录日志与锁定计数复用 |
| BCrypt 迁移 | 登录时无感重哈希，不做停机刷库脚本 | 全量刷库要求掌握所有存量系统的运维窗口，不现实；自然迁移零运维成本，过渡期内两种算法并存由 algo 列分派 |
| 权限校验位置 | Filter 集中校验（映射清单），不用 @PreAuthorize 注解 | 注解方式要改 12 个模板的每个端点签名且易漏；集中式一处实现全接口覆盖，GenApiPerms 常量类与五级回落同源生成，不易漂移 |
| 缺省策略 | perms 缺失的写操作**拒绝**、读操作放行 | 安全缺省（fail-closed）：存量系统升级后宁多一次配置也不裸奔写接口 |
| 验证码形态 | 算术验证码，不引图形库 | 产物原则「零重依赖」；算术码对机器识别的防护弱于扭曲字符，但对产物这一非高价值目标场景够用，P2 可换 |
| BCrypt 依赖 | spring-security-crypto 单模块 | 全家桶会接管安全链路与 AuthContextFilter 打架；单 crypto 模块只有哈希工具类 |

## 五、验收标准

1. 产物重启 → 刷新页面**不掉线**（token 仍有效，业务接口正常响应）；过期会话（改短 TTL 验证）被拒并清理
2. 旧 SHA-256 存量用户登录成功且 password 列已变为 BCrypt 格式、algo=bcrypt；新用户注册即 BCrypt
3. 非 admin 角色用户：无 delete perms 时调 DELETE 接口返回 403，日志留痕；授予后通过；admin 直通
4. 错误密码 5 次 → 第 6 次明确提示锁定；10 分钟后自动解锁；全程 sys_login_log 留痕
5. 平台全量测试绿 + 产物黄金基线对 auth 相关变更场景零意外 diff（基线快照按新产物更新一次）
