## 1. 主题与边界

用户指定 V9.3 主题为「**生成产物自动化测试**」：不是重写测试中心，而是在 V9.2 验证中心（S1–S9 平台自身质量门禁）之上，增加对**一句话建系统生成出来的目标工程**的自动化验证。

| 维度 | V9.2 验证中心 | V9.3 新增 |
| --- | --- | --- |
| 验证对象 | 代码生成器平台自身 | 生成产物（目标工程的后端 / 前端） |
| 套件 | S1–S9 | S10 / S11 / S12 |
| 触发 | MANUAL / CI / SCHEDULE / RERUN | 追加 `GEN` |
| 输入 | 无（跑平台仓库） | `TC_GEN_ROOT`（产物根目录） |
| 落库 | run / case / artifact 三层 | 复用同一套三层结构 |

**边界**：不新增生成能力、不改控制台技术栈、不把结果接成合并阻断门禁；S11/S12 依赖的外部工具链缺失时必须如实 `SKIPPED`，不得伪造通过。

新建 **设备资产管理系统**（`v93_asset_demo`，manual DDL，4 张表：`asset_category` / `asset_supplier` / `asset_device` / `asset_maintenance`），流水线 `PPL20261114142047`：

| 服务 | 平台 8120 / 产物后端 8140 / 产物前端 9040 / 控制台 9530 均在监听 |
| 真实产物 GEN 验证 | `TC20261114-00147`、`TC20261114-00109` 均 **PASSED**，`total=3 / passed=1 / failed=0 / skipped=2` |
| S10 | 真跑产物自带 4 个 ControllerTest，**20/20 用例全过**（不再是 2 条最小夹具冒烟） |
| S11 / S12 | 无 Docker / 无 Playwright，如实 **SKIPPED** |
| 三层落库 | `tc_run` 1 行 + `tc_case_result` 3 行 + `tc_artifact` 3 个日志（S10.log 41873 B 等） |
| 编译 / 构建 | `mvn -o compile`、`mvn -o package`、`TcSuiteRegistryTest`、控制台 `npm run build` 全部通过 |

**全流程实测顺带修掉的真实缺陷**（坑库 `dev-doc/02-坑/` 坑 65–69）：

1. `GenSelfCheckServiceImpl.compileTests()` 缺「肥 jar 且未配 classpath 就诚实跳过」保护（V9.2 #5 只覆盖主编译）；`addScaffoldTestSources()` 把脚手架已落盘的基座测试类显式加入 javac 编译单元。
2. `scaffold-test/LoginStateTestSupport.java` 模板占位符 `__PKG_` → `__PKG__`。
3. `PipelineExecutor` 命令参数里的 pom / jar 路径绝对化（子进程相对 cwd 二次解析）。
4. `stepDeployFrontend()` 按产物 `package.json.scripts` 自动选 `dev`(Vite) / `serve`(vue-cli)，修掉「控制台 Vue2 与生成物 Vue3 技术栈串台」。
5. 重跑用 `LambdaUpdateWrapper.set(col, null)` 显式清场，规避 MyBatis-Plus NOT_NULL 策略导致 `fail_reason` 残留。
6. 生成产物 Vue3 页面 3 处 Vue2 遗留：`vuePage.ftl` 尾部 `gen:end` 标记、`GenMenuServiceImpl` 的 `GroupView` 改用 `h(RouterView)`、9 处 `>>>` → `:deep()`。
