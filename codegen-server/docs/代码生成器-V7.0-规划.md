## 二、主题与理由

**为什么是它**：

1. **人工配置是建模之后最大的剩余成本**：AI 建模 30 秒出 30 张表，但每表 25+ 列级开关、模块分组、树形/主子识别仍需逐表手调，「配表即出」断在最后一环。
2. **AI 干这事恰好擅长**：列注释+列类型 → 查询方式/表单控件/字典，是强模式匹配任务；菜单分组是常识性归纳，比规则推断覆盖面大得多。
3. **设施全现成**：AI 调用通道、降级原则、pipeline 步骤挂点、规则推断基线都已存在，本版只做「一个新步骤 + 建议暂存 + 预览应用」，不动生成主链路。
4. **预览确认控制信任成本**：AI 建议不直接落库，diff 预览 + 勾选应用，错误建议的代价是一次取消勾选，而不是回滚配置。

**为什么不是别的**：

- 产物 AI 能力包（生成系统自带 AI 对话/RAG）：价值大但与生成器主线无关，属于「产物功能」序列（同支付/文件能力包），另立版本。
- 对话式迭代建模：依赖建模结果的多轮 diff 协议，复杂度高；先让单轮推荐跑通，多轮是后续演进。
- AI 审查 DDL：收益集中在导入期，而导入期已有模板/规范约束，痛感低于配置期。

## 三、范围

### P0-1 AI 推荐服务 `AiRecommendService`

- 输入：本系统全部表与列元数据（表名/注释/列名/注释/类型/是否主键/现有推断值）。
- 输出三层建议 JSON：
  - **列级**：`is_query / query_type / is_list / is_form / html_type / dict_type / sort`
  - **表级**：`module_name`（模块分组）、`tree_parent_column / tree_label_column`（树形识别）、`master_table_id / relation_type`（主子/中间表）
  - **菜单组织**：目录层级、菜单名称、图标候选、排序
- 分批策略沿用 model/modules 两段式：先按模块分组，逐模块调用，单批输出预算可控（本地小模型可用）。
- 结构化输出约束（JSON Schema / Function Calling），不做自由文本解析。

**验收**：对 40 表示例系统跑一批，建议 JSON 完整无截断；每项建议可定位到 tableId + 字段名。

### P0-2 pipeline 新步骤 `ai_recommend`（仅自动）

- 挂点：表结构就绪后、模板生成前，作为独立步骤自动执行；本期不做手动触发入口。
- 服务端白名单校验：枚举值（html_type / query_type / dict_type）必须在合法集内；引用的列名/表名必须存在；主子引用不得成环。非法项**逐项丢弃**并记录原因，回落 V6.6 规则默认值。
- 降级：`ai.enabled=false` → skipped；超时（沿用 30s）/ 调用失败 / JSON 截断 → failed-degraded。两种降级都不阻断 pipeline，用规则默认继续生成，产物与 V6.8 行为一致。

**验收**：见 AC-1 / AC-2 / AC-5。

### P0-3 建议暂存 + diff 预览 + 勾选应用

- 建议暂存于 pipeline 步骤产物 JSON，**不落** `gen_table / gen_table_column`。
- 前端预览页：三层分组展示「当前值 vs 建议值」diff，逐项勾选；已手改字段（与规则默认不一致）标记「已手改」默认不勾选。
- 「应用」时才写库：列级/表级写 `gen_table_column / gen_table`；菜单组织参数不落 sys_menu，作为写盘后菜单注册环节的输入。
- 未应用直接生成 = 全部走规则默认，预览页可随时回来看，但 pipeline 结束后建议随步骤归档只读。

**验收**：见 AC-3 / AC-4。

## 四、明确不做（Out of scope）

- 产物侧 AI 能力包（AI 对话/RAG 进生成物）
- 对话式迭代建模、AI 审查 DDL、AI 种子数据/错误修复
- 表配置页手动「AI 推荐」按钮
- 模型配置 UI（沿用 yml）

## 五、验收标准（二值）

- AC-1 `ai.enabled=false` 跑 pipeline → 步骤 skipped，产物与 V6.8 完全一致
- AC-2 AI 返回非法枚举/不存在的列名 → 该项丢弃 + 回落规则默认 + 日志记录，pipeline 不中断
- AC-3 未点应用 → `gen_table / gen_table_column` 零 UPDATE
- AC-4 勾选应用 → 被选项与建议一致写库，重新生成的 vue 页面与菜单随之变化
- AC-5 AI 超时 → failed-degraded，pipeline 整体成功（带降级标记）
- AC-6 40 表系统分批调用 → 无截断 JSON，建议完整暂存

## 六、风险与缓解

| 风险 | 缓解 |
|---|---|
| token 成本随表数增长 | 分批 + 输出预算上限；只传必要元数据 |
| AI 建议覆盖手改 | 「已手改」标记默认不勾选；应用动作显式触发 |
| 小模型输出不稳 | JSON Schema 约束 + 逐项白名单校验 + 降级规则基线兜底 |
| 主子/树形误识别 | 引用存在性校验 + 成环检测 + 预览页人工把关 |
