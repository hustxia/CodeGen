# 代码生成器 V6.10 规划 —— 平台可观测性（Actuator + 度量面板）

> 日期：2026-11-10　状态：**规划待过目**
> 定位：给平台补上「能看见自己在干什么」的能力——JVM/HTTP 基础指标、生成与流水线的业务指标，以及平台内的一页监控面板。
> 版本身份：V6.10（原 MCP 方案已取消，不实施）。

## 一、现状核对（2026-11-10 实测）

| 项 | 现状 | 位置 / 证据 |
|---|---|---|
| Actuator 依赖 | **无**。`pom.xml` 只有 `spring-boot-starter-web` / `aop` / `test` | `pom.xml` grep `actuator|micrometer|prometheus` 零命中 |
| management 配置 | **无**。`application.yml` 没有任何 `management:` 节点 | 全文 grep 零命中 |
| 探活端点 | **不存在**。全仓无 `/health` Controller | grep `@RequestMapping("/(health|monitor)` 零命中 |
| 鉴权白名单 | 有 `/actuator` 和 `/health` 两条，但**指向不存在的端点**，属死条目 | `AuthContextFilter.java:43-51` |
| 定时任务能力 | **无 `@EnableScheduling`**，项目从未引入 Spring 调度 | 全仓 grep `EnableScheduling` 零命中 |
| 前端监控页 | **无**。无监控菜单、无 ECharts 依赖 | `codegen-web/src` grep `actuator|monitor|metrics|echarts` 零命中 |
| 现有可观测手段 | 仅 logback 文件日志 + `sys_oper_log` 操作审计（业务级，非性能级） | `logs/codegen-server.log`、`common/log/` |

**结论**：这不是"补几个配置"，而是从 0 建。但同时要顺手修掉两条死白名单——它们是安全噪音：给不存在的路径开门不危险，但会让人误以为"探活已经有了"。

## 二、版本决策（已确认）

| 决策项 | 结论 | 理由 |
|---|---|---|
| 版本号 | **V6.10**（MCP 取消，不占用版本号） | 纯平台侧能力，零产物模板改动 |
| 采集与存储 | **Micrometer + 内存环形缓冲**（5s 一采，保留 30 分钟，360 个样本点） | 单机平台，零外部部署、零新表；代价是重启丢历史、多实例不共享，已接受 |
| 面板形态 | **平台内嵌「系统监控」页**（Vue + ECharts），数据走后端 `/monitor/*` 聚合接口 | 前端不直接暴露 actuator 原始结构，字段与权限都可控 |
| 端点暴露 | **只白名单 `/actuator/health`**；`metrics` 等必须带 token；`env/beans/heapdump/threaddump/loggers` 永不暴露 | 最小暴露面；同时把 `/health` 死条目删掉 |

## 三、范围

### P0-1 依赖与安全基线

- 新增 `spring-boot-starter-actuator`（Boot 3.2.5 自带 Micrometer 1.12，无需单独引）。
- `application.yml` 新增 `management` 段，**枚举式放行**，不用 `*`：

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics        # 不含 env/beans/heapdump/threaddump/loggers
  endpoint:
    health:
      show-details: never                   # 不对外吐数据库地址等内部信息
  metrics:
    tags:
      application: codegen-server
    web:
      server:
        max-uri-tags: 100                   # 防 URI tag 基数爆炸
```

- `AuthContextFilter.WHITE_LIST`：删 `/health`，把 `/actuator` **收窄为 `/actuator/health`**。
  现有匹配逻辑是 `path.equals(prefix) || path.startsWith(prefix + "/")`，因此 `/actuator/health/liveness` 这类子路径仍自动放行，无需逐条列。
- 单测断言：`WHITE_LIST` 不含 `/actuator` 整体、`exposure.include` 不含 `env/heapdump`。

### P0-2 采样与环形缓冲

- **本版必须新增 `@EnableScheduling`**（平台首次引入调度）。单独放 `config/MonitorConfig.java`，不污染主启动类。
  同时显式设 `spring.task.scheduling.pool.size: 2`——默认单线程，将来再加定时任务会互相阻塞。
- `MonitorSampler`：`@Scheduled(fixedDelayString = "${monitor.sample.interval-ms:5000}")`，每轮构造一个不可变 `MetricSnapshot` 放入 `ArrayDeque`（容量 360，满了 `pollFirst`）。
- 采样项全部从 `MeterRegistry` 读，不另建计数：

| 分类 | 指标 | 来源 |
|---|---|---|
| JVM | 堆已用/上限、非堆已用、线程数、GC 暂停累计次数与耗时 | `jvm.memory.used/max`、`jvm.threads.live`、`jvm.gc.pause` |
| 进程 | CPU 使用率、启动时长、可用处理器数 | `process.cpu.usage`、`process.uptime`、`system.cpu.count` |
| HTTP | 区间请求数、QPS、平均耗时、P95/P99、错误数（5xx/4xx） | `http.server.requests`（**开启直方图**：`management.metrics.distribution.percentiles-histogram.http.server.requests: true`） |
| 业务 | 见 P0-4 | 自定义埋点 |

- 采样任务体内必须 `try/catch` 全包并 `log.warn`，绝不让异常冒到调度器。

### P0-3 聚合接口

对外统一 `Result` 信封（与全平台一致），路径前缀 `/monitor`，权限码统一 `monitor:view`。

| 接口 | 方法 | 入参 | 返回 |
|---|---|---|---|
| `/monitor/overview` | GET | — | 实时快照：JVM/CPU/线程/启动时长/版本/采样开关状态 |
| `/monitor/series` | GET | `metric`（如 `jvm.heap`）、`minutes`（1~30，默认 30） | `{points:[{t,v}], unit}` |
| `/monitor/http` | GET | `minutes`、`topN`（默认 10） | 区间 QPS、平均/P95/P99 耗时、错误率、Top N 慢接口（`uri/method/count/avgMs/maxMs`） |
| `/monitor/business` | GET | `minutes` | 生成批次次数与成功率、写盘文件数、pipeline 各状态计数、文档转换耗时 |

- `metric` 走**白名单枚举**（`jvm.heap` / `jvm.threads` / `process.cpu` / `http.qps` / `http.p95`），非法值返回 400，不把参数透传给 MeterRegistry。
- 窗口未满时返回已有点数，并在 `warmup: true` 标记，避免前端误判断线。

### P0-4 业务埋点（最小侵入）

只在 4 个位置加 `Timer.Sample` + try/finally，**不新增自定义 AOP 切面**（平台上切面已经够多了）：

| 位置 | 指标 | 说明 |
|---|---|---|
| `GenCodeServiceImpl#writeToDisk` | `gen.write` timer + `gen.write.files` counter(按结果 tag) | 最关心的"一次生成写了多少文件" |
| `GenCodeServiceImpl#preview` | `gen.preview` timer | 预览耗时，用于判断是否需要缓存 |
| `PipelineExecutor` 步骤收尾 | `pipeline.step` timer + `pipeline.run` counter(tag: `state=success/fail/stopped`) | 面板上的流水线成功率来源 |
| `DocPreviewEngine#convertToPdf` | `doc.convert` timer + counter(tag: `result=hit/converted/failed`) | V6.9 的 LibreOffice 转换是已知慢点，必须可见 |

- 埋点失败不得影响主流程：`MeterRegistry` 调用包在 `try/catch` 里，异常只记 debug 日志。
- 不为每个业务动作都埋点——只埋"会慢、会失败、会被追问"的 4 处。

### P0-5 前端监控页

- 新依赖 `echarts`（按需引入 `LineChart` + `GaugeChart` + `CanvasRenderer`，不整包引入）。
- `src/api/monitor.js`（4 个接口）+ `src/views/monitor/index.vue`。
- 页面结构（与 S4 效果图对齐后实施）：
  1. 顶部 4 张指标卡：堆内存使用率、活跃线程、区间 QPS、平均响应耗时
  2. JVM 趋势区：堆内存折线 + 线程数折线（近 30 分钟）
  3. HTTP 区：QPS + P95 双轴折线；下方 Top N 慢接口表格
  4. 业务区：生成批次成功率环形图、写盘文件数柱状、pipeline 状态分布、文档转换耗时折线
- 刷新：5s 轮询，`document.visibilitychange` 隐藏时暂停、恢复时立即拉一次；`beforeDestroy` 清定时器（防止菜单切换后定时器泄漏）。
- 菜单：`sys_menu` 新增 `id=3030 /path=/monitor/component=monitor/index/perms=monitor:view`，沿用 V6.9 验证过的 `require.context` 动态路由机制，**不改 router/index.js**。
- id 段确认：V6.9 已占用 3000/3010/3020，本版用 3030 段。

### P0-6 探活与文档

- `/actuator/health` 免 token 可访问，返回 `{"status":"UP"}`；`show-details=never` 保证不泄露 DB/JVM 细节。
- 数据库健康灯沿用 Boot 自带 `DataSourceHealthIndicator`（默认开启），无需自写。
- `docs/` 补一页《可观测性说明》：指标含义、采样窗口限制（重启即丢、多实例不共享）、排障常用 curl。

## 四、不在本版范围

- Prometheus 拉取 / Grafana 面板 / 外部时序库（本版只做内存窗口）。
- 告警（阈值触发 + 站内通知/邮件）：留 V6.11，本版只保证"看得见"。
- 历史留存与跨实例聚合：单机定位，明确不做。
- 前端性能监控（Web Vitals）、链路追踪（Tracing）：不引入。

## 五、风险

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | 首次引入 `@EnableScheduling` | 与现有 SSE / 单线程 pipeline runner 抢线程或互相阻塞 | 独立 `MonitorConfig`、显式 `pool.size: 2`、采样体全 catch |
| 2 | 采样异常导致定时任务静默停摆 | 面板画到一半没点了，且无人发现 | catch + warn；`/monitor/overview` 返回最近一次采样时间，前端超过 3 个周期无更新则显示"采样停滞" |
| 3 | Actuator 误暴露 `env`/`heapdump` | 数据库密码、内存全量可被下载 | `exposure.include` 枚举式 + 白名单只放 health + 单测断言 |
| 4 | `http.server.requests` 的 URI tag 基数爆炸 | 内存上涨、指标不可读 | `max-uri-tags: 100`；确认所有路径都是模板（`/gen/table/{id}`）而非裸 id |
| 5 | 直方图内存开销 | 每个 URI 一组桶，接口多时不可忽略 | 只对 `http.server.requests` 开；观察一轮后按需收窄到指定 URI |
| 6 | 前端 5s 轮询 + 多标签页重复拉取 | 无谓压力 | `visibilitychange` 暂停 + 只拉增量序列 |
| 7 | ECharts 体积（整包 ~1MB） | 主包膨胀、首屏变慢 | 按需引入 + 异步 chunk（复用 V6.9 `pdf-renderer` 同款做法） |
| 8 | 删掉 `/health` 白名单可能影响既有探活脚本 | 运维探活 401 | **已核实**：`scripts/nightly-fullgen.mjs:112` 探活走 `/gen/pipeline/config`，未用 `/health` 或 `/actuator`，删除安全；仓库外脚本若有依赖，改为转发到 `/actuator/health`，不恢复全开 |
| 9 | 内存窗口被误当"历史监控" | 重启后图线归零被当成故障 | 说明文档 + 面板显式标注"仅进程内 30 分钟" |

## 六、验证方式（S8 口径）

- **编译**：`mvn compile` 零错误；`mvn test` 既有 196 例不回归；新增用例覆盖白名单收窄断言、`/monitor/series` 的 metric 白名单与 minutes 钳位、环形缓冲满后淘汰最旧。
- **接口**：
  - `GET /actuator/health` 无 token → 200 且 `status=UP`
  - `GET /actuator/metrics` 无 token → 401；带 token → 200
  - `GET /actuator/env` → 404（未暴露）
  - `GET /monitor/overview` 带 token → 200，字段含 `lastSampleAt`
  - `GET /monitor/series?metric=evil` → 400；`minutes=999` → 钳到 30
  - 连续 2 分钟后再查 `/monitor/series`，`points.length >= 20`
- **UI**：真浏览器打开监控页，console 零 error，4 张卡片有值、趋势图至少 2 个点、Top N 表格非空，截图存档；切走菜单后确认轮询停止（Network 无新请求）。
- **业务埋点**：跑一次 `gen_write`，`/monitor/business` 的写盘文件数增量与磁盘实际变更数一致。
