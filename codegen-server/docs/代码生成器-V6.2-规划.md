**问题**：平台把代码生成到了极致，但产物「最后一公里」（构建镜像、上流水线、安全配置）和平台自身的「被自动化调用」能力都是空白。夜跑链路是唯一自动化通道，且只服务本机。

## 二、主题与理由

**主题：产物交付面三件套——① `codegen.mjs` CLI（平台 token 化接口 + 单文件脚本，CI 可接）；② 产物部署物（Dockerfile 多阶段 + docker-compose + CI 流水线模板，系统级开关 `gen_deploy`）；③ 配置安全升级（密码改环境变量占位符 `${DB_PASSWORD:...}`，主 yml 零明文）。**

理由：

1. **CLI 是被推迟最久、理由已消失的欠账**：基线护栏成立后，CLI 生成不会放大错误反而放大护栏价值（CI 里每次生成后跑基线比对）；
2. **部署物是产物可信化的自然收尾**：V4.2 做了「产物可信」（离线可编译、路径命名唯一），V4.5 做了「产物完整」（打印单据），V6.0 做了「产物可拆」（微服务设施），唯独「产物可交付」没做；
3. **配置安全是零争议的补丁**：明文密码是盘点中点名的安全短板，环境变量占位符一行改动，且与 local.yml 机制兼容不冲突。

## 三、范围

### P0-1 CLI 生成（平台接口 + 单文件 CLI）

- 平台新增只读生成接口：`POST /gen/cli/preview`（token 鉴权，参数 projectId/tableIds，返回与现有 preview 同构的文件清单）；`POST /gen/cli/download`（复用现有 ZIP 通道）；**不新增写库端点**——CLI 只读生成，写盘由 CLI 本地完成
- `codegen.mjs` 单文件 CLI（Node 22+ 内置 fetch，零依赖）随平台 `scripts/` 下发：
  - `node codegen.mjs gen --system <projectCode> [--module <x>] --out <dir> [--force]`
  - `node codegen.mjs status --system <projectCode>`（台账概览）
  - exit code 约定：0 成功 / 1 生成失败 / 2 环境不满足（对齐 verify-all.mjs 既有约定）
- CI 场景闭环：GitHub Actions / Jenkins 示例段落写入文档（不是模板，是文档示例）——拉平台 token → CLI 生成 → `verify-all.mjs` 验证 → 提交产物仓库

### P0-2 产物部署物（开关式，默认关）

- `sys_project.default_gen_deploy`（可空三态，回落链照 V4.5 print 先例：表级→系统级→硬编码 0；不进 17 键，回落唯一实现新方法 `GenTemplateModel.resolveGenDeploy`）
- 开启时 scaffold 追加产物（`bootRoot` 下）：
  - `Dockerfile`：多阶段（maven:3.9-eclipse-temurin-21 build → eclipse-temurin:21-jre 运行），`JAVA_OPTS` 透传，非 root 用户
  - `.dockerignore`（target/、logs/、db/）
  - `docker-compose.yml`：app + mysql（健康检查 + depends_on condition）；micro 结构时追加 gateway 服务与 Nacos（注释态，与 V6.0 两栖语义一致）
  - `deploy/ci-github-actions.yml.example` 与 `deploy/Jenkinsfile.example`（改名即用，不自动激活）
- 接线：scaffold `vo.nextSteps` 增加 docker 构建引导；`GenPathResolver` 无新增归属（部署物全部落 bootstrap 模块）

### P0-3 配置安全升级

- `applicationYml` 数据源段改占位符：`url/username/password` 全部 `${DB_URL:...}/${DB_USERNAME:...}/${DB_PASSWORD:...}`，默认值保留当前行为（本机直跑零变化）

- **回归红线**：mono/multi/micro 全场景产物行为零变化（占位符默认值=原明文值，基线快照更新一次后锁死）

## 四、关键设计决策

| 决策点 | 定案 | 理由 |
|---|---|---|
| CLI 形态 | 单文件 `codegen.mjs`（Node 内置 fetch，零依赖） | 产物用户环境已证明有 Node（vue 工程）；零依赖=拷走即用；不做 npm 包发布（维护成本不值） |
| CLI 权限 | 只读生成，token 复用 auth login | 写库走 CLI 会绕过台账与审计——这是刻意的安全边界，不是功能缺失 |
| 部署物开关 | `default_gen_deploy` 可空三态，默认关 | 与 V4.5 gen_print、V6.0 nacos.enabled 同款决策模式：新能力默认零影响，存量产物零 diff |
| compose 要素 | app+mysql 为默认，Nacos 注释态 | 与 V6.0「两栖运行」语义一致；注释态即文档，启用=取消注释 |
| 密码方案 | 环境变量占位符 + 默认值兜底，不强制 | 强制改密会破坏「本机直跑零变化」；默认值兜底保住开发体验，生产由 env 覆盖 |
| CI 模板形态 | `.example` 文件随产物下发 | 自动激活的 CI 文件在无 CI 环境是垃圾文件；`.example` 改名即用（与 local.yml 同款先例） |

## 六、验收清单

1. **CLI 无头生成**：新起 bash 会话（无浏览器、无 cookie）执行 `node codegen.mjs gen --system v62demo --out /tmp/out` → 全部生成物落盘，exit 0；错 token → exit 2
2. **部署物可用**：`gen_deploy=1` 系统产物 `docker build` 成功 → `docker compose up` → health 探活 200 → `docker compose down` 干净退出；本机无 Docker 时验收降级为 Dockerfile 语法 lint（hadolint）并明示
3. **配置安全**：grep 全部产物 yml 无 `password: <明文>` 命中（占位符除外）；环境变量覆盖生效（`DB_PASSWORD=x java -jar ...` 可连库）
4. **存量零 diff**：`gen_deploy` 缺省系统重新 scaffold → 与 V6.1 时点产物逐文件一致；`mvn test` 全绿 + 基线（6 场景 + deploy 场景新增）零 diff
5. **验收样板**：V6.0 的 micro 测试系统补开 `gen_deploy` → compose 五服务编排注释态可见，app+gateway 可起

## 八、风险

| 风险 | 缓解 |
|---|---|
| docker build 拉基础镜像慢/内网不可达 | Dockerfile 基础镜像走参数化 `ARG BASE_IMAGE`，文档给内网镜像替换示例；验收允许降级 lint |
| CLI token 泄露被滥用 | token 短时效（auth 既有机制）；CLI 只读边界（P0-1）保证最坏损失是「多生成一次代码」 |
| 占位符改造破坏存量流水线（seed/db 步直连 yml 假设） | seed 走 JdbcTemplate 用平台配置不经产物 yml；契约测试覆盖 yml 内容断言 |
| Node 版本碎片（产物用户可能是 Node 18） | CLI 只用 Node 18+ 均有的 API（fetch 在 18 内置）；文档声明最低版本 |
