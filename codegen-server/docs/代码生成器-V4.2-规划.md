# 代码生成器 V4.2 规划：让生成结果可追溯、可回滚

> 依据：2026-10-22 对 `codegen-server` 源码、`gen_platform` 库实际数据、`codegen-demo-target` 磁盘产物的逐项核对。
> 每条缺口都附**文件位置**或**实测数字**，不含推测项。
>
> **版本编号说明**：产品 V4.0 已用于主题皮肤体系，迁移脚本 `V4.0__user_theme.sql` / `V4.1__project_gen_defaults.sql` 两个编号已占用（V4.1 属 V3.1 交付）。本版接续为 **V4.2**，迁移脚本同名，此后产品版本与迁移编号对齐。

## 一、现状核对

### 1.1 已经很强的部分（不要重做）

| 能力 | 落点 | 实测 |
|---|---|---|
| 生成主链路 | 实体→Mapper→Service→Controller→DTO/VO→api.js→vue 页 | 73 个唯一产物路径在盘 |
| 四级路径回落 | `support/GenPathResolver` | V3.1 已收敛为单实现，预览/写盘/差异/ZIP/路由同步共用 |
| 写盘策略 | 同名跳过 / 覆盖合并（`.gen-backup/<批次>/`） | 10 个批次，312K 备份 |
| 差异与合并 | `GenMergeUtils`，标记块内外分离 | WRITTEN 70 / MERGED 94 / SKIPPED 57 |
| 校验与自检 | `GenVerifyServiceImpl`（309 行）、`GenSelfCheckServiceImpl`（836 行，6 类检查） | 编译前静态核对 |
| 脚手架 | `GenScaffoldServiceImpl`（1953 行，含 pom/基座类/数据权限） | 空工程一键起 |
| 模板版本 | `gen_template.version` + 历史/回滚接口 | 12 个模板 |

**结论：生成能力本身不缺，缺的是"写完之后的管理"。**

### 1.2 三处硬缺口（本版要解决的）

#### 缺口 1：两套台账字段分裂，是下一次分叉的种子

| | `gen_history` | `gen_output` |
|---|---|---|
| 行数 / 批次 | 164 / 8 | 221 / 10 |
| 记录范围 | 仅 WRITTEN + MERGED | WRITTEN + MERGED + **SKIPPED** |
| 有 `backup_path`（回滚用） | ✅ | ❌ |
| 有 `project_id`（系统归属） | ❌ | ✅ |
| 有 `md5`（漂移检测用） | ❌ | ✅ |
| 排序规则 | `utf8mb4_0900_ai_ci` | `utf8mb4_general_ci` |

两个写入口，都在 `GenCodeServiceImpl`：

- `recordHistory()` 第 371 行 → `INSERT gen_history`
- `recordOutput()` 第 395 行 → `INSERT gen_output`

两个方法都是 `catch (Exception e) { }` 全吞，**写失败静默**。

目前内容恰好一致（70 + 94 = 164），但排序规则不同导致连 `UNION` 都报错：

```
ERROR 1271 (HY000): Illegal mix of collations for operation 'UNION'
```

这正是 V3.1 踩过的老路：同一事实两处实现，字段还互补，**迟早对不上**。

#### 缺口 2：覆盖模式生成的文件，回滚根本不认

`GenApplyServiceImpl.rollback()` 第 228 行：

```java
if (!"WRITTEN".equals(status) || !StringUtils.hasText(filePath)) {
    continue;   // MERGED 直接跳过
}
```

而实测数据：

| status | 行数 | 有备份的行数 | 回滚是否处理 |
|---|---|---|---|
| WRITTEN | 70 | 0（新文件，回滚=删除） | ✅ |
| MERGED | 94 | **94（备份全在）** | ❌ **整类跳过** |

也就是说：**最需要回滚的覆盖场景（94 个文件，手写代码与生成代码混在一起），备份好好躺在 `.gen-backup/` 里，回滚视而不见。**

另外三个问题：

- 粒度是整批，**没有预览、不能只回滚部分文件**
- 回滚动作**不记台账** → 回滚本身不可再回滚
- 备份无清理策略，只增不减

#### 缺口 3：md5 只写不读，漂移检测原料闲置

`GenCodeServiceImpl` 第 410 行写入 `row.setMd5(...)` 之后，**整个代码库没有任何消费方**（`grep getMd5` 零命中）。

同时台账与磁盘已经开始脱节：73 个唯一产物路径中，**6 个文件已不在磁盘上**（被人删了或目录结构变了），台账没有任何提示。

## 二、本版主题与选择理由

**主题：生成结果可信化 —— 一次写盘之后，任何时候都能回答三个问题：**

1. 这批到底写了哪些文件？（唯一台账，字段齐全）
2. 磁盘上现在还是我生成的那份吗？（漂移检测）
3. 我要撤销，能撤到哪一步、撤完是什么样？（可预览、可选择、可回滚的回滚）

**为什么是它，而不是新功能**：V3.1 解决的是「写到哪」（路径回落），V4.2 解决「写完之后」（生命周期）。当前 94 个文件的备份实际不可用、台账两套并存、md5 闲置——这些不是潜在风险，是**已经存在的账实不符**。在这个基础上加新能力（逆向生成、CLI），只会把不可回滚的资产越堆越多。

## 三、范围

### P0-1 台账合一（1 人日）

**改法**

- `gen_output` 增列：`backup_path varchar(500)`、`prev_md5 varchar(32)`（覆盖前原文件 md5，供漂移判断）
- 写盘只写 `gen_output` 一处；`gen_history` 停止写入，数据迁完保留只读一个版本后删除
- 统一排序规则到 `utf8mb4_0900_ai_ci`（MySQL 8 默认，与 `gen_history` 一致）
- 迁移脚本 `V4.2__unify_gen_ledger.sql`，幂等：
  1. 加列（先查 `information_schema`）
  2. 按 `batch_no + abs_path` 回填 `backup_path`
  3. `ALTER TABLE ... CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci`
- 台账写失败不再静默：`log.warn` + 把失败条数放进接口返回体（`ledgerErrors`），写盘仍不因此失败

**验收**

- 一次写盘后 `SELECT COUNT(*) FROM gen_output WHERE batch_no=?` == 接口返回文件数（含 SKIPPED）
- 跨表/无 UNION 报错；`gen_history` 行数不再增长
- 历史 164 行的 `backup_path` 回填后，与 `.gen-backup/` 磁盘实际文件逐一对应

**风险**：`CONVERT TO` 会锁表。单机工具，164 + 221 行，窗口期内执行即可；脚本前先 `SELECT` 备份两张表。

---

### P0-2 回滚能力补全（1.5 人日）

**改法**

- 支持 `MERGED`：有 `backup_path` 且文件存在 → 还原；否则按「无备份」处理并计入跳过
- 选择性回滚：`POST /gen/history/rollback` 支持 `{batchNo, ids?|paths?}`，不传则整批（保持向后兼容）
- 新增预览接口 `POST /gen/history/rollback/preview`（dryRun）：返回 `将还原 N / 将删除 M / 将跳过 K / 冲突明细`
- 回滚本身写台账：`action = ROLLBACK`，`message` 记「回滚批次 X 的文件」，使回滚可再回滚
- 前端：产物台账页批次明细勾选 + 「回滚预览 → 确认执行」两步

**验收**

- 覆盖模式生成 → 手改一处 → 回滚预览 → 执行：手改内容按预览承诺处理（还原到生成前）
- 只勾 3 个文件回滚，其余文件 mtime/内容不变
- 回滚后再回滚，回到第一次回滚前的状态
- `MERGED` 94 条历史记录里任取一条，现在能回滚且备份内容正确

---

### P0-3 漂移检测（1 人日）

**改法**

- 新接口 `POST /gen/drift`：按每个 `abs_path` 的**最新台账记录**取 `md5`，与磁盘实算比对，返回 `SAME / DRIFTED / MISSING`
- 差异接口 `POST /gen/diff` 的每条结果加 `drift` 字段（`SAME/DRIFTED/MISSING/UNKNOWN`）
- 向导第②步与差异页：`DRIFTED` 显示「磁盘已被手改」标记 + mtime
- 覆盖策略加第三档 **`只写未漂移文件`**：`DRIFTED` 一律跳过并在结果里说明，避免一键覆盖掉手写代码
- 批量写盘时若存在 `DRIFTED`，执行前弹二次确认并列出文件清单

**验收**

- 手改一个文件 → `drift` 返回 `DRIFTED`，路径与 mtime 对得上
- 删一个文件 → `MISSING`；未改文件 → `SAME`，**无一处误报**（当前基线：73 路径里 67 SAME / 6 MISSING / 0 DRIFTED）
- 选「只写未漂移」生成后，`DRIFTED` 文件内容一字节未变

---

### P1-1 台账巡检（0.5 人日）

一个只读报告接口 `GET /gen/ledger/health`，三类异常：

| 类型 | 判定 | 当前实测 |
|---|---|---|
| 孤儿记录 | 台账有、磁盘无 | 6 条 |
| 无记录文件 | 磁盘有、台账无（限目标工程 `src/`） | 待首次跑出 |
| 重复记录 | 同批次 + 同路径出现多行（历史双写残留） | 迁移后核对，应为 0 |

前端在产物台账页加「健康检查」按钮，输出可复制表格。**只报告不自动修**——自动删记录风险高于收益。

### P1-2 备份保留策略（0.5 人日）

`.gen-backup/<批次>/` 目前只增不减（312K / 10 批，量小但会涨）。

- 配置项 `gen.output.backup-keep-batches`（默认 20）、`backup-keep-days`（默认 30）
- 清理只在**写盘成功后**触发，且只删不满足任一保留条件的批次目录
- 清理动作写日志，不写台账（避免污染）

### P2-1 模板按系统绑定（1.5 人日，视需求）

`gen_template` 现有 `table_id`（0 = 全局），缺 `project_id`。

- 加 `project_id`（NULL = 全局），回落：表级 `table_id` → 系统 → 全局
- 模板管理页加作用域切换（全局 / 某系统）
- **前置条件**：真的出现「两套系统模板规范不同」的需求。没有就继续延后（这是 V3.1 就定下的判断，不因排期宽松而变）

## 四、明确不做

| 项 | 理由 |
|---|---|
| 逆向生成（从代码反推表配置） | 独立主题，工作量和风险都远超一个迭代；且依赖本版台账先稳住 |
| CLI / CI 生成入口 | 依赖「台账唯一 + 漂移可见」这个前提，放到 V4.3 |
| 多租户权限隔离（谁能看哪个系统） | 单团队内部工具，`sys_role` 维度已够；真要多租户得重做鉴权 |
| 写盘并发锁 | 单机工具，`batch_no + 覆盖前确认` 已够；分布式锁是给多实例部署用的，现在没有这个场景 |
| 台账自动修复（自动删孤儿记录） | 无法区分「用户故意删的文件」与「异常丢失」，自动修会制造二次错误 |

## 七、如果方向想换（备选主题与代价）

| 备选 | 内容 | 选它的代价 |
|---|---|---|
| A. 生成即验证 | 生成 → 编译 → 起服务 → 冒烟一条龙（复用 `self-check` + `scaffold`） | 现有 94 个文件仍不可回滚；错一次覆盖就是永久丢失，验证做得再好也补不回 |
| B. CLI / CI 生成 | `codegen-cli` + Maven 插件，脱离 UI 生成 | 需要台账先唯一，否则 CI 生成的记录和 UI 生成的对不上，排障成本翻倍 |

**推荐仍是本版主题**：A/B/C/D 都是"往上加能力"，而当前问题是"底座在漏"。先把底座焊死，后面加什么都稳。

## 八、风险

| 风险 | 影响 | 应对 |
|---|---|---|
| `CONVERT TO` 锁表 | 迁移期间写入阻塞 | 单机工具、行数 <400，窗口期执行；执行前 `mysqldump` 两张表 |
| 历史 `backup_path` 回填不全 | 老批次仍不可回滚 | 回填按 `batch_no + abs_path` 精确匹配；匹配不上的在巡检报告里列出，不猜 |
| 回滚 MERGED 覆盖用户手写 | 数据丢失 | 预览必须列出「将还原（会覆盖手改）」；默认不勾选 DRIFTED 文件 |
| 台账列改完忘改前端 | 字段显示空 | 台账页字段与 `GenOutput` 实体逐字段核对（S7 字段绑定铁律） |
| 两套台账迁移期间双写 | 又分叉 | 迁移脚本执行到「停止写 gen_history」这一步后，代码同批上线，不留中间态 |
