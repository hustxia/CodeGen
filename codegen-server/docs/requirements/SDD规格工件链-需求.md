# SDD 规格工件链与 Converge 对账 — 需求

> 版本：V9.21（对应演进规划 V1.30 第一期 M1.1）
> 日期：2026-11-28

## 1. 背景与目标

当前生成器的入口是"表配置 + 一键生成"，生成结果是否**符合当初的意图**，只能靠人逐页点开看。GitHub 热点验证了 Spec-Driven Development（Spec Kit 15 万星）的方向：规格先行、生成对账、收敛后才进验收。

本期把 SDD 最小闭环落进平台：

- **规格工件版本化**：constitution / spec / plan / tables / tasks 五类工件，保存即快照，CONFIRM 后才能作为对账依据；
- **Converge 规格对账**：以生效 SPEC 的期望清单为依据，核对实际产物（gen_table / gen_table_column），输出"已实现 / 缺失 / 多余"三栏结论。

使用者：平台上的系统负责人（写规格、看对账）；生成器产品本身的演进（V1.30 后续门禁/护栏都挂在这条工件链上）。

## 2. 功能点

| 编号 | 功能点 | 一句话 |
|---|---|---|
| F-01 | 工件树 | 五类工件各取最新版本，一屏看清链条完整度 |
| F-02 | 工件编辑保存 | Markdown 正文 + YAML 元信息 + 期望清单 JSON，保存即新增版本快照（DRAFT） |
| F-03 | 工件确认 | DRAFT → CONFIRMED；对账只认 CONFIRMED |
| F-04 | 基本法初始化 | 一键生成项目级 constitution（沉淀坑库硬约定默认内容），已有则返回最新 |
| F-05 | 历史版本 | 同类型版本倒序，可回看不可覆盖 |
| F-06 | 执行对账 | 采集实际产物逐项比对，落报告与明细 |
| F-07 | 报告列表 | 项目维度时间倒序，汇总数与状态直出 |
| F-08 | 报告详情 | 明细按 MISSING → EXTRA → OK 排序，含规格来源与处理建议 |

## 3. 边界与异常

- 项目无 CONFIRMED 的 SPEC 工件时执行对账 → 业务报错（提示先确认 SPEC），不落报告。
- 对账范围第一版收敛为**表 / 字段 / 枚举**三类；语义对账（接口、页面）后续版本扩，本期不做。
- FIELD 对账一律以 `表名.列名` 为键；EXTRA 只对 TABLE 类全量比对，FIELD/ENUM 类不做全量比对（避免噪音）。
- 雪花 ID 一律字符串化下发（坑库 spring-boot-3 #2）。
- 工件不可物理删除、不可修改历史版本；纠正 = 保存新版本。
- `missing=0 且 extra=0` → CONVERGED，前端据此放行"进入验收"提示。

## 4. 验收标准

- [ ] 工件树能展示五类工件及各自最新版本号、状态
- [ ] 保存工件后版本 +1，历史版本可在列表回看
- [ ] DRAFT 工件确认后状态变 CONFIRMED，再次保存仍是新 DRAFT
- [ ] 基本法初始化重复调用幂等（第二次返回已有最新）
- [ ] 对生效 SPEC 执行对账，报告明细三类齐全、排序符合 MISSING→EXTRA→OK
- [ ] 无 CONFIRMED SPEC 时对账返回业务错误提示
- [ ] 前端页面 console 零 error，字段与后端实体逐字段一致
