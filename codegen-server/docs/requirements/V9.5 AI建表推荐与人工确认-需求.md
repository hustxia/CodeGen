> 日期：2026-11-15　版本：**V9.5**　状态：**需求草案（待 UI 确认，尚未开发）**
> 承接：V5.0「一句话建系统」、V9.4「分阶段确认」、V7.0「AI 页面/菜单推荐」
> 设计文档：[`V9.5 AI建表推荐与人工确认-设计.md`](../design/V9.5 AI建表推荐与人工确认-设计.md)
> 前置需求：[`V9.4一句话建系统分阶段确认-需求.md`](./V9.4一句话建系统分阶段确认-需求.md)

## 一、背景与目标

V9.4 已经把"**需求 → 功能清单 → 表结构与 SQL → 建库建表 → 构建启动**"做成了四步、每步都人工确认的可检查链路。其中"AI 建表"由 `AiModelServiceImpl.model`（`POST /gen/pipeline/ai-model`）产出候选表结构，再经 V9.4 第③步的表结构编辑器和 SQL 同源预览进入建库。

但在真实使用中存在三个不够顺手的断层：

1. **AI 建表被锁死在四步向导里**。想"先让 AI 设计一套表、人确认后落库"，也必须走完 V9.4 的完整向导；没有一个独立的"AI 建表助手"入口。
2. **大型系统会截断**。本地 7B 模型单次 `model()` 只敢出 3-5 张（完整）或 6-8 张（按模块）表，要凑出几十张表，V9.4 靠前端"循环调 ai-model 再合并"，没有服务端统筹、没有整体进度、合并去重也不稳健。
3. **确认只到"表 + 列基础字段"**。AI 目前只给表名/列名/类型/PK，外键关系、索引、是否可空这些决定表质量的关键项要么靠人手动补，要么不建模。

V9.5 的诉求非常明确：**把"AI 推荐建表 + 人工确认"抽成一个独立功能模块**，与 V9.4 的"一句话建系统"向导**并列共存、互不影响**；AI 从需求（或某个已有系统）产出**可编辑的完整表设计**（含关系/索引/可空），人在一个交互式表结构编辑器里增删改、看实时 SQL，确认后才落库或建库。

> 核心约束（来自用户）：**单独一个功能模块，不影响原来开发「一句话建系统」功能**。因此 V9.5 全部是新增入口与复用，禁止修改 `GenPipelineController`、`GenPipelineServiceImpl`、V9.4 向导页面。

### 目标

- 提供独立的"AI 建表助手"入口（后端 `/gen/ai-build` + 前端 `/gen/aibuild`），不改动 V9.4 任何代码。
- AI 从需求**或已有系统**出发，产出可编辑表设计；大型系统按模块分批建模、服务端合并去重、带进度。
- 人工在交互式编辑器里增/删/改表与列（表名、注释、列名、类型、可空、主键、索引、外键关系），并实时看到同源 DDL。
- **确认前零写库**：AI 与 DDL 预览保持无状态；只有最终"确认落库 / 建库"按钮有副作用，且二次确认。
- 复用现有 `ai-model`、`buildDdl`/`prepareDb`、`assessRelevance` 相关性护栏、可编辑表格组件与流水线状态机。

## 二、功能点

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F-01 | 独立 AI 建表入口 | P0 | 新路由 `/gen/aibuild`；与 V9.4 向导并列，可单独进入；可新建系统或"为已有系统补表" |
| F-02 | AI 推荐表设计（含关系/索引） | P0 | 复用 `AiModelServiceImpl.model`，扩展 prompt 让 AI 一并给出外键关系、索引建议、是否可空；输出 `GenAiBuildPlanVO` |
| F-03 | 大型系统分批建模 | P0 | 复用 `ai-modules` 拆模块 → 逐模块 `model` → 服务端合并去重 → 统一进度（SSE/轮询，沿用现有 `stream` 范式） |
| F-04 | 交互式表结构编辑器 | P0 | 对 AI 结果做增/删/改表与列（名称、类型、注释、可空、主键、索引、外键）；复用现有可编辑表格 |
| F-05 | 同源 DDL 实时预览 | P0 | 复用 `GenPipelineService.previewDdl` 与 `buildDdl`；表结构任一改动即重算，预览与执行同一出口 |
| F-06 | 人工确认后落库/建库 | P0 | 确认后二选一：① 落为草稿项目（导入 `gen_table`/`gen_table_column`，不执行 DDL）；② 直接 `prepareDb` 建库，进入 `await_confirm` 后再由本模块"构建"按钮触发 `run` |
| F-07 | AI 相关性护栏复用 | P0 | 大模型返回疑似通用后台模板时拦截；关联度偏低时告警仍允许人工确认/重生成（复用 `assessRelevance`） |
| F-08 | 规范校验复用 | P1 | 复用现有 `fixColumns` 与 `GenDdlServiceImpl` 的库名/危险语句/ dry-run 校验；确认前把表结构规范成可执行形态 |

### 与 V9.4 的分工

| 维度 | V9.4「一句话建系统」 | V9.5「AI 建表助手」 |
|---|---|---|
| 定位 | 端到端四步向导（含构建部署） | 聚焦"建表设计"的独立模块 |
| 入口 | `/gen/pipeline` 向导 | `/gen/aibuild`（新） |
| AI 建表 | 第③步内嵌调用 `ai-model` | 模块主干，扩展关系/索引、分批合并 |
| 表结构编辑 | 复用编辑器（耦合向导） | 复用同一组件，但独立页面承载 |
| 落库 | 确认后 `create`+`prepareDb` | 确认后落草稿项目或直接 `prepareDb`（复用） |
| 构建部署 | 向导第④步 `run` | 复用现有 `run`，不新增执行链 |

## 三、范围边界

### 本期做

- 新增 `/gen/ai-build` 控制器与 `AiTableRecommendService`（编排层，复用 `AiModelServiceImpl` + `GenPipelineService`）。
- 扩展 AI 建模 prompt：在现有 `{tables:[{tableName,tableComment,columns:[{name,type,comment,pk}]}]}` 基础上增加 `indexes`、`relations`（外键）与列级 `nullable`。
- 新增大型系统分批建模编排：模块拆分 → 逐模块 `model` → 按表名去重合并 → 进度。
- 新增交互式表结构编辑器页面（V9.5 专属，复用现有表格组件）。
- 复用 `previewDdl`/`buildDdl`/`prepareDb`/`run`/`assessRelevance`/`fixColumns`，不重写。
- 新增"落为草稿项目"路径（导入 `gen_table`/`gen_table_column`，不执行 DDL），或"直接建库"。
- 保留手动 DDL、危险 SQL 拦截、同名系统阻断、单流水线 running 锁。

### 本期不做

- 修改 V9.4 向导、`GenPipelineController`、`GenPipelineServiceImpl` 的任何代码（硬约束）。
- 新增 LLM 供应商或模型配置页面（沿用 V9.4 边界，复用 `gen.pipeline.ai` 配置）。
- 多轮对话式需求澄清、PRD/原型图自动生成。
- AI 自动修改已有业务表结构（仅"为已有系统补表"时新增缺失表，不删不改既有表）。
- 远程/容器部署；V9.5 复用本机部署与现有 `run`。
- 撤销已执行的建库（DDL 不提供 DROP 业务表）。

## 四、阶段与写入边界

| 阶段 | 用户操作 | 允许行为 | 禁止行为 | 完成标志 |
|---|---|---|---|---|
| ① 录入需求 | 填系统名/描述；选"新建系统"或"为已有系统补表"；选规模（精简/大型） | 调 AI 模块拆分（大型）或准备建模 | 不创建项目、不写业务库 | 展示建模范围 |
| ② AI 推荐表设计 | 点击"AI 推荐"，等待进度 | 分批调 `ai-model`，合并去重，返回 `GenAiBuildPlanVO` | 不写平台库或业务库、不建表 | 展示可编辑表设计 |
| ③ 人工确认（编辑器） | 增删改表/列、关系/索引；看实时 SQL；刷新预览 | 调用 `previewDdl` 计算同源 DDL | 不执行任何 DDL | 表设计 `confirmed=true` |
| ④ 落库/建库 | 点"落为草稿"或"确认建库并构建" | 草稿：导入 `gen_table`/`gen_table_column`（无 DDL）；建库：`prepareDb`+进入 `await_confirm` | 未确认不得执行 DDL；建库后不得自动 `run` | 草稿项目 / `await_confirm` |

确认落库前，表设计数据属于前端暂存/服务端产物文件；确认后才进入现有任务持久化与流水线状态机。

## 五、业务规则与异常

| 场景 | 约定 |
|---|---|
| 空系统名/描述 | 不调用 AI，前端提示补全 |
| AI 未启用（无 LLM key） | 前端禁用 AI 推荐，仅保留"手动粘贴 DDL"通道（复用 V9.4 降级） |
| 大模型返回通用模板 | 复用 `assessRelevance` 拦截；关联度偏低仅告警，允许编辑/重生成 |
| 大型系统某模块建模失败 | 保留成功模块结果，列失败项，由用户决定继续或重试（复用 V9.4 不伪造成功原则） |
| 表名/列名冲突（合并） | 按表名去重，首份优先并记 conflict 告警；列以各表内唯一为准 |
| 表结构被修改 | 标记 SQL 已过期，必须刷新预览后才能确认建库 |
| 外键指向表不存在 | 关系建议被丢弃并记入 `drops`，不写库 |
| 索引列非法（不存在的列） | 索引建议被丢弃并记 `drops` |
| 数据库名非法/为空 | 服务端拒绝预览与执行（复用 `GenDdlServiceImpl` 校验） |
| AI 超时/不可用 | 不写业务库，可重试或切换手动 DDL |
| 为已有系统补表 | 仅新增缺失表，绝不动既有表/列；跨系统写入被拒 |
| 重复点击 | 所有 AI、预览、落库/建库按钮均带 loading 防重 |
| 建库/构建失败 | 展示真实失败原因，沿用现有 `failed` 状态与重试 |
