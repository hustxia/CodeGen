> 规划：[`代码生成器-V9.2-规划.md`](../代码生成器-V9.2-规划.md)

## 一、背景与目标

V9.1 及之前，平台已有一批验证能力（Java 单测、i18n 契约、206 语言键、前端构建、空库冒烟、Vue3 产物断言、新旧 jar 等价性），但散落在脚本、CI、命令行和人工截图里：`verify.sh` 全绿 ≠ 版本验收通过，结果写 `/tmp` 即丢，没有运行历史、没有报告、触发方式碎片化、没有用例级结构、阈值（MIN_TESTS=240）早已过时。

V9.2 把「**已有测试资产产品化**」，由两个子模块组成：

1. **用例中心 `/test/*`（test_* 七表）**——让业务方**编写/生成/执行**接口 & UI 自动化用例资产（环境、套件、用例、数据集、执行、定时回归）。
2. **验证中心 `/tc/*`（tc_* 三表）**——把**平台自身的验证套件 S1–S9** 收拢成一次可追溯、可导出、可接入 CI 的运行。

延续「一版只做一件事」：V9.2 只做测试相关，不新增生成能力、不改模板字符串、不改控制台技术栈；V9.1 立下的「产物零 diff 契约」继续有效。

**谁用**：用本平台交付系统的开发者（编写/执行业务用例）；质量/CI 负责人（做版本验收门禁）。

**不做会怎样**：门禁失真、结果不留存、触发碎片化、无用例级结构、验收证据散落、阈值过时——六类痛点（见规划文档 §1）。

### 版本编号说明

V9.2 主题由用户指定为「测试中心」。规划初稿只含用例中心，实现期将「验证中心」合并进同一版本（规划文档 §14 实现说明），故 V9.2 实际交付两个子模块。

## 三、边界与异常

| 项 | 约定 |
|---|---|
| 用例中心 | 不做脚本 IDE、不写代码；不做性能压测、App/小程序；不做用例录制器、缺陷跟踪 |
| 验证中心 | 不写用例（那是用例中心）；不替代 CI（是 CI 事实源之一）；不接合并阻断门禁（V9.3 评估） |
| 命令来源（FR-01） | 验证中心命令模板服务端硬编码，请求体只交 suiteId，argv 拒绝 shell 元字符；不存在命令注入 |
| 路径穿越 | 日志/产物读取走 `TcPathGuard` 白名单，只允许 run 隔离目录 |
| 雪花 ID 精度 | 所有对外 ID 一律字符串下发（坑库 spring-boot-3 #57/1653 同坑，V9.2 已补指针） |
| 默认套件 | 验证中心仅 P0（S1–S7）默认勾选；P1 的 S8/S9 需显式选择（本机内存约 6GB 约束） |
| 门禁阈值 | `MIN_TESTS` 提到 312，与实测单测数对齐 |
| 产物零 diff | V9.1 契约继续有效；验证中心不触碰生成模板 |
