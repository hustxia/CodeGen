# 流水线数据初始化（seed 步）需求

> 2026-10-25。上游规划：`docs/代码生成器-V5.2-规划.md`（含 2026-10-25 修订记录）。本期实现 **P0 全部**，P1（AI 语义生成 / 金额一致 / 自定义种子 SQL）后续迭代。

## 一、背景与目标

流水线建库建表后业务表全部 0 行，演示/联调前必须手工造数。本期在流水线 `db` 步之后、`scaffold` 步之前插入 **seed（数据初始化）** 步，自动为业务表灌入可用的中文示例数据；并提供独立补数接口供存量系统使用。

## 二、功能点

| 编号 | 功能点 | 一句话 |
|---|---|---|
| F-01 | seed_mode 三态开关 | 向导第②步新增「数据初始化」：规则生成（默认）/ 跳过；落 `gen_pipeline.seed_mode`（NULL=off） |
| F-02 | seed 步接入流水线 | 步骤种子与执行器各插 1 步，`off` 时成功跳过并说明 |
| F-03 | 规则生成引擎 | FK 拓扑排序 + 列类型/语义/枚举驱动造数 + 唯一列防撞 + 行数策略（上限 2000 行） |
| F-04 | 幂等与重放 | 插数前查行数，非 0 跳过；结果落盘 `seed.sql` 可人工重放 |
| F-05 | 独立补数接口 | `POST /gen/pipeline/{id}/seed`，存量系统只补 0 行的表 |
| F-06 | 步骤报告 | seed 步 message = 每表插入行数 + 跳过原因清单 |

## 三、边界与异常

- 外键成环：降级按台账顺序 + 告警，不阻断
- 联合唯一：只对单列唯一做随机后缀；联合唯一冲突重试 3 次后跳过该表并记报告
- 无外键的"伪明细"：一律按普通表处理（只认 information_schema 真实外键）
- 表不在台账（0 行且无配置）：跳过并记原因
- 脚手架基座表（sys_user 等）：不在台账内，天然不参与
- 单次 seed 插数总上限 **2000 行**（修订记录第 3 条），超限表记"待补数"

## 四、验收标准

- [ ] 新流水线选「规则生成」跑完：有数据的表、行数符合策略、枚举值合法、外键自洽、唯一列无重复
- [ ] 选「跳过」或旧流水线（无 seed 步/seed_mode NULL）：行为与现状完全一致
- [ ] seed 幂等：重复执行/重跑流水线不重复插数
- [ ] 存量系统调独立接口补数成功（只补 0 行表）
- [ ] `mvn -o test` 全绿（新增生成器单测）
- [ ] 前端向导选项与步骤卡片正常展示
