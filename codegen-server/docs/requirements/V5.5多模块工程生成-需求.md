> 日期：2026-10-24　状态：S1 需求已整理，四项歧义按推荐方案定案（用户跳过提问），待效果图确认
> 关联：V5.0 一句话建系统（产物基础复用本版结构）；速查「配置回落两个入口必须同步」

## 一、背景与目标

现状：生成产物是**单 Maven 模块**工程（`demo-server/`，controller/service/mapper/entity 全在一个 `src/main/java`），模块边界不存在，微服务拆分要从零重排代码。V5.0「AI 一句话建系统」产出的系统也需要多模块结构作底座。

目标：**系统级可配置生成 Maven 多模块工程**；模块拆分线即未来微服务拆分线，升级微服务时按模块搬走即可，不需要重新组织代码。单模块系统零影响。

## 三、多模块结构标准

```
<systemCode>-parent/                    # backendPath 根（聚合 pom）
├── pom.xml                             # parent：依赖管理 + modules 聚合
├── <systemCode>-common/                # 基座：exception/config/util/DictTexts/TimeJacksonConfig/MaskUtils
│   ├── pom.xml
│   └── src/main/java/<rootPkg>/common/
├── <systemCode>-domain/                # entity + mapper(+xml)
│   ├── pom.xml
│   └── src/main/java/<rootPkg>/domain/{entity,mapper}/
├── <systemCode>-service/               # controller + service + dto/vo（跟业务走，微服务拆分单位）
│   ├── pom.xml
│   └── src/main/java/<rootPkg>/service/{controller,service,dto,vo}/
└── <systemCode>-bootstrap/             # 启动壳：启动类 + application.yml
    ├── pom.xml                         # spring-boot-maven-plugin 在这层
    └── src/main/java/<rootPkg>/ + resources/application.yml
```

依赖链：`domain → common`，`service → domain`，`bootstrap → service`。
包结构不变（仍是 `<rootPkg>` 向下），启动类放顶层包默认扫全子包；`@MapperScan` 固定指 `<rootPkg>.domain.mapper`。

## 四、功能点编号列表

| 编号 | 功能点 | 一句话 |
|---|---|---|
| F-01 | 工程结构配置 | `sys_project.project_structure`（NULL=单模块 / 'multi'=多模块），系统编辑页下拉，三态可空（V4.4 教训：NOT NULL DEFAULT 杀死回落层） |
| F-02 | 脚手架多模块化 | scaffold 按结构生成 parent+4 子模块目录、5 份 pom、启动类、application.yml；基座类落 common |
| F-03 | 产物落盘多模块化 | `GenPathResolver` 加「产物→模块归属」层：entity/mapper/xml→domain，controller/service/dto/vo→service，基座→common，pom/启动类/yml→bootstrap；预览/写盘/ZIP/回滚四个入口全走它 |
| F-04 | 模板适配 | 新增 pom×5/启动类/application.yml 模板；现有业务模板内容不动，仅落盘模块随 F-03 变化 |
| F-05 | 回归保障 | 基线加多模块场景快照；契约测试加多模块路径断言；单模块系统基线零 diff 证明存量无感 |

## 五、边界与异常

- `project_structure` 为 NULL 或 'mono'：走现有单模块逻辑，产物路径、模板行为与改造前**逐字节一致**（基线证明）
- 多模块系统重新 apply：不自动迁移旧单模块产物，预览差异会显示位置变化，由用户重新生成覆盖（backup 批次机制照常兜底）
- ZIP 下载：目录结构随多模块变化（内含 5 个子模块目录），前端下载流程不变
- 前端工程（Vue）不拆，仍单工程
- 脚手架幂等：结构切换后重复 scaffold 按现有 force/备份机制处理
- 编译门禁：多模块产物在 demo-target `mvn compile` 必须通过（S8 实测）
