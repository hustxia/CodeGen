# V6.3 支付能力包 需求

> 日期：2026-10-25　规划：docs/代码生成器-V6.3-规划.md（范围/决策/排期以规划为准，本文记需求条目与 S0 修正）

## 一、背景

生成系统对「收款」空白：订单、缴费、报名费类表都要用户手工对接支付 SDK、处理验签幂等、考虑回调安全。V6.3 生成通用支付模块，生成即可收款。

## 二、需求条目

| 编号 | 需求 | 优先级 | 验收方式 |
|---|---|---|---|
| F-01 | `sys_project.pay_enabled` 系统级开关，开启时 scaffold 生成支付模块（pay_order 表 + PaymentService 抽象 + wxpay/alipay/mock 三实现） | P0 | AC1 |
| F-02 | pay_order 通用支付单表：out_trade_no 唯一键、amount 分（bigint）、pay_channel、pay_status（0待支付/1成功/2关闭/3退款）、business_type/business_id、回调原始报文、审计列 | P0 | AC1 |
| F-03 | 端点四件：POST /pay/order（下单）、POST /pay/notify/{channel}（回调验签+幂等+金额校验）、GET /pay/order/{outTradeNo}（查单）、POST /pay/close/{outTradeNo}（关单） | P0 | AC2/AC4 |
| F-04 | 渠道由 yml `pay.channel=mock\|wxpay\|alipay` 单选，缺省 mock；mock 与真渠道走同一条状态流转链路（统一 markPaid 入口，幂等） | P0 | AC2 |
| F-05 | mock 模拟支付端点（仅 mock 渠道生效）：置成功并触发与真渠道同构的流转链路 | P0 | AC2 |
| F-06 | 查单补偿定时任务（@Scheduled 可配开关与间隔）：回调不可达时轮询渠道对账收状态 | P0 | AC4 |
| F-07 | 业务表联动：业务表含 pay_status 字段时，详情页「去支付」入口；支付成功后按 business_type 更新业务表 pay_status（表名白名单校验防注入） | P0 | AC2 |
| F-08 | 前端收银台：渠道选择 → 二维码弹窗（qrcode 前端生成）→ 支付结果轮询（2s 间隔）→ 成功跳转 | P0 | AC3 |
| F-09 | 前端支付记录页：pay_order 列表 + 状态徽标 + 手动关单/查单 | P0 | AC3 |
| F-10 | 密钥全部 `${PAY_*:}` 环境变量占位符，主 yml 零明文（复用 V6.2 机制） | P0 | AC5 |
| F-11 | mock 渠道全链路自检断言（下单→支付→查单→业务联动） | P0 | AC2 |

## 三、S0 检索与修正

- 坑库/知识库检索：支付领域零沉淀（`14-业务场景与案例/03-支付系统设计.md` 为空骨架）；可复用先例 = V6.2 `${DB_*:}` 占位符、V6.1 renderShared 前端注入、三态回落唯一实现模式（resolveGenPrint/resolveGenDeploy）
- **修正 1**：规划写 `pay_enabled tinyint 缺省 0`——按 V4.4 坑库教训（NOT NULL DEFAULT 杀死回落层），改为**可空三态**（NULL=关），回落唯一实现 `GenTemplateModel.resolvePay`（项目级 → 硬编码 0），语义与规划等价
- **修正 2**：产物扫码支付需要后端出码——M1 收敛为「后端返回微信 code_url，前端 qrcode 库本地出码」，后端零图像依赖
- **修正 3**：自检框架接线（产物 health 步后跑 mock 全链路）降级为冒烟脚本对产物实跑 mock 全链路（起产物服务+建业务库），产物内置自检下版再接
- 微信 SDK `wechatpay-java` 0.2.x 中央仓库直供、支付宝 `alipay-sdk-java` 中央仓库直供——无 Alfresco 式私仓风险（V6.1 坑 43b 不复现）

## 四、验收标准（AC）

- **AC1**：pay_enabled=1 系统 scaffold 产物含：db/pay.sql（pay_order DDL）、common/pay/ 四类（PaymentService 接口 + WxPay/AliPay/Mock 实现）、PayController、PayReconcileJob、pom 含两 SDK 依赖
- **AC2**：产物起服务（mock 渠道）：POST /pay/order 下单 → POST /pay/mock/{outTradeNo}/pay → GET /pay/order/{outTradeNo} 状态=1；business_type 指向含 pay_status 的业务表时该行 pay_status 联动置 1；重复 mock 支付幂等（pay_order 不重复、金额不变）
- **AC3**：产物前端含 cashier.vue（收银台）+ order.vue（支付记录）+ api/pay.js + router-snippet；pay_status 业务表详情有「去支付」
- **AC4**：查单补偿任务类存在且可配置（yml 开关+间隔占位符）
- **AC5**：产物 yml 无明文支付密钥（grep 断言），local.yml.example 引导
- **AC6**：产物 `mvn compile` 通过（两 SDK 中央仓库拉取后离线可编）
- builtin 回归：pay_enabled 未开启的系统产物零支付痕迹

## 五、明确不做（P2）

平台代收付/资金归集（合规红线）、小程序支付、聚合支付服务商分账、对账单自动对账、微信 JSAPI/H5、退款端点、pay_code 表级绑定、支付宝沙箱 profile（均 P1/下版）。
