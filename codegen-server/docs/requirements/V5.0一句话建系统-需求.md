## 一、背景与目标

现状：新建一个系统（如 wms/财务）需要手工 6 步——建台账、填路径、跑脚手架（curl）、补审计列、清网关前缀、dryRun。2026-10-23 财务系统接入踩了 4 层根因链（详见当日工作日志）。

目标（M1）：**输入系统名称 + 一句话描述 → 确认 AI 生成的表结构 → 一键触发流水线 → 看到分步进度 → 部署完成后拿到可访问的系统**。全程不碰数据库、不开 curl、不看日志排错。

M2/M3（双进度条并行、全自动模式、进程管理页、AI lint）不在本版。

## 二、功能点编号列表

| 编号 | 功能点 | 一句话 |
|---|---|---|
| F-01 | AI 领域建模 | 输入名称+描述，LLM 生成候选 DDL（M1 接真实 LLM，失败可手动粘贴 DDL 兜底） |
| F-02 | 表结构确认 | AI 结果以可编辑表格呈现，用户可增删改列后再执行 |
| F-03 | 建库建表+导表 | 确认后执行 DDL 并自动导入 gen_table（复用 execute-ddl） |
| F-04 | 一键流水线 | 「开始构建」按钮：骨架→扫表→生成(compile 开)→打包→部署→健康检查，串行执行 |
| F-05 | 进度可视化 | 流水线运行期分步进度条 + 每步状态/耗时/日志摘要，SSE 推送 |
| F-06 | 部署产物管理 | 记录部署实例（端口/PID/日志路径），支持停止；完成卡片展示前端访问地址 |
| F-07 | 登录接口补全 | 修复 scaffold withAuth 真缺陷：生成 AuthController（登录/登出/me）+ 前端登录页 |
| F-08 | 生成前置 lint | apply 前按 BaseEntity 约定检查目标库表列，缺审计列阻断并在报告给出补齐 SQL |
| F-09 | apiBase 去回落 | GenTemplateModel apiBase 前缀三级回落删掉 "demo" 硬编码段（空即空） |

## 三、边界与异常

- AI 不可用/超时：F-01 降级为「手动粘贴 DDL」模式，流水线其余步骤不受影响
- 流水线中途失败：任务停在失败步，可从失败步重试（scaffold/apply 幂等：force=false、备份批次机制）
- 端口占用：分配器预检 8080/9080 等默认段，被占自动顺延并写回台账；**子进程启动必须显式 --server.port 且清理 SERVER__PORT 环境变量**（坑 #5）
- 建库建表属破坏性操作：执行前弹确认，列明影响库与表清单
- 同名系统/同名表已存在：阻断并提示，不静默覆盖
- 并发：同一时刻仅允许 1 条运行中的流水线（M1 简化，后续可扩展）

## 五、歧义点（请用户确认）

1. **LLM 供应商**：M1 接哪家？（候选：OpenAI 兼容接口 / 本地 Ollama / 腾讯混元）。默认假设：OpenAI 兼容接口，base-url+key 放 application.yml
2. **部署形态**：M1 假设「本机 dev 运行」（java -jar + npm run serve 常驻），不做远程部署/容器化
3. **前端启动方式**：dev server 常驻（热更可见）vs build+静态托管（资源占用低）。默认假设：dev server 常驻
4. **AI 建库范围**：AI 只建业务表，系统表（sys_user 等）由脚手架自带 SQL 负责——确认此边界？
