## 一、背景与目标

现有流水线已经具备 AI 模块拆分、AI 表建模、DDL 执行、生成配置导入、前后端代码生成、菜单注册、种子数据、打包部署和健康检查能力，但仍有两个可确认性缺口：

1. AI 模块清单只作为生成表结构的中间数据，用户无法先检查“系统应该有哪些模块和功能”。
2. 用户在建表前只能看到表结构，看不到服务端即将执行的完整 MySQL SQL。

V9.4 不新建另一套生成器，而是增强现有向导，使“输入 xx 系统 + 一句话描述”形成以下可检查链路：

**需求 → 功能清单 → 表结构与 SQL → 建库建表 → 构建启动。**

用户已明确选择“**每个阶段都确认**”：任何 AI 生成和 SQL 预览均不得写业务数据库；建表成功后也不得自动启动构建。

### 目标

- 让功能清单成为可见、可编辑、可勾选的正式生成输入。
- 让完整 SQL 成为建表前可核对的正式产物。
- 保证 SQL 预览与实际执行来自同一服务端组装方法。
- 保留现有代码生成和部署能力，只在明确确认后执行有副作用的阶段。

## 二、功能点

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F-01 | AI 功能清单 | P0 | 根据系统名称和描述生成模块名、模块说明、每模块 3~6 条功能点；支持编辑、增删、勾选 |
| F-02 | 清单驱动表建模 | P0 | 只针对勾选模块逐模块生成表结构；显示进度；按表名去重；列明失败模块 |
| F-03 | 完整 SQL 同源预览 | P0 | 服务端生成完整 MySQL DDL，包含建库语句、候选表和标准主键/审计列；展示表数和语句数 |
| F-04 | SQL 确认后建库建表 | P0 | 用户确认库名、表数和 SQL 后，才创建流水线、系统台账并执行现有 prepare-db |
| F-05 | 构建启动二次确认 | P0 | 建表结果真实展示；用户再次点击后才执行代码生成、打包、部署和健康检查 |

### 生成范围调整

原向导的“快速（3~5 表）/完整系统（8~12 模块）”两种隐藏建模口径，统一调整为**功能清单勾选控制范围**：默认勾选 AI 规划的全部模块，用户可减少或调整模块后再建模。手动粘贴 DDL 模式继续保留，不强制经过 AI 功能清单。

## 三、范围边界

### 本期做

- 扩展现有 AI 模块拆分响应，增加 `functions` 功能点数组。
- 改造现有向导为四步：录入需求、功能清单、表结构与 SQL、建表与构建。
- 新增无状态 AI 模式 DDL 预览接口。
- 复用现有 `buildDdl`、`prepareDb`、`run`、SSE 进度和失败重试。
- 保留手动 DDL、危险 SQL 拦截、同名系统阻断、单流水线限制和本机部署。
- 增加 AI 响应兼容、SQL 同源和四阶段浏览器验证。

### 本期不做

- 完全无人值守自动建库、自动构建。
- 新增 LLM 供应商或模型配置页面。
- 多轮对话式建模、需求到业务流程图、原型图或 PRD 自动生成。
- AI 自动修改已有业务表，开放 DROP、TRUNCATE、ALTER DROP。
- 远程部署、容器部署、新建独立自动化平台。
- 为功能清单或 SQL 预览新增平台数据库表。

## 四、阶段与写入边界

| 阶段 | 用户操作 | 允许行为 | 禁止行为 | 完成标志 |
|---|---|---|---|---|
| ① 录入需求 | 输入系统名、描述、库名，点击生成功能清单 | 调用 AI 规划模块 | 不创建流水线、系统台账、业务库表 | 展示功能清单 |
| ② 功能清单 | 编辑/勾选模块，确认清单 | 调用 AI 逐模块生成候选表，计算 SQL 预览 | 不写平台任务和业务数据库 | 展示表结构与完整 SQL |
| ③ 表结构与 SQL | 编辑表结构、刷新 SQL，确认执行 | 创建流水线与系统台账，执行确认后的 DDL，导入表配置 | 不自动构建 | 返回真实建表结果，状态 `await_confirm` |
| ④ 建表与构建 | 核对结果，点击开始构建 | 执行现有生成、打包、部署、健康检查 | 未点击不得运行构建步骤 | `success` 或 `failed`，可打开系统或重试 |

确认建表前的数据属于向导暂存；刷新页面可能丢失，页面应明确提示。确认建表后沿用现有任务持久化和断点能力。

## 五、业务规则与异常

| 场景 | 约定 |
|---|---|
| 空系统名/描述 | 不调用 AI，前端提示补全 |
| 未勾选任何模块 | 禁止确认清单 |
| AI 未返回 `functions` | 按空数组兼容，模块名称和说明仍可使用 |
| 部分模块建模失败 | 保留成功模块结果并列出失败项，由用户决定是否继续 |
| 候选表为空 | 禁止生成执行 SQL 和建表 |
| 数据库名为空或非法 | 服务端拒绝预览与执行 |
| 表名/列名需要规范化 | 预览与执行共同沿用现有 `fixColumns` 规则，不得各写一套 |
| 表结构被修改 | 标记 SQL 已过期，必须刷新预览后才能确认建表 |
| AI 模式 SQL 编辑 | SQL 只读；需修改时编辑功能清单或表结构后重新生成 |
| AI 不可用/超时 | 不写业务库，可重试或切换手动 DDL |
| 重复点击 | 所有 AI、预览、建表和构建按钮均有 loading 防重 |
| 建表失败 | 展示真实失败原因，不进入构建确认 |
| 构建失败 | 保留 `failed` 状态和步骤日志，沿用现有重试 |
