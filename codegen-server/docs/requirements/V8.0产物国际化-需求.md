# 代码生成器 V8.0 —— 产物工程国际化（i18n）

> 日期：2026-11-11　状态：**已确认范围，开发中**
> 上游：V7.5「项目语言配置」（206 语言清单 / `default_language` / `supported_languages` / 生成物 `lang`、`dir` 注入）
> 用户确认（2026-11-11）：作用对象 = **生成的系统**；译文策略 = **内置精译 + 占位包**

## 一、背景与目标

V7.5 交付的是「配置能力」：平台能回答「这个系统支持哪些语言、默认是什么、RTL 怎么排」，并把 `lang` / `dir` 写进产物 `index.html`。但产物工程本身仍是纯中文硬编码——切到 `ar-SA` 只会得到一个 `<html dir="rtl">` 的中文界面。

V8.0 要把这些配置真正用起来：**按系统已配的语言，生成一套可切换的多语言产物前端**，让「一份表配置 → 生成能说多种语言的系统」成立。

**谁用**：用本平台给海外客户交付后台系统的开发者；在系统管理里配好默认语言/启用语言，生成后业务方即可在页面右上角切语言。

**不做会怎样**：每接一个海外项目要人工改 22 个模板与全部生成页；V7.5 的语言清单沦为摆设；RTL 语言只有 `dir` 声明没有镜像布局。

### 版本编号说明

`docs/代码生成器-V7.4-规划.md` 的「备选主题」把 V8.0 预留给「C 端只读商城生成」。本次由用户明确指定 **V8.0 主题为国际化**，覆盖该备选；C 端商城顺延到 V8.1+ 候选。本文不修改 V7.4 原文，仅在文末修订记录登记该决策。

## 二、功能点

| 编号 | 功能点 | 优先级 | 说明 |
|---|---|---|---|
| F-01 | 系统级 i18n 开关 | P0 | `sys_project.i18n_enabled` 三态（NULL=关 / 1=开 / 0=关），回落实现唯一；系统编辑弹窗可配 |
| F-02 | 内置精译词库 | P0 | classpath `i18n/messages/<locale>.json`，8 种语言的人工精译，覆盖约 60 个 `common.*` 键；与 V7.5 `languages.json` 同源（清单不另建） |
| F-03 | 占位语言包 | P0 | 其余语言生成**键齐全**的占位包，值为空串 → 运行时回落默认语言；单个语言包结构完整，用户补译即可生效 |
| F-04 | 产物语言包生成 | P0 | 按 `supported_languages` 生成 `src/locales/<locale>.json` + `index.js`；留空 = 默认语言 + 8 种内置精译；显式配置按清单（上限 206） |
| F-05 | 产物运行时（零依赖） | P0 | `src/utils/i18n.js`：`$t` / `setLocale` / `getLocale`、缺失键三级回落（当前语言 → 默认语言 → key）、`localStorage` 持久化、`Intl` 日期/数字格式化、切换时同步 `<html lang/dir>`。不引 `vue-i18n`，产物离线可编译 |
| F-06 | 文案接线（模板零改动） | P0 | 渲染后重写器把产物前端固定中文替换为 `$t('common.xxx')`；22 个 `.ftl` 源码零改动、黄金基线快照零 diff；骨架的布局/登录/首页/请求提示同步接线 |
| F-07 | 语言切换器 | P0 | 产物右上角 `LanguageSwitch.vue`，只列该系统启用语言，显示中文名 + 本地自称，RTL 语言带标记；切换后整页响应式重渲染 |
| F-08 | RTL 布局 | P0 | `dir=rtl` 时骨架样式走逻辑属性（`margin-inline-start` 等），切换时动态更新 `<html dir>`；代码块/路径保持 LTR |
| F-09 | 平台文案翻译页 | P0 | 按系统 + 语言编辑译文：键清单、内置值、覆盖率、批量保存、导入/导出 JSON、重置为内置 |
| F-10 | 译文接口 | P0 | 分页查询 / 保存 / 导出 / 导入 / 可用语言 / 键清单，统一 `{code,msg,data}`，错误也是 HTTP 200 + `code` |
| F-11 | 业务名占位键 | P1 | 表/字段中文名生成 `table.<表>.label` / `column.<表>.<列>.label` 键，占位值 = 中文原名，用户可逐语言补译；V8.0 不自动翻译业务名词 |
| F-12 | 文档与验证记录 | P0 | 需求/设计/接口/验证记录、UI 效果图、三层验证证据 |

## 三、边界与异常

| 项 | 约定 |
|---|---|
| 三态语义 | `i18n_enabled` NULL / 0 = 关（存量系统零 diff）；1 = 开。沿用 `resolvePay` / `resolveFile` 同款 |
| 语言清单唯一真源 | 复用 `LanguageConfig.all()` 的 206 语言；BCP47 标签按 V7.5 `options()` 去重后使用，禁止再建一份清单 |
| 未配置语言 | `supported_languages` 留空 → 默认语言 + 8 种内置精译；非清单内标签直接丢弃并记 WARN，不生成畸形文件名 |
| 文件数上限 | 最多 206 个语言包；每个约 2KB。超出白名单一律拒绝，防路径穿越（标签正则 `^[A-Za-z0-9-]{2,32}$`） |
| 译文缺失 | 三级回落：当前语言非空值 → 默认语言 → key 本身；不显示空白、不抛异常 |
| 用户译文覆盖 | `sys_i18n_message` 按 `(project_id, locale, msg_key)` 唯一；生成时覆盖内置值；清空 = 恢复回落 |
| 产物零重依赖 | 不新增任何 npm 依赖；`i18n.js` 纯 ES5+ 语法，`node --check` 可过 |
| 模板基线 | `.ftl` 源码零改动，三副本 MD5 不变；`i18n_enabled=关` 时全部产物逐字节与 V7.5 一致 |
| 数据归属 | 内置词库是平台级静态配置；用户译文按 `project_id` 隔离，删系统时一并清理 |
| 并发 / 权限 | 译文保存按 `(project_id, locale, msg_key)` upsert，沿用平台鉴权，不新增白名单端点 |
| 明确不做 | 平台自身 `codegen-web` 界面翻译；产物后端错误消息 i18n；uni-app 移动端 i18n；字典/枚举值翻译；图片内文字；AI 翻译；机器规则批量翻译。以上列 P1/顺延 |

> 说明：用户选择的「内置精译 + 占位包」意味着 **206 种语言都有完整语言包结构，但只有 8 种有人工译文**。这是刻意的取舍——没有译文源就不伪造译文；平台提供逐语言编辑与导入，业务方按需补译。验收会分别断言「结构覆盖 206」与「精译覆盖 8」。

## 四、验收标准（可勾选、可观测）

- [ ] AC-01 `sys_project.i18n_enabled=1` 的系统生成产物，前端出现 `src/utils/i18n.js`、`src/locales/index.js`、`src/components/LanguageSwitch.vue` 与 ≥9 个语言包；=0/NULL 时这些文件一个都不出现，且其余产物与基线逐字节一致。
- [ ] AC-02 `supported_languages` 配 `zh-CN,en-US,ar-SA` 时恰好生成 3 个语言包；配 206 个标签时生成 206 个且无异常；非法标签 `../../etc` 被拒且不产生任何文件。
- [ ] AC-03 8 种内置精译语言包的 `common.*` 键数量相同且值非空；其余占位包键数量相同、值为空串。
- [ ] AC-04 产物 `vuePage` 生成页中「查询/重置/新增/编辑/删除/保存成功/共 N 条」等固定文案已变成 `$t('common.xxx')`，且 `node --check` 对产物 JS 零错误、Vue 模板可被解析。
- [ ] AC-05 `i18n.js` 单测覆盖：命中当前语言、回落默认语言、回落 key、非法标签、切换后 `localStorage` 与 `<html lang/dir>` 同步。
- [ ] AC-06 真浏览器打开产物页面：右上角可切换 `中文 / English / العربية`，切到 `ar-SA` 时 `<html dir="rtl">`、按钮文案变阿拉伯语、console 零 error。
- [ ] AC-07 平台文案翻译页：选系统 + 语言 → 显示键清单与覆盖率 → 改一条保存 → 重新生成产物，该译文出现在 `src/locales/<locale>.json`；导出 JSON 再导入后值一致。
- [ ] AC-08 译文接口分页/保存/导出/导入/边界（不存在的系统、非法语言、必填缺失）各调一次，断言 `code` 而非仅 HTTP 状态。
- [ ] AC-09 后端 `mvn -o -DskipTests compile` 零错误；新增单测全绿；全量测试除既有红灯 `HistogramConfigProbeTest` 外无新增失败。
