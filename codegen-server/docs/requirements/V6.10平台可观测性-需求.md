# V6.10 平台可观测性 —— 需求

> 版本：V6.10　日期：2026-11-10　状态：**待过目**
> 上游规划：[代码生成器-V6.10-规划.md](代码生成器-V6.10-规划.md)
> 一句话：让平台能回答三个问题——现在慢不慢、哪里在报错、上一次生成写了多少文件。

## 背景与目标

平台目前只有 logback 文件日志和 `sys_oper_log` 业务审计，**没有任何运行时指标**：`pom.xml` 无 Actuator、`application.yml` 无 `management` 配置、全仓无 `/health` Controller，白名单里那两条 `/actuator`、`/health` 指向的是不存在的端点。

出现问题时的现状是"翻日志 + 猜"。典型场景：

- 生成一次代码要 40 秒，是模板渲染慢还是写盘慢？不知道。
- 流水线失败率多高？只能一条条翻 `gen_pipeline` 表。
- V6.9 的 LibreOffice 文档转换经常"感觉很久"，到底几秒？没有数据。

本版目标：**单机、零外部依赖地看到 JVM、HTTP、业务三类指标，并在平台内有一页能持续看的面板。** 目标不是做完整 APM，不引入 Prometheus/Grafana/链路追踪。

## 功能点

| 编号 | 功能点 | 说明 |
|---|---|---|
| F-01 | Actuator 接入 | 加 `spring-boot-starter-actuator`；`management.endpoints.web.exposure.include` **枚举放行** `health,info,metrics`，不含 `env/beans/heapdump/threaddump/loggers`；`health.show-details=never` |
| F-02 | 端点安全收窄 | `AuthContextFilter.WHITE_LIST` 把 `/actuator` 收窄为 `/actuator/health`，删除死条目 `/health`；`/actuator/metrics` 必须带 token |
| F-03 | 定时采样 | 独立 `MonitorConfig` 加 `@EnableScheduling`（平台首次），`spring.task.scheduling.pool.size=2`；`@Scheduled(fixedDelay=5000)` 采样，异常全 catch + warn |
| F-04 | 环形缓冲 | `ArrayDeque` 容量 360（30 分钟 × 5s），满则淘汰最旧；每个样本带 `timestamp` |
| F-05 | JVM/进程指标 | 堆已用/上限、非堆已用、活跃线程、GC 暂停次数与耗时、CPU 使用率、进程启动时长、CPU 核数 |
| F-06 | HTTP 指标 | 区间请求数、QPS、平均耗时、P95、P99、4xx/5xx 错误数；开启 `percentiles-histogram`，`max-uri-tags=100` |
| F-07 | 慢接口排行 | 按 URI 模板聚合，返回 Top N（默认 10）的 `uri/method/count/avgMs/maxMs` |
| F-08 | 业务埋点 | 4 处：`GenCodeServiceImpl#writeToDisk`（耗时 + 文件数）、`#preview`（耗时）、`PipelineExecutor`（步骤耗时 + 运行状态）、`DocPreviewEngine#convertToPdf`（耗时 + 命中/转换/失败） |
| F-09 | 实时概览接口 | `GET /monitor/overview`：当前快照 + `lastSampleAt` + 采样是否在走 |
| F-10 | 序列查询接口 | `GET /monitor/series?metric=&minutes=`：metric 走**白名单枚举**，非法值 400；minutes 钳到 1~30；窗口未满返回 `warmup=true` |
| F-11 | HTTP 聚合接口 | `GET /monitor/http?minutes=&topN=`：区间汇总 + Top N 慢接口 |
| F-12 | 业务聚合接口 | `GET /monitor/business?minutes=`：生成批次与成功率、写盘文件数、pipeline 状态分布、文档转换耗时 |
| F-13 | 监控页面 | `/monitor` 一页：4 张指标卡 + JVM 趋势 + HTTP 趋势与慢接口表 + 业务区；ECharts 按需引入、异步 chunk |
| F-14 | 轮询与暂停 | 5s 轮询；页面隐藏时暂停、恢复时立即拉一次；离开页面清定时器 |
| F-15 | 菜单与权限 | `sys_menu` 新增 `id=3030`、`path=/monitor`、`component=monitor/index`、`perms=monitor:view`；后端 `/monitor/*` 校验该权限码，超管直通 |
| F-16 | 采样停滞提示 | 页面发现 `lastSampleAt` 超过 3 个采样周期（15s）未更新时，顶部显示"采样停滞"告警条 |

## 边界与异常

- **窗口边界**：缓冲满后淘汰最旧样本，不扩容；重启后为空，页面显示 `warmup=true` 与"仅进程内 30 分钟"提示。
- **多实例**：各实例独立统计，互不聚合；本版不做跨实例合并（已明确写入限制）。
- **采样失败**：单轮采样抛异常只 `log.warn`，不影响业务请求，也不让调度任务停摆。
- **埋点失败**：`MeterRegistry` 调用包 `try/catch`，异常只记 debug，绝不影响生成主流程。
- **鉴权**：`/actuator/health` 免 token；`/actuator/metrics`、`/monitor/*` 均需 token；无权限返回 403，无 token 返回 401。
- **参数非法**：`metric` 不在白名单 → 400；`minutes` 越界 → 钳位而非报错；`topN` 上限 50。
- **前端降级**：ECharts chunk 加载失败时，指标卡与表格仍可用，趋势区显示"图表组件加载失败"。
- **既有脚本兼容**：已核实 `scripts/` 下探活走 `nightly-fullgen.mjs` 的 `healthy()`，探测目标是 `/gen/pipeline/config`，**未访问 `/health` 或 `/actuator`**，因此删除死条目安全。若仓库外的运维脚本有依赖，改为转发到 `/actuator/health`，**不允许恢复 `/actuator` 全量放行**。
- **敏感信息**：`health.show-details=never`，面板不展示数据库地址、连接串、JVM 参数原文。

## 验收标准

| 编号 | 验收标准 | 验证方式 |
|---|---|---|
| AC1 | `GET /actuator/health` 无 token 返回 200 且 `status=UP` | curl |
| AC2 | `GET /actuator/metrics` 无 token 返回 401，带 token 返回 200 | curl ×2 |
| AC3 | `GET /actuator/env` 返回 404（未暴露） | curl |
| AC4 | `GET /monitor/overview` 带 token 返回 200，含 `lastSampleAt`、`sampling=true` | curl |
| AC5 | `GET /monitor/series?metric=evil` 返回 400；`minutes=999` 被钳到 30 | curl ×2 |
| AC6 | 服务启动 2 分钟后 `GET /monitor/series?metric=jvm.heap` 返回 `points.length >= 20` | curl + jq |
| AC7 | 缓冲满 360 点后仍只保留 360 点，最旧点被淘汰 | 单测（容量调小后断言） |
| AC8 | 采样任务内抛异常不影响后续轮次执行 | 单测（注入抛异常的取数器，断言下一轮仍执行） |
| AC9 | 跑一次 `gen_write`，`/monitor/business` 的文件数增量与磁盘实际变更数一致 | 接口 + 文件比对 |
| AC10 | 监控页 console 零 error，4 张卡片有值、趋势图 ≥2 个点、慢接口表非空 | 真浏览器 + 截图 |
| AC11 | 切到其他菜单后，Network 无新增 `/monitor/*` 请求 | DevTools 观察 |
| AC12 | `mvn test` 既有 196 例不回归，新增用例全过 | `mvn test` |
| AC13 | `#[WHITE_LIST]` 不含 `/actuator` 整体，`exposure.include` 不含 `env/heapdump` | 单测断言 |
| AC14 | 前端 `npm run build` 零 error，ECharts 不在主包内 | 构建产物检查 |

## 明确不做（本版本）

- 告警发送（阈值 + 站内信/邮件/Webhook）：留 V6.11。
- Prometheus 拉取端点、Grafana 面板、外部时序库。
- 指标历史持久化、跨实例聚合。
- 分布式链路追踪（Tracing）、日志采集（ELK/Loki）。
- 前端性能指标（Web Vitals）、慢 SQL 采集。
- MCP 服务（方案已取消，不实施）。
