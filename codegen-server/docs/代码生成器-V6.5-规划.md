# 代码生成器 V6.5 规划 —— 移动端支持：uni-app 单源 H5 + 微信小程序

> 日期：2026-10-25　状态：规划待过目
> 与 V6.1~V6.4 无强耦合；「我的待办」移动页联动 V6.1（未实装则该页留占位菜单），小程序支付联动 V6.3（P1）。
> 定位：产物从「PC Web 一个端」扩展为「PC + H5 + 微信小程序」——移动审批、移动查数、移动录入。

## 一、现状核对（2026-10-25 实测）

| 项 | 现状 | 位置 |
|---|---|---|
| 产物前端 | Vue 2.7.16 + Element UI 2.15.14 + vue-cli/webpack，**纯 PC 桌面布局**，无任何响应式/移动端处理 | `GenScaffoldServiceImpl:3320-3433` |
| 移动端痕迹 | **零**：模板与脚手架无 uni-app/小程序/媒体查询（grep 命中均为 remove 假阳性） | 全量 grep |
| 接口契约 | REST + Bearer token（/auth/login 签发），与端无关——**移动端可直接复用**，后端零改动 | AuthContextFilter（V6.4 将升级两级校验） |
| 枚举/字典链路 | 列注释「1xx 2yy」→ enumMap、dict_type 回落链——移动端表单控件映射可直接复用同一套模型 | GenUtils / GenTemplateModel |
| 审批待办接口 | V6.1 规划 /flow/todo、/flow/done、/flow/task/{id}（flowTodo.ftl 雏形已现） | V6.1 规划 |
| uni-app 编译链 | `@dcloudio/uni-app` + vite CLI 构建（`build:h5` / `build:mp-weixin`），Node 可跑、可进流水线；**小程序真机预览/上传仍需微信开发者工具**（CI 内只能出包不能发布） | uni-app 官方 CLI 文档 |
| 小程序平台约束 | 小程序 request 域名须 HTTPS 且在 mp 后台配白名单——**本地联调须开发者工具勾「不校验合法域名」** | 微信平台规则 |

**问题**：移动场景（领导手机审批、员工手机请假/查工资条）只能开 PC 页面凑合——Element UI 表格在手机上不可用。生成器覆盖了 Web 全链路，移动端是完整空白。

## 二、主题与理由

**主题：`sys_project.mobile_enabled` 开关——生成独立 uni-app 工程 `{code}-mobile`（Vue 3 + vite + uni-ui），单源编译 H5 与微信小程序两个产物；M1 交付登录、标准列表/详情/表单、我的待办五类页面，与 PC 共用同一后端与 token 体系。**

理由：

1. **uni-app 单源是生成器视角的最优解**：一套页面模板编译两端，模板维护成本减半；uni-app 是国内小程序事实标准生态，文档/组件/踩坑资料最厚；
2. **独立工程而非改造 PC 前端**：Element UI 表格/弹窗形态在手机上没有可接受的响应式改造路径，强行适配两头不讨好；独立 `{code}-mobile` 工程互不干扰，PC 产物行为零回退（与 V6.3 pay_enabled 同款开关模式）；
3. 后端接口与鉴权端无关，移动端**纯前端增量**——不动 12 个后端模板，风险面天然隔离；
4. 移动审批与 V6.1 待办接口天然联动，是四版规划里移动端价值最直接的落点。

## 三、范围

### P0-1 uni-app 工程模板（`{code}-mobile`）

- 技术栈：uni-app（Vue 3 语法）+ vite + **uni-ui**（官方组件库，跟随官方维护不押注第三方）+ pinia（token/用户态）
- 脚手架产出完整工程：请求封装（baseURL 按 `MOBILE_API_BASE` 环境变量注入，H5 走代理 / 小程序直连 HTTPS）、token 拦截器（复用 /auth/login 与 Bearer 头）、登录页、tabBar 框架（首页/待办/我的）
- **浏览器兼容取舍**：Vue 3 语法仅用于 mobile 工程，PC 前端维持 Vue 2 不动（两工程独立构建互不影响）；产物后端 Java 21 无影响
- 工程落 `{code}-mobile/`，与 `{code}-web/`、`{code}-server/` 平级——三目录产物布局在自检/打包契约中登记

### P0-2 标准页面模板三件

- `mobileList.vue`：搜索栏 + uni-ui 列表卡片 + 下拉刷新/上拉加载（分页语义与 PC page 接口一致）；行点击进详情
- `mobileDetail.vue`：字段分组展示（字典/枚举列走 commentLabel 映射显示标签而非裸值）+ 操作按钮（编辑/删除/审批，按 v-perm 同源 perms 显隐）
- `mobileForm.vue`：按列类型自动映射控件——varchar→input、text→textarea、bigint/int→number、date/datetime→日期选择、tinyint+enumMap→picker 单选（**复用 GenTemplateModel 现有列分类标记，不新增模型**）；主从表 M1 只带主表（从表编辑不上移动端）
- 页面生成范围：平台系统编辑页新增「移动端页面」多选（M1 缺省全部标准表，树表/主从表缺省排除可勾选）

### P0-3 我的待办移动页（联动 V6.1）

- 待办列表 + 详情内嵌审批操作（通过/驳回/意见），复用 /flow/todo、/flow/task/{id}、/flow/approve|reject 端点——**接口零新增**；V6.1 未实装时该页隐藏（菜单条件渲染），实装后自动出现

### P0-4 流水线与自检接线

- `scaffold` 步：`mobile_enabled=true` 时追加写盘 mobile 工程（relPath 契约加 `webRoot` 同级的 `mobileRoot`）
- `package_frontend` 扩展（或新子步 `package_mobile`）：`npm run build:h5` 出 H5 静态包（部署到 web 同机独立端口/路径）；`build:mp-weixin` 出小程序包目录（**交付 zip，真机预览由用户在微信开发者工具导入——CI 内不做小程序上传，诚实边界**）
- 自检：H5 构建产物存在性 + 首页路由断言；小程序仅目录结构断言（CI 无开发者工具无法运行时验证）

### P0-5 平台端

- 系统编辑页：`mobile_enabled` 开关 + 移动端页面勾选（与 P0-2 生成范围联动）
- 帮助文案：小程序合法域名配置、开发者工具「不校验合法域名」联调开关、HTTPS 要求——如实写进产物 readme

### P1（本版尽力，不做门禁）

- 微信授权登录：wx.login → code2session → 绑定 sys_user（需要服务端新增 /auth/wx-login 端点与 openid 列——后端不再是纯零改动，单独评估）
- 小程序支付：复用 V6.3 pay_order，小程序 JSAPI 下单端点
- 扫码填单（uni.scanCode → 表单回填）、订阅消息通知（审批到达提醒）
- H5 版移动审批推送（企业微信/钉钉工作台集成 H5 链接）

### P2（明确不做，下版再说）

- App 原生打包（uni-app 打 Android/iOS 包，HBuilderX 云打包依赖外部服务）
- 小程序上传与审核自动化（miniprogram-ci 需私钥上传权限，运维面话题）
- 离线缓存/弱网同步
- 移动端可视化页面装修

## 四、关键设计决策

| 决策点 | 定案 | 理由 |
|---|---|---|
| 端方案 | uni-app 单源 → H5 + mp-weixin，不做独立小程序原生工程 | 一套页面模板两端产出，生成器模板成本减半；原生小程序工程意味着再养一套模板体系，收益不抵成本 |
| UI 库 | uni-ui（官方） | uView 停更风险、第三方押注；uni-ui 跟 uni-app 官方版本走，且组件覆盖 M1 所需（list/form/picker/refresh） |
| 工程形态 | 独立 `{code}-mobile`，不改 PC 前端 | Element UI 无可接受的移动化路径；独立工程零回退风险；双 Vue 版本（PC 2 / mobile 3）经独立构建隔离，不共存一个工程 |
| 登录体系 | 复用账号密码 + Bearer token，M1 不做 wx.login | token 体系端无关直接可用；wx.login 引入 openid 绑定与后端新端点，是独立的安全话题，P1 单独评估 |
| 生成范围 | 标准表缺省上移动端，树表/主从表缺省排除 | 树形与主从多 tab 交互在手机上无成熟形态，硬塞产出不可用页面不如不生成（诚实边界）；可勾选放开 |
| 小程序发布 | CI 只出包不发布 | miniprogram-ci 上传需管理员私钥且不可逆发布——发布决策留给人，生成器不出「一键上架」 |

## 五、验收标准

1. 人事系统开启 `mobile_enabled` → 流水线 9/9 绿 + mobile 工程写盘 → `build:h5` 成功出包
2. H5 手机浏览器/模拟器：登录 admin → 员工列表下拉刷新/分页 → 详情字典列显示标签 → 新增/编辑表单控件类型正确（日期选择器、枚举 picker）→ 提交成功 PC 端可见
3. 微信开发者工具导入 `dist/build/mp-weixin` → 勾选跳过域名校验 → 登录/列表/表单与 H5 行为一致
4. V6.1 已实装前提下：移动端「待办」tab 可见请假审批任务，手机上完成通过/驳回，PC 端状态同步
5. PC 产物黄金基线零 diff（mobile 全部在独立目录与独立模板中，PC 模板零改动——本版红线）
