## 1. 系统定位

码匠是一个**以数据库表为输入、以可运行前后端工程为输出**的代码生成平台。用户在网页上配置表结构 / 导入 DDL，平台通过模板引擎渲染出 Entity、Mapper、Service、Controller、Vue 页面、API 等产物，并可选「一键建系统」把产物打包部署成独立可运行的服务。

核心价值：把「建表 → 出 CRUD → 出页面 → 跑起来」的重复劳动收敛为一个平台操作。

## 3. 整体架构

```
                         ┌─────────────────────────────────────────────┐
  浏览器 ── HTTP ──▶      │            codegen-server (8120, 单体)         │
                         │                                               │
                         │  AuthContextFilter (Bearer 鉴权 + UserContext) │
                         │        │                                      │
                         │  Controller 层 (15 个 REST 控制器)             │
                         │        │                                      │
                         │  Service 层 (33 个接口 / impl)                 │
                         │    ├─ GenCodeService   代码生成主流程           │
                         │    ├─ GenTemplateEngine 模板渲染               │
                         │    ├─ GenPipelineService + PipelineExecutor    │
                         │    ├─ AuthService / PermissionService 权限      │
                         │    └─ DocService 文档中心                      │
                         │        │                                      │
                         │  Mapper 层 (MyBatis-Plus)  ◀──▶  MySQL         │
                         │                                               │
                         │  common/ (config context datascope exception    │
                         │           flow handler log page result util)   │
                         │  monitor/ (V6.10 可观测性七件套)               │
                         │  support/ (生成辅助：seed/bpmn/naming/path)     │
                         └─────────────────────────────────────────────┘
                                      │ 调用子进程 / 写盘
                                      ▼
                          目标工程 (用户配置的后端+前端工程目录)
```

**分层约定**
- `controller`：仅做参数绑定、权限码校验、结果包装（`Result<T>`），不含业务。
- `service` / `service/impl`：业务逻辑；`PipelineExecutor` 是唯一允许起子进程的类。
- `common`：跨切面的通用能力（异常、结果、上下文、数据权限、日志、PageHelper 式分页）。
- `monitor`：V6.10 可观测性，独立包，不依赖业务 Service。
- `support` / `util`：无状态的纯工具（命名转换、路径解析、种子生成、模板模型构建）。

## 6. 核心模块详解

### 6.1 代码生成主流程（`GenCodeServiceImpl`）
入口三件套：
- `generateZip(GenDownloadDTO)` — 打包 ZIP 下载，产物不落盘。
- `preview(GenDownloadDTO)` — 前端预览单个/批量文件内容。
- `writeToDisk(GenWriteDTO, batchNo)` — **真正写盘**，流程：

```
renderTables(ids)
   └─ GenTemplateEngine.render(table, cols)  →  Map<relPath, content>
writeTable(table, overwrite, skipDrifted, ...)
   ├─ 渲染（含 V6.10 Timer.Sample 埋点开始）
   ├─ 漂移检测（GenDriftService：人工改过的文件默认跳过）
   ├─ 备份旧文件（batchNo 时间戳目录）
   ├─ 写盘
   ├─ 记录 gen_output 台账
   └─ 埋点结束：monitorMetrics.finishWrite(sample, success, statusCounts)
deliverSqlForProjects(idsByProject, batchNo)  →  menu.sql / db.sql / seed.sql 落 .gen-artifacts
菜单注册（GenMenuService）+ 路由片段（router-snippet.txt）
```

- **幂等**：重跑先 reset 步骤状态；写盘前先备份，文件名用 `batchNo`（yyyyMMddHHmmss）区分。
- **V6.10 埋点**：写盘耗时与按状态（WRITTEN/MERGED/SKIPPED/ERROR）的文件数计入 `gen.write` / `gen.write.files`。

### 6.2 模板引擎（`GenTemplateEngine`）
- **模板存库**：`gen_template` 表，`tpl_code` 唯一；`table_id=0` 为全局模板，`>0` 为表级覆盖（表级优先，回填全局）。
- **内存缓存**：全局模板首次 1 条 SQL 全量载入；表级覆盖命中后才缓存。`evict()` 在模板增删改/回滚/种子同步后失效。
- **渲染**：Freemarker 2.3.31，`RETHROW_HANDLER`；模型由 `GenTemplateModel.build(table, cols, children, project)` 构建（含根包、模块名、列分组、枚举/字典标记、ApiPerms 等）。
- **产物清单**（按表开关裁剪）：`entity` / `mapper` / `service` + `serviceImpl` / `pageDto` / `saveDto` / `vo` / `controller` + `{Class}ApiPerms.java` / `apiJs` / `vuePage` / `printPage` / `crudControllerTest` / `testSchemaTable` / 共享 `README` `router-snippet`。
- **主子表**：递归最多三层（`loadChildren`），跨系统引用在生成期即拦截抛错。
- **能力包注入**：系统 `flow_enabled` / `pay_enabled` / `mobile_enabled` 开启时，额外注入待办中心 / 收银台 / 移动端动态页配置（零侵入，未开启则返回空 Map）。

### 6.3 一句话建系统流水线（`PipelineExecutor`）
12 步串行，每步状态落库 `gen_pipeline_step`，并用 `PipelineSseRegistry` 实时推 SSE 给前端进度条：

```
model → db → ai_recommend → seed → scaffold → gen
      → package_backend → deploy_backend
      → package_frontend → package_mobile → deploy_frontend
      → health
```

- **每步**：`mark(running)` → 执行 → `mark(success|failed)` 或降级 → 推 SSE；任一步失败即停整线。
- **降级不阻断**：
  - `ai_recommend`：`ai.enabled=false` → `skipped`；AI 超时/JSON 截断 → `failed-degraded`，后续按 V6.6 规则推断，产物与 V6.8 一致。
  - `seed`（AI 值池）：失败回落规则词库。
- **踩坑固化**（写进类注释）：子进程必须显式 `--server.port` 且清 `SERVER__PORT`；部署日志落文件便于 `tail`；脚手架/生成/DDL 全部幂等，整线重跑是安全兜底重试。
- **健康检查**：`health` 步用 `HTTP/1.1` 探测前端端口，dev server 首次请求触发全量编译，给 12×20s≈4min 重试预算。
- **SQL 交付物**（V7.2）：流水线成功后把 `db.sql`/`seed.sql`/`menu.sql` 复制到目标工程 `db/`，缺失只告警不阻断。

### 6.4 鉴权与权限
- **`AuthContextFilter`**（`OncePerRequestFilter`，最高优先级 +10）：
  - 白名单（`/auth/login`、`/actuator/health`、`/v3/api-docs`、`/swagger-ui*`、`/error`）免 token。
  - 解析 `Authorization: Bearer <jwt>`；SSE 的 `EventSource` 不支持自定义头，允许 `?access_token=` 兜底。
  - 解析成功 → 填充 `UserContext`（userId/username）；角色与数据权限范围**每次查库**（改权限即时生效，不写死 token）。
  - 解析失败 / 缺失 → 统一 `Result` 结构返回 401，前端 axios 拦截器弹重新登录。
- **`JwtUtil`**：JJWT 0.12.5，密钥与生产 `JWT_SECRET` 必须从环境变量注入（`application.yml` 默认值仅为克隆即跑，启动打 WARN）。
- **`PermissionService`**：`permissionsOf(userId)` 汇总角色菜单 `perms`；`isSuperAdmin` 直通。监控接口 (`monitor:view`) 即在此校验。

### 6.5 数据权限（`DataScopeInterceptor` + `UserContext`）
- 拦截器用 jsqlparser 改写查询 SQL，按 `UserContext.dataScope` 追加部门/本人条件。
- 范围取「最宽」：`all > dept > self`；查库失败按**最小权限 `self`** 降级（fail-closed，不会因异常变全量）。

## 7. V6.10 平台可观测性（重点）

### 7.1 架构
```
Micrometer MeterRegistry
   │  (http.server.requests / jvm.* / 业务 Timer·Counter)
   ▼
MonitorSampler  @Scheduled(fixedDelay=interval-ms, 默认 5s)
   │  区间差分：本轮累计 − 上轮累计 → 增量
   ▼
MonitorStore    ArrayDeque 环形缓冲（cap=buffer-size, 默认 360 = 30 分钟）
   │
   ▼
MonitorController  /monitor/*  (monitor:view 权限)
   │  收敛成页面形状 + 统一鉴权
   ▼
前端 views/monitor/index.vue  (ECharts 按需异步 chunk + 降级)
```

**设计要点**
- **区间差分**：`http.server.requests` 的 count/totalTime 从启动累计，直接展示会让曲线一直向上；Sampler 每轮记录 `prev` 累计值，采出「本区间增量」。HTTP 按 `method|uri|status` 聚合，业务按 `gen.write`/`pipeline.step`/`doc.convert` 聚合。
- **环形缓冲**：`ArrayDeque`，满则淘汰最旧；方法统一 `synchronized`（写=调度线程，读=HTTP 线程）；**重启归零、多实例不共享**（进程内内存窗口，非集中式监控）。
- **失败隔离**：埋点 (`MonitorMetrics`) 与采样 (`MonitorSampler`) 全部 try/catch，指标坏掉绝不让生成主流程失败；采样失败只 `warn`，定时任务继续。

### 7.2 埋点 API（`MonitorMetrics`）
| 方法 | 用途 |
|---|---|
| `start()` | 返回 `Timer.Sample`（埋点起点） |
| `stop(sample, name, tags...)` | 停止计时并打 tag |
| `count(name, amount, tags...)` | 计数（如写盘文件数） |
| `finishWrite(sample, success, statusCounts)` | 写盘收尾：一次 timer + 按状态文件数 |

调用点：`GenCodeServiceImpl.writeToDisk`（写盘计时）、`PipelineExecutor` 每步 `pipeline.step` 三态（`success`/`degraded`/`failed`）。

### 7.3 接口（需 `monitor:view`）
| 端点 | 说明 |
|---|---|
| `GET /monitor/overview` | 实时概览：JVM 堆/非堆、线程、GC、CPU、HTTP QPS/avg/P95/P99/4xx/5xx、采样状态 |
| `GET /monitor/series?metric=&minutes=` | 指标趋势序列（窗口聚合，支持 warmup 提示） |
| `GET /monitor/http?minutes=&topN=` | HTTP 聚合 + 慢接口排行（按 URI 平均耗时降序） |
| `GET /monitor/business?minutes=` | 业务指标：代码生成批次/成功率/文件数、流水线运行/步骤、文档转换 |

`SeriesMetric.of(metric)` 支持 cpu/heap/qps/latency 等指标枚举；`HttpStatsAggregator` 负责 P95/P99 百分位与慢 URI 聚合。

### 7.4 安全与配置
```yaml
management:
  endpoints.web.exposure.include: health,info,metrics   # 只放这三个
  endpoint.health.show-details: never                  # 外部只看 {"status":"UP"}
  metrics.tags.application: codegen-server
monitor:
  sample.interval-ms: 5000     # 5s 一采
  sample.buffer-size: 360      # 30 分钟窗口
```
- **不暴露** `env`/`beans`/`heapdump`/`threaddump`/`loggers`。
- `AuthContextFilter` 白名单只放 `/actuator/health`；`/metrics` 等其余端点仍需 Bearer token。
- `task.scheduling.pool.size: 2`（V6.10 首次引入调度，默认单线程，避免将来定时任务互相阻塞）。

### 7.5 前端（`codegen-web`）
- `src/api/monitor.js`：4 个聚合接口封装，全部走后端 `/monitor/*`（**不直接打 Actuator**）。
- `src/views/monitor/index.vue`：指标卡 + 两张 ECharts（JVM、HTTP 趋势）。
  - ECharts **按需引入 + 异步 chunk**（`webpackChunkName: "echarts"`），不进主包；
  - 加载失败只降级趋势区，指标卡与表格仍可用（`chartError` 兜底）。
  - 定时轮询 `overview`/`series` 刷新（页面内 `setInterval`）。

## 10. 部署与运维

### 10.1 建库与初始化
- 执行 `docs/sql/` 下平台表 DDL（约 13 张平台表），并导入默认账号 `admin/admin123`（BCrypt）。
- 前端默认账号同后端；登录后首屏为系统/表配置。

### 10.2 后端启动
```bash
# JDK 21，profiles 含 local（application-local.yml 覆盖口令/路径）
mvn -o spring-boot:run        # 开发态
java -jar codegen-server.jar  # 打包后（需 -parameters 编译，POM 已固化）
# 端口 8120；health: GET /actuator/health → {"status":"UP"}
```
- **必须 `-parameters`**：否则 Spring MVC 参数名绑定报「Name for argument not specified」500（POM 已固化 `maven-compiler-plugin` 该参数）。
- **肥 jar 自检**：`gen.selfcheck.classpath` 须指向目标工程依赖，否则 javac 解析不到嵌套依赖，满屏 `cannot find symbol`（假报错）。

### 10.3 前端启动
```bash
npm install --legacy-peer-deps
npm run serve        # 默认 9530，dev server
# vue.config.js 中 proxy: /dev-api → http://127.0.0.1:8120
```
- Node 22 需 `NODE_OPTIONS=--openssl-legacy-provider`（Vue CLI 5 + OpenSSL 3 兼容）。

### 10.4 常见排错
| 现象 | 根因 | 处理 |
|---|---|---|
| 登录 500 / 种子未写入 | 目标库 `sys_user` 缺 `password`/`nickname` 约定列 | 脚手架前 `ensureLoginSeedColumns` 自动补列并迁移 `password_hash` |
| 子进程起不来 / 端口等不到 | 残留 `SERVER__PORT` 环境变量高于命令行 | 启动子进程前 `pb.environment().remove("SERVER__PORT")` |
| 打包步 `CreateProcess error=267` | 后端工程目录/pom 不存在（代码没生成或 root 配错） | 先确认 scaffold/gen 步骤成功、台账 `backend_root` 正确 |
| 生成「写盘 0 文件」但流水线仍继续 | 未校验自检结果 | `stepGen` 现校验 `vo.passed`，自检不过直接失败 |
| 监控页图表空白但卡片正常 | ECharts 异步 chunk 加载失败 | 已降级，指标卡/表格可用；检查网络/构建 |

## 11. 前端架构（`codegen-web`）

```
src/
├── api/         # 按域分文件，封装 axios（monitor.js / gen.js / system/*）
├── views/       # login / gen(生成) / monitor(监控) / system(用户角色菜单) / doc / flow / error-page
├── router/      # index.js：/login、/403、/404、主布局 children（按权限动态）
├── store/       # modules：用户、权限、菜单
├── layout/      # 主框架（侧边栏/顶栏，按菜单渲染）
├── directive/   # v-hasPermi 等权限指令（与后端 perms 同源）
├── utils/       # request 封装（拦截 401 弹登录、统一 baseURL /dev-api）
└── styles/      # 主题
```
- 路由分「白名单路由」与「后端菜单动态注入」两类；权限指令 `v-hasPermi` 与后端 `ApiPerms` 生成物同源（`{moduleName}:list/add/edit/remove`）。
- `monitor` 视图为 V6.10 新增，纯消费 `/monitor/*` 聚合接口，不直连 Actuator。
