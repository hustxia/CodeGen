# 代码生成器 V6.8 规划 —— 生成物可维护性：重生成不丢手改，元数据/素材/品牌一次对齐

> 日期：2026-10-28　状态：规划待过目
> 与 V6.1~V6.7 无强耦合，只消费既有模式（三态开关、scaffold-* 资源目录、`resolveXxx` 唯一回落）。
> 定位：把「生成一次就完事」升级为「**可以反复重生成**」——手改资产不丢、关联/尺寸/素材/品牌跟着元数据走，不再靠人肉补。
> 前置关系：本版是商城 V2「交易闭环」的平台侧前置依赖（该规划已列 P0-a 字典脚手架、P0-b DDL 补 deleted，本版一并收口）。

## 二、主题与理由

**为什么是它**：

1. **真实痛感最密**：悦集商城一次完整落地（文件能力 + 后台名称 + 素材 + 品牌）产生 4 类手改、40+ 处文件级修改，全部踩在「重生成会覆盖」的雷上。手改越多，越不敢重生成——与「配表即出」的价值主张反向。
2. **成本最低、收益即时**：本版六项都是模板/资源层改造，不动主链路（不拆单体、不动流水线阶段），回归面靠 V6.7 刚落地的 175 例 + 产物测试骨架兜底。
3. **是商城 V2 的硬前置**：字典脚手架（P0-a）与 DDL `deleted`（P0-b）已写在商城 V2 规划里「真源未修」，不修则商城每次重生成都会把手改的 11 页字典打回原形。
4. **一次对齐，长期复利**：品牌参数化、素材链路、图片尺寸之后，新建任何产物工程都不再需要「改名 + 换图 + 调尺寸」这三件套。

**为什么不是别的**：

- C 端商城生成（V6.9 候选）：价值更大但依赖本版——C 端页面同样要外键名称、图片尺寸、品牌、字典，先修地基再盖楼。
- 拆 `GenScaffoldServiceImpl` 单体：债真实，但纯内部重构，且拆完仍需等价证明；本版新增的「受保护文件清单」正好是拆分的安全网。
- 模板组第二技术栈（Vue3+Vite）：商城仍用 Vue2，收益在未来。

## 三、范围

### P0-1 重生成差异预览与受保护文件清单

- `dryRun` 升级为**文件级影响面报告**：逐文件输出 `新增 / 覆盖 / 跳过（内容一致）/ 受保护跳过`，附行数变化；`/gen/apply` 的 dryRun 分支返回该报告（前端向导新增「预览」页签）。
- **受保护文件清单**：手改过的文件打标记（首次覆盖前自动写 `.gen-protect` 清单，或按路径白名单：`vuePage` 中的 `gen:begin key="vue-methods"` 块外内容视为用户区），`overwrite=true` 时命中受保护 → 默认跳过并报告，需显式 `force` 才覆盖。
- 备份命名沿用 V4.3 的 `.before` 约定，禁止回到秒级时间戳（V4.2 缺陷：同秒备份互相覆盖）。

**验收**：对已手改的产物连续 dryRun 两次，第二次报告「0 新增 0 覆盖，N 跳过」；带 `force=false` 重生成后手改内容逐字节不变（diff 为空）。

### P0-2 DDL 与 BaseEntity 对齐（补 `deleted`）

- 生成/导入 DDL 时，凡实体继承 `BaseEntity`（含逻辑删除）→ 建表语句自动补 `deleted tinyint NOT NULL DEFAULT 0`（幂等：已存在则跳过），并与 `schema-test.sql` 快照同步。
- 顺带校验：`create_time/update_time/create_by/update_by` 同批检查，缺失即在报告里列出。

**验收**：新导入一张含 `id/name` 两列的表，生成 DDL 含 5 个审计列；对已存在的 7 张商城表执行补列脚本，`SELECT COUNT(*) WHERE deleted IS NULL` 为 0。

### P0-3 字典脚手架 + 去前端硬编码 URL

- `scaffold/` 增加 `sys_dict_type` / `sys_dict_data` 建表 SQL（`IF NOT EXISTS`）+ 常用种子（`sys_status`、`sys_yes_no`、`order_status` 等）；产物 `SysDictController`（`GET /system/dict/data/type/{code}`）+ 前端 `@/api/dict` 一并生成。
- `vuePage.ftl:864` 的 `/api/system/dict/...` 改为从模型变量取前缀（`apiBase`/空前缀二选一，按 `gatewayPrefix`），彻底去掉硬编码。
- 字典缺失时前端行为：不报错、按原始值渲染（已有退回逻辑，补测试）。

**验收**：新建产物工程跑起来，字典页有 3 条种子；生成的 11 类页面字典下拉正常回显中文，网络面板 URL 无 `/api` 硬编码（走 `/dev-api` 代理或直连）。

### P0-4 多图字段类型 + 图片尺寸可配

- 新增字段类型 `multiImage`（列名语义：`*_images`/`*_pics`/`*_gallery` 结尾的 JSON 字符串列自动归类；可手工改）。
- 生成 `MultiImageUpload` 组件（复用本轮 mall 已跑通的实现：v-model 为 JSON 数组字符串、空瓦片追加、删除发空串、silent 标志防 watcher 回环、非法 JSON 降级为空）。
- 图片展示尺寸走模型变量：列表 `imageListSize`（默认 80px，列宽联动）、详情 `imageDetailSize`（默认 120px）、行内编辑 72px；不再硬编码 44/64。

**验收**：给 `slider_images` 打 `multiImage` 后生成物能上传 3 张、列表显示缩略图、详情可预览大图；改尺寸配置为 100 后重生成，模板内无残留 `44px`。

### P0-5 素材链路一次生成（占位图 / 白名单 / 代理）

- `scaffold/` 增加 `static/img/placeholder.svg`（产物自带占位图）；`ImageUpload`/`el-image` 统一 `onerror` 兜底。
- 产物 `AuthContextFilter` 白名单固定含 `/img`、`/uploads`、`/shop`（`/shop` 为 V6.9 预留，本版先放行空前缀）。
- 前端 `vue.config.js` 代理清单由脚手架生成：`/dev-api`（剥前缀）+ `/img` `/uploads`（不剥）并注释「漏配 → 整页占位图」。

**验收**：新产物上传一张图 → 前端 `<img>` 直链 200（未登录）；故意删 `/img` 代理 → 走查脚本能报「图片 404」，恢复后通过。

### P0-6 品牌参数化（appName / logo / 主色）

- `sys_project` 增加 `app_name`、`app_logo`、`app_theme_color`（可空，回落工程名 + 内置 logo + `#e1251b`）。
- 注入点：前端 `public/index.html` title、`layout` 品牌区、登录页标题、后端 `pom` description、README、footer；logo 从项目配置读取（有值则复制到 `public/logo.png`）。
- 前端向导「系统编辑」加三个输入框（与三态开关同区），一次填写全站生效。

**验收**：改 `app_name=悦集商城`、`app_logo` 上传一张 → 重生成后标题/侧边栏/登录页三处一致，无需手工 sed。

## 四、明确不做

- **C 端商城工程生成**（PC/H5 前台、`/shop` 公开接口、买家身份）：V6.9 主题，本版只预留白名单与前缀。
- **交易编排**（订单状态机/库存防超卖/优惠券核销）：V7.0，接 V6.3 支付能力包。
- 拆 `GenScaffoldServiceImpl` 单体：本版只加「受保护文件清单」，拆分留待事件驱动（先攒够回归护栏）。
- 图片压缩/缩略图服务：本版只做前端展示尺寸与占位兜底，服务端缩略图另议（V7.0 与 C 端同期）。
- 多语言、暗色主题：非商城当期需求。

## 八、风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 受保护判定过宽 → 用户想要的更新也跳过 | 重生成「看起来没生效」 | 报告显式列出「受保护跳过 N 个」，附 `--force` 单文件覆盖入口 |
| 受保护判定过窄 → 仍覆盖手改 | 回到老问题 | 先用 `gen:begin/gen:end` 块判定（模板已有该标记），块外一律算用户区 |
| 字典种子与业务枚举漂移 | 下拉文案对不上 | 种子只放通用字典；业务枚举由表级 `dict_code` 声明，生成时校验存在性 |
| DDL 补列在存量库执行失败（非空约束/默认值） | 落地卡住 | 生成 ALTER 语句而不是直接执行；`DEFAULT 0` + 可空二选一，按 MySQL 版本给建议（坑库 mysql.md 有 NOT NULL DEFAULT 杀中间层的记录） |
| 品牌 logo 复制覆盖用户自定义图 | 图被换掉 | 仅当 `app_logo` 有值且目标不存在时写入；存在则跳过并报告 |
| 模板改动面大（vuePage 1,550 行） | 基线全红、回归成本高 | 尺寸/多图/ref 全走模型变量与 `<#if>` 分支，先改模型再改模板；基线按场景增量刷新并逐一核对 diff |
