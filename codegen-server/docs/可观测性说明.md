# 平台可观测性说明（V6.10）

> 适用版本：代码生成器 V6.10（平台可观测性）
> 配套文档：`代码生成器-V6.10-规划.md` / `design/V6.10平台可观测性-设计.md` / `requirements/V6.10平台可观测性-需求.md`
> 菜单 SQL：`sql/V6.10__monitor_menu.sql`

## 一、它解决什么问题

此前平台只有 logback 文件日志 + `sys_oper_log` 操作审计（业务级），**没有任何性能 / 运行时可见性**。出现「生成变慢」「某个接口偶发 5xx」「流水线跑得久」这类问题时，只能翻日志、靠猜。

V6.10 补上三层可见性：

1. **JVM / 进程基础指标**：堆内存、线程、GC、CPU、启动时长
2. **HTTP 指标**：区间请求数、QPS、平均 / P95 / P99 耗时、4xx / 5xx、慢接口排行
3. **业务指标**：生成批次成功率、写盘文件数、流水线状态分布、文档（LibreOffice）转换耗时

## 二、架构与数据流向

```
Micrometer MeterRegistry  ──采集──>  MonitorSampler（@Scheduled 5s）
        ▲                              │ 累计值 → 区间差分
        │ Actuator 暴露 /actuator/health                            
   JVM/HTTP/业务埋点                    ▼
                              MonitorStore（内存环形缓冲，360 点 = 30 分钟）
                                              │
                                   MonitorController /monitor/*
                                              │ 聚合 + 权限校验
                                      前端「系统监控」页（Vue + ECharts）
```

- **采集**：Spring Boot Actuator + Micrometer（Boot 3.2.5 自带 Micrometer 1.12，无需单独引包）。
- **存储**：纯内存环形缓冲，5 秒一采、保留 360 点 = **30 分钟**。满了淘汰最旧，不扩容。
- **面板**：平台内嵌「系统监控」页，数据走后端 `/monitor/*` 聚合接口，**前端不直接访问 `/actuator`**——字段与权限都可控。

## 三、指标含义

### JVM / 进程

| 指标 | 说明 |
|---|---|
| 堆已用 / 上限 | `jvm.memory.used/max`（area=heap），单位为 MB |
| 堆使用率 | 已用 / 上限，0~1 |
| 非堆已用 | 元空间等（area=nonheap） |
| 活跃线程 | `jvm.threads.live` |
| GC 次数 / 暂停 | `jvm.gc.pause` 累计 count / totalTime |
| CPU 使用率 | `process.cpu.usage`，0~1 |
| 可用核数 | `system.cpu.count` |
| 启动时长 | `process.uptime`，秒 |

### HTTP（区间差分，非累计）

| 指标 | 说明 |
|---|---|
| 区间请求数 | 本采样周期内的请求总量 |
| QPS | 请求数 / 采样周期（秒） |
| 平均耗时 | 区间内总耗时 / 请求数 |
| P95 / P99 | 基于直方图桶的线性插值（近似值，非精确计费口径） |
| 4xx / 5xx | 按状态码前缀统计的区间错误数 |
| 慢接口 TopN | `方法 URI` → 次数 / 平均 / 最大耗时，按平均耗时降序 |

> URI 是 Micrometer 模板（如 `/gen/table/{id}`），不会因裸 id 爆炸基数。

### 业务（埋点位置）

| 指标 | 埋点位置 |
|---|---|
| 生成批次次数 / 成功率 / 平均耗时 | `GenCodeServiceImpl#writeToDisk`（timer + 文件数 counter） |
| 预览耗时 | `GenCodeServiceImpl#preview` |
| 流水线步骤耗时 + 运行结果分布 | `PipelineExecutor` 步骤收尾 / `GenPipelineServiceImpl` |
| 文档转换（命中 / 转换 / 失败） | `DocPreviewEngine#convertToPdf` |

埋点失败不影响主流程：所有 `MeterRegistry` 调用包在 try/catch，异常只记 debug 日志。

## 四、采样窗口的限制（重要，先看这段）

- **仅进程内 30 分钟**：重启后历史清零，多实例不共享——这是设计取舍（零外部依赖、零新表），**重启后曲线归零不是故障**。
- **监控页只看当前实例**：多实例部署时各实例独立采样，页面反映的是你连到的那一台。
- **直方图只对 `http.server.requests` 开启**：其余指标按累计值做区间差分（本轮 − 上轮），因此「曲线上的点」与「窗口聚合」是同一口径，不会出现「累计值混进 30 分钟窗口」。
- 采样任务体内全包 try/catch 并 `log.warn`：单轮失败不会让定时任务停摆，但面板会显示「采样停滞」提示。

## 五、探活端点

- `GET /actuator/health` **免 token**，返回 `{"status":"UP"}`。
- `management.endpoint.health.show-details: never`：**不对外吐数据库地址 / JVM 细节**。
- 数据库健康灯由 Boot 自带 `DataSourceHealthIndicator` 提供，无需自写。
- 其余端点：`/actuator/metrics` 等**必须带 token**；`env / beans / heapdump / threaddump / loggers` **永不暴露**（配置枚举式放行，见 `application.yml` 的 `management.endpoints.web.exposure.include: health,info,metrics`）。

## 六、权限

- 菜单 `/monitor` 权限码 `monitor:view`；后端 `/monitor/*` 统一校验该码，**超管直通**。
- 菜单录入 SQL：`docs/sql/V6.10__monitor_menu.sql`（`id=3030`，前端走 `require.context` 动态路由，无需改 `router/index.js`）。

## 七、排障常用 curl

```bash
# 1) 探活（免 token）
curl -i http://localhost:8080/actuator/health

# 2) 实时概览（需 token；字段含 lastSampleAt，可判断是否在采样）
curl -H "Authorization: Bearer <TOKEN>" http://localhost:8080/monitor/overview

# 3) 趋势序列（metric 仅限白名单：jvm.heap / jvm.threads / process.cpu / http.qps / http.p95）
curl -H "Authorization: Bearer <TOKEN>" "http://localhost:8080/monitor/series?metric=jvm.heap&minutes=30"

# 4) HTTP 聚合 + 慢接口 Top10
curl -H "Authorization: Bearer <TOKEN>" "http://localhost:8080/monitor/http?minutes=30&topN=10"

# 5) 业务指标
curl -H "Authorization: Bearer <TOKEN>" "http://localhost:8080/monitor/business?minutes=30"

# 6) 原始指标（需 token；不要用它做面板数据源）
curl -H "Authorization: Bearer <TOKEN>" http://localhost:8080/actuator/metrics
```

## 八、常见问题

| 现象 | 原因 / 处置 |
|---|---|
| 面板顶部红色「采样停滞」 | 后端调度线程异常；查日志里 `指标采样失败` 的 WARN，定位 `MonitorSampler` |
| 图表区空白但指标卡有值 | ECharts 异步加载失败，已降级；指标卡与慢接口表仍可用 |
| P95 / P99 恒为 0 | 确认 `management.metrics.distribution.percentiles-histogram.[http.server.requests]=true` 已开 |
| 重启后曲线归零 | 正常，内存窗口不持久化（见第四节） |
| `/monitor/*` 返回 403 | 当前账号无 `monitor:view` 权限（超管除外） |
| `/monitor/series?metric=xxx` 返回 400 | metric 不在白名单，属预期（防止把参数透传给 MeterRegistry） |

## 九、不在本版范围（留 V6.11+）

Prometheus 拉取 / Grafana 面板 / 外部时序库、阈值告警（站内通知 / 邮件）、历史留存与跨实例聚合、前端 Web Vitals、链路追踪（Tracing）。
