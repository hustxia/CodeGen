## 一、现状核对（全部为实测，非推测）

### 1.1 子表支持：模型允许多子，引擎只取一张（本版核心缺口）

| 事实 | 证据位置 |
|---|---|
| 数据模型天然支持一主多子：子表通过 `gen_table.master_table_id` + `master_foreign_key` 挂到主表，多张子表可指向同一主表 | `GenTable.java` 179 行 `masterTableId` |
| 渲染引擎**只取一张**：`loadChild` 查询带 `LIMIT 1`（按 id 升序取第一张），其余子表静默忽略 | `GenTemplateEngine.java` 140~160 行 |
| 模型层注释自认：「本表作为主表：子表信息（当前支持单子表）」 | `GenTemplateModel.java` 320 行 |
| 详情接口一主一子（含孙表三级递归） | `controller.ftl` 201~225 行 `/with-children` |
| 前端详情是 420px 只读抽屉，仅主表字段；编辑弹窗单子表表格 | `vuePage.ftl` 306~338 行 |

### 1.2 级联写：新增已有，删除缺失

| 能力 | 现状 | 证据位置 |
|---|---|---|
| 级联新增/更新 | **已有**：`saveWithChildren` 同事务全量替换 + 三级递归（但只针对那"一张"子表） | `serviceImpl.ftl` 74~140 行 |
| 级联删除 | **没有**：`removeById(id)` 只删主行，子行 `deleted=0` 残留 | `controller.ftl` 523~527 行 |

### 1.3 模板组织：三形态合一，`<#if>` 已成负担

- `serviceImpl.ftl` 133 行：单表/树形/主子三合一；`vuePage.ftl` 1,339 行同样多形态合一
- 模板总计 12 个 / 2,545 行（10-23 `wc -l` 实测）

- **36 份产物基线**（3 场景 × 12 模板）：分道与多子化重构的护栏；多子化会让 master-detail 基线**预期内变化**，须显式更新并写明

## 二、主题与目标

**主题：一主多子 + 级联写完整化 + 模板分道**

一句话：让"有关联的表"支持任意多张子表、详情多 tab 一览全部明细、删得干净；单表保持最简。

- 级联删除默认**级联模式**（删主行同事务逻辑删除**全部**子表行）——按 2026-10-23 用户决定；另提供**阻止模式**表级可配
- 详情形态升级为**多 tab**：每个 tab 一张明细表（只读详情场景先行）

## 三、任务清单

### P0-1 模板分道（规模 L，纯重构零行为变化）

`serviceImpl.ftl` 拆为 `serviceImpl-simple` / `serviceImpl-tree` / `serviceImpl-masterdetail`；渲染入口按形态派发，选择结果记入产物 readme。

**验收**：三场景 36 份基线全绿。硬门禁——分道不许夹带行为变化。

### P0-2 子表模型多子化（规模 L，产物预期变化）

引擎与模型层把单子表改为一主多子：

- `GenTemplateEngine.loadChild` 去掉 `LIMIT 1`，改为 `loadChildren` 返回 `List<ChildInfo>`（每张仍可递归挂孙表）
- `GenTemplateModel.build` 的 `child.*` 键改为 `children[]`；`hasChild` 保留为便捷布尔，另给 `childCount`
- 依赖 `child.*` 的模板（serviceImpl / controller / saveDto / vuePage / apiJs 涉及处）同步改为 `<#list children as child>` 循环化
- **基线场景扩展**：新增第 4 个场景 `master-multichild`（一主两子，其一含孙表），基线从 36 份增至 **48 份**；master-detail 场景产物随循环化重写更新

**验收**：`master-multichild` 场景生成的 controller/service 能对两张子表各自 CRUD；`/with-children` 返回全部子表明细。

### P0-3 级联删除双模式（规模 M，直接按多子表设计）

**表结构**（迁移 SQL V4.4）：

```sql
ALTER TABLE gen_table
  ADD COLUMN delete_cascade_mode TINYINT NOT NULL DEFAULT 1
  COMMENT '删除级联模式：0=阻止(有子行拒删) 1=级联(同删全部子表) 2=不处理(现状)';
ALTER TABLE sys_project
  ADD COLUMN default_delete_cascade_mode TINYINT NULL COMMENT '系统级默认，空=1';
```

- 独立回落（表级 → 系统 → 硬编码 1），**不进 17 开关体系**
- 生成侧（masterdetail 模板）：`mode=1` 生成 `deleteWithChildren(id)`——同事务逻辑删除主行 + **逐张子表**按外键逻辑删除（含孙层），返回每张子表删除行数；`mode=0` 任一子表存在有效行即拒绝，提示各子表明细数；`mode=2` 维持现状
- 批量删除走同一 service 方法

### P0-4 详情多 tab（规模 M，前端为主）

- `vuePage.ftl`（masterdetail 分道）详情从 420px 只读抽屉升级为**宽抽屉 + `el-tabs`**：tab 1 = 主表字段键值，tab 2..N = 每张子表一个只读明细表（列取子表 `isList` 列）
- 数据源复用 `/with-children` 多子返回，前端不发额外请求；明细行数超阈值时 tab 内懒加载分页（apiJs 加轻量按子表查明细接口）
- **编辑弹窗仍保持单子表逐个编辑（本版不做多子同时编辑）**——多子编辑涉及行内校验与脏数据管理，放 P2 评估；详情各 tab 提供"去编辑"入口

### P0-5 契约测试补不变式（规模 S）

`GenPipelineContractTest` 新增 5 例：

1. `cascadeDeleteMarksAllChildrenDeleted`：多子表 mode=1 删主单，**每张**子表行 `deleted=1`
2. `cascadeDeleteReachesGrandChild`：三级场景孙行同样 `deleted=1`
3. `blockDeleteRefusesWithActiveChildren`：mode=0 有有效子行拒绝，提示含各子表行数
4. `mode2KeepsLegacyBehavior`：mode=2 锁定现状
5. `detailWithChildrenReturnsAllChildren`：`/with-children` 返回全部子表（多子化回归）

## 八、风险与应对

| 风险 | 应对 |
|---|---|
| 多子化改动面大（模型键 `child.*` → `children[]` 波及多个模板） | 拆两次提交：先 P0-1 分道（零变化），再 P0-2 多子化（基线显式更新）；每步基线跑绿才进下一步 |
| 三级 + 多子组合（多张子表各自有孙表）遗漏 | 基线场景 master-multichild 明确含一张带孙表的子表；契约用例 2 覆盖 |
| 详情 tabs 数据量大（一张明细上万行） | tab 内分页 + 阈值懒加载；默认先全量 |
| 默认级联是行为翻转 | mode=2 逃生门；配置页高亮提示；发布说明 |
| 全量替换被误当缺陷 | P1-1 增量保存兜住；文档写清取舍 |
