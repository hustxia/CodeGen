## 一、定位与边界

V9.4 是现有一句话建系统流水线的**可确认性增强**，不是新平台、新生成器或新部署器。

| 做 | 不做 |
|---|---|
| AI 功能清单可见、可编辑、可勾选 | 不做多轮需求对话和 PRD 生成 |
| 清单驱动现有 AI 表建模 | 不替换现有代码生成模板体系 |
| 服务端完整 SQL 只读预览 | 不允许预览接口写任何数据库 |
| SQL 确认后建表，构建再次确认 | 不做无人值守全自动执行 |
| 复用现有部署、健康检查、失败重试 | 不做远程或容器部署 |

### 现状复用点

| 能力 | 现有位置 | V9.4 用法 |
|---|---|---|
| AI 模块拆分 | `AiModelServiceImpl.modules` / `GenPipelineAiModulesVO` | 响应增加功能点数组 |
| AI 表建模 | `AiModelServiceImpl.aiModel` | 按勾选模块调用，现有模型不变 |
| DDL 组装 | `GenPipelineServiceImpl.buildDdl` | 预览与执行唯一出口 |
| DDL 预检执行 | `GenDdlServiceImpl.execute` | 继续负责 dry-run、危险语句和库名校验 |
| 任务与系统台账 | `GenPipelineServiceImpl.create/ensureProject` | 仅在 SQL 确认后创建 |
| 建库建表 | `GenPipelineServiceImpl.prepareDb` | 复用，不另建执行链 |
| 构建部署 | `GenPipelineServiceImpl.run` + `PipelineExecutor` | 仅在构建确认后触发 |
| 向导页面 | `codegen-web/src/views/gen/pipeline/index.vue` | 调整四步交互，复用表格编辑与步骤进度 |

## 二、表结构（S2）

### 平台数据库

**无新增表、无新增列、无菜单 SQL。**

功能清单、候选表和 SQL 预览在确认建表前均为前端暂存数据；DDL 预览是无状态计算，不落平台库或业务库。确认建表后继续写入现有 `gen_pipeline`、`sys_project`、`gen_table`、`gen_table_column`。

### 业务数据库

只在用户点击“确认 SQL 并建库建表”后，由现有 `prepareDb` 创建目标库和业务表。业务表继续包含：

- `id` 主键；
- `create_time` / `update_time`；
- `create_by` / `update_by`；
- `deleted` 逻辑删除列。

本阶段不需要新增或执行平台 DDL 脚本。

## 三、核心模型

### 3.1 FeatureModule（AI 暂存模型）

```json
{
  "name": "资产档案",
  "desc": "统一维护设备分类、资产台账与生命周期状态",
  "functions": ["设备分类管理", "资产档案管理", "资产条码管理", "资产状态变更"],
  "checked": true
}
```

- `name/desc/functions` 由 AI 返回；`checked` 为前端交互字段，不下发给 AI。
- 旧模型响应缺少 `functions` 时按 `[]` 处理。
- 空名称模块、空功能点可在前端编辑；未勾选模块不参与表建模。

### 3.2 DDL 预览请求

```json
{
  "dbName": "asset_demo",
  "tables": [
    {
      "tableName": "asset_info",
      "tableComment": "资产档案",
      "columns": [
        {"name": "asset_name", "type": "varchar(128)", "comment": "资产名称", "nullable": true}
      ]
    }
  ]
}
```

### 3.3 DDL 预览响应

```json
{
  "dbName": "asset_demo",
  "ddl": "CREATE DATABASE IF NOT EXISTS `asset_demo` DEFAULT CHARACTER SET utf8mb4;\nCREATE TABLE IF NOT EXISTS ...",
  "tableCount": 1,
  "statementCount": 2
}
```

`statementCount` 按服务端 DDL 组装结果计算：1 条建库语句 + N 条建表语句，不通过简单截取字符串猜测。

## 四、流程与状态

### 4.1 向导步骤

| 前端 step | 页面 | 主按钮 | 副作用 |
|---|---|---|---|
| 0 | 录入需求 | 生成功能清单 | 仅 AI 只读调用 |
| 1 | 确认功能清单 | 确认清单，生成表结构和 SQL | 仅 AI 调用和服务端 SQL 计算 |
| 2 | 表结构与 SQL | 确认 SQL 并建库建表 | 创建任务/台账，执行 DDL，导入表配置 |
| 3 | 建表与构建 | 开始构建并启动 | 执行现有构建流水线 |

手动 DDL 在第 0 步切换后沿用现有手动流程，不强制生成 AI 功能清单。

### 4.2 流水线状态

```text
未创建任务
  │ 确认 SQL
  ▼
draft
  │ prepare-db 成功
  ▼
await_confirm
  │ 用户点击“开始构建并启动”
  ▼
running ──► success
  │
  └──────► failed ──► 用户重试 ──► running
```

任何 AI 或 SQL 预览失败都发生在任务创建前，不产生 `draft/failed` 假任务。

## 五、后端设计（S6）

### 5.1 AI 功能清单扩展

修改：

- `GenPipelineAiModulesVO.Module`：增加 `List<String> functions`。
- `AiModelServiceImpl.MODULE_PROMPT`：要求每模块返回 3~6 条简洁、可命名的业务功能点，仍只输出 JSON。
- `AiModelServiceImpl.modules` 解析：读取 `functions` 字符串数组，过滤空白；字段缺失或类型不符时按空数组兼容，不让新增字段破坏旧模型响应。

接口保持不变：

| 接口 | 方法 | 路径 | 请求体 | 响应变化 |
|---|---|---|---|---|
| AI 功能清单 | POST | `/gen/pipeline/ai-modules` | `{systemName,systemDesc}` | `modules[]` 增加 `functions:string[]` |

### 5.2 SQL 预览接口

新增：

| 接口 | 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|---|
| AI 模式 SQL 预览 | POST | `/gen/pipeline/ddl-preview` | `{dbName,tables}` | `{dbName,ddl,tableCount,statementCount}` |

新增 DTO/VO：

- `GenPipelineDdlPreviewDTO`：`dbName` 必填并复用 `[a-z0-9_]{1,64}` 规则，`tables` 非空。
- `GenPipelineDdlPreviewVO`：`dbName/ddl/tableCount/statementCount`。

`GenPipelineService` 增加 `previewDdl`：

1. 校验数据库名和候选表非空。
2. 调用与 `prepareDb` 完全相同的 `buildDdl(dbName,tables)`。
3. 返回 SQL 和统计值。
4. 不调用 `JdbcTemplate`、`GenDdlService`、`create`、`ensureProject`、`prepareDb`。

`buildDdl` 继续统一完成 `fixColumns`、主键/审计列补齐、表注释和建库语句拼接；禁止前端自行拼接另一份执行 SQL。

### 5.3 建表与构建

- 建表继续复用 `POST /gen/pipeline/{id}/prepare-db`，其 AI 分支不得改变现有 `buildDdl` 行为。
- 构建继续复用 `POST /gen/pipeline/{id}/run`，状态必须为 `await_confirm`。
- 不新增自动触发器、定时任务或后台监听；两个动作都由用户按钮显式发起。

## 六、前端设计（S7）

### 6.1 页面结构

1. **录入需求**：系统名、描述、数据库名、目标模块；移除快速/完整选择，增加“生成后仅预览，不会建表”的提示。
2. **功能清单**：模块卡片、勾选、名称/说明/功能点编辑、新增/删除、全选、生成进度和失败模块。
3. **表结构与 SQL**：
   - “表结构”页签复用现有可编辑表格；
   - “SQL 脚本”页签展示只读 SQL、表数、语句数、复制按钮；
   - 表结构变化后将预览标记为过期，强制刷新；
   - 底部确认弹窗再次展示目标库和表数。
4. **建表与构建**：展示目标库、成功表数、导入配置数、失败原因；构建步骤保持待运行，提供独立“开始构建并启动”。

### 6.2 关键暂存状态

| 状态 | 用途 |
|---|---|
| `featureModules` | 功能清单及勾选状态 |
| `featureLoading` | 防止重复生成清单 |
| `moduleProgress/moduleErrors` | 逐模块建模进度与失败提示 |
| `sqlPreview` | 服务端返回的只读 SQL 与统计 |
| `sqlStale` | 表结构变化后使旧预览失效 |
| `activeSchemaTab` | 表结构 / SQL 脚本页签 |

### 6.3 前端 API

在 `codegen-web/src/api/pipeline.js` 增加 `previewPipelineDdl(data)`；现有 `aiPipelineModules/aiPipelineModel/createPipeline/preparePipelineDb/runPipeline` 继续复用。

## 七、安全与异常

| 风险 | 设计约束 |
|---|---|
| AI 输出未经确认直接写库 | AI 和预览接口保持无状态、无数据库连接；只有 prepare-db 有副作用 |
| 预览 SQL 与执行 SQL 不一致 | 两个入口共用 `buildDdl`，增加同源测试 |
| 错库执行 | 沿用 `GenDdlServiceImpl` 的库名校验、USE 语句注入和 dry-run |
| 危险 SQL | 沿用现有 DROP/TRUNCATE/ALTER DROP/无条件 DELETE 拒绝 |
| 重复提交 | 按钮 loading + 现有单流水线 running 锁 |
| AI 局部失败 | 显示失败模块，不隐藏、不伪造成功；用户决定是否继续 |
| 暂存丢失 | 确认建表前提示刷新会丢失；确认后由现有任务持久化接管 |

## 八、测试与验收（S8 待回填）

### 后端

- AI 模块 JSON：含功能点、缺少功能点、空功能点、异常 JSON。
- SQL 预览：建库语句、表数量、语句数量、审计列、非法库名、空表集合。
- SQL 同源：同一输入下预览结果与 `buildDdl` 输出逐字一致；`prepareDb` 继续走同一出口。
- 零副作用：预览测试不依赖或不调用数据库、任务创建和系统台账。
- 回归：既有 `PipelineContractTest` 及相关生成器测试。

- AI 功能清单生成期间业务库表数不变。
- SQL 预览前后 `gen_pipeline` / `sys_project` 无新增记录。
- SQL 确认后才出现任务、台账和真实建表结果。
- `await_confirm` 停留时构建步骤均为 `wait`。
- 四阶段浏览器走查，console/pageErrors/failedRequests 为 0，截图回填此处。
