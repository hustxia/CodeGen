# V9.2 测试中心 —— 设计文档

> **V9.2 由两个子模块组成**：本文档描述「用例中心 `/test/*`（test_* 七表）」；其姊妹模块「验证中心 `/tc/*`（tc_* 三表，平台自身验证套件 S1–S9）」见 [`V9.2验证中心-设计.md`](./V9.2验证中心-设计.md)。
> 日期：2026-11-13　形态：CodeGen 控制台内嵌模块（非独立平台）
> 前置：`docs/design/V6.7产物测试出厂-设计.md`（产物侧测试骨架）；上一版本「测试工厂」（生成侧三类测试产物，尚未落地）
> 范围：接口自动化 + UI 自动化；不含性能压测、不含移动端

---

## 一、定位与边界

一句话：把「生成出来的测试产物」变成「可管理、可编排、可回归的测试资产」。

| 做 | 不做 |
|---|---|
| 用例 / 套件 / 环境的增删改查 | 不做脚本 IDE，不写代码，只配用例 |
| 接口执行 + JSONPath / JSON Schema 断言 | 不做性能压测 |
| UI 执行（Playwright 托管） | 不做 App / 小程序 |
| 定时回归、CI 触发、失败重试、报告导出 | 不做用例录制器（后续版本再议） |
| 通过率趋势、失败归因 | 不做缺陷跟踪，不替代 Jira |

**为什么内嵌**：菜单、权限、多系统台账（`sys_project`）、JWT、操作日志、模板体系全部复用，新增的只有用例库与两个执行器。独立平台要重造这五套基础设施。

## 三、功能设计

| 编号 | 功能点 | 位置 | 关键实现 | 验收标准 |
|---|---|---|---|---|
| F-01 | 环境管理 | `TestEnvController` + `TestEnvServiceImpl` | CRUD + `POST /test/env/{id}/verify` 探活（GET base_url，3s 超时） | 探活结果三态：通 / 401 / 超时 |
| F-02 | 套件管理 | `TestSuiteController` | CRUD + 按 `project_id` 过滤；`table_id` 反查 `gen_table` 取表注释做默认名 | 同系统下套件名唯一 |
| F-03 | 用例 CRUD | `TestCaseController` | 保存时校验 `asserts_json` 可解析；`path` 必须以 `/` 开头 | 非法断言 JSON 直接 400 并回显行号 |
| F-04 | 用例试运行 | `POST /test/case/{id}/try` | 内存执行，不落 `test_run`；返回断言逐条结果 | 试运行不产生执行记录，不触发清理 SQL |
| F-05 | cURL 解析导入 | `POST /test/case/parse-curl` | 解析 `-X` / `-H` / `-d` / URL，生成 method/path/headers/body 草稿 | 覆盖 Chrome「Copy as cURL (bash)」格式 |
| F-06 | 套件批量生成 | `POST /test/suite/generate?tableId=` | 按 `gen_table` + `gen_table_column` 推导冒烟用例（见第四节） | 单表产出 ≥6 条用例，全部可执行 |
| F-07 | 断言引擎 | `TestAssertEngine`（support 包，纯函数） | 支持 `status` / `jsonpath` / `schema` / `duration` / `header` 五类，`op` 支持 eq/ne/contains/regex/gt/lt/exists | 纯函数可单测，不依赖 Spring |
| F-08 | 变量与传参 | `TestVarContext` | `${env.x}` / `${case.x}` / `${var.x}` 三级作用域；`extract_json` 写入本批次上下文 | 用例链（新增→详情→删除）可跑通 |
| F-09 | 执行编排 | `TestRunService` | 按 `order_no` 串行、按套件并行；单用例超时（默认 10s）中断并记 fail | 并发上限可配，超限排队不丢弃 |
| F-10 | 接口执行器 | `ApiTestExecutor` | JDK `HttpClient`，不引第三方；连接超时 3s / 读超时 10s | 不依赖目标工程任何依赖 |
| F-11 | UI 执行器 | `UiTestExecutor` + `playwright-runner` sidecar | HTTP 提交 `{spec, env, vars}`，回传 `{status, screenshot, trace, error}`；sidecar 不可用时降级为「UI 执行不可用」 | 主应用不因 sidecar 挂掉而不可用 |
| F-12 | 生产环境只读 | `TestGuard` | `env.is_prod=1` 时非 GET 用例直接判 skip 并记原因，不弹窗确认 | 生产环境跑写用例：0 请求发出 |
| F-13 | 结果落库与报告 | `TestRunService` | 批次汇总 + 用例明细；`GET /test/run/{id}/report.xml` 导出 JUnit XML | Jenkins / GitLab 可直接消费 |
| F-14 | 定时回归 | `TestScheduleJob`（Spring `@Scheduled`，30s 扫描） | 多实例下用 `sys_project` 行锁避免重复触发 | 同一 cron 分钟只触发一次 |
| F-15 | 生成器联动 | `TestSuiteGenService` | 生成批次中 `test-api` / `test-e2e` 产物自动注册套件；指纹比对决定覆盖/待合并 | 重新生成不覆盖手工改过的用例 |
| F-16 | 权限与菜单 | `sys_menu` + `sys_role_menu` 种子 | 权限码：`test:env:*` / `test:suite:*` / `test:case:*` / `test:run:*` / `test:schedule:*` | 无权限菜单不渲染、接口 403 |

## 四、用例模型：生成 / 手工 / 合并

### 4.1 用例 JSON

用例不是代码，是声明式 JSON，生成器、手工编辑、CI 三方共用同一格式：

```json
{
  "name": "新增订单 · 必填校验",
  "method": "POST",
  "path": "/order/save",
  "headers": { "Authorization": "Bearer ${case.login.token}" },
  "body": { "customerId": "${var.customerId}", "amount": 100 },
  "extract": { "orderId": "$.data.id" },
  "asserts": [
    { "type": "status",   "expect": 200 },
    { "type": "jsonpath", "path": "$.code", "op": "eq", "expect": 200 },
    { "type": "jsonpath", "path": "$.data.amount", "op": "eq", "expect": 100 },
    { "type": "schema",   "ref": "order_vo.json" },
    { "type": "duration", "op": "lt", "expect": 800 }
  ],
  "cleanupSql": "DELETE FROM biz_order WHERE id = ${var.orderId}"
}
```

三条硬规则：
1. `asserts` 必须是数组 —— 失败时能精确定位到第几条断言，而不是笼统「断言失败」。
2. `extract` 必须有 —— 用例间传参（登录拿 token、新增拿 id），是真实业务链路的必需品。
3. `cleanupSql` 必须配 —— 否则测试数据污染环境，且生产环境强制不执行。

### 4.2 自动生成什么

| 用例要素 | 推导来源 |
|---|---|
| method + path | `controller.ftl` 的开关组合（`genPageApi` / `genAddApi` / …） |
| 请求体字段集 | `gen_table_column` 中 `is_form=1` 的列 + 类型默认值 |
| 必填校验用例 | `is_required=1` 的列，逐字段置空，断言业务码 ≠ 200 |
| 唯一键冲突用例 | `is_unique=1` 的列，连插两条同值 |
| 长度越界用例 | `length` 列，超长字符串 |
| 字典合法/非法用例 | `dict_type` 列，取字典项与非法值各一条 |
| 基础断言 | 生成 VO 的结构：`$.code`、`$.data.records` 为数组 |
| 用例链 | page → add → detail → edit → delete 顺序 |
| 清理语句 | 表名 + 主键列 |

**冒烟层基本可全自动**：单表 6~8 条。这部分占日常回归价值的大头，零人工成本。

### 4.3 必须人工填写的

| 类型 | 原因 |
|---|---|
| 业务语义断言 | 金额计算、状态流转、库存扣减只有业务知道 |
| 跨表链路 | 下单 → 扣库存 → 生成流水，涉及时序 |
| 数据权限场景 | 哪个角色能看哪些数据，属配置而非结构 |
| 异常分支 | 第三方超时、重复提交、并发冲突 |
| UI 关键路径 | 哪些流程最值得自动化，是产品判断 |

一个模块通常 2~5 条。

### 4.4 来源与合并规则

```
source      = generated | manual
fingerprint = 生成时用例内容的哈希
```

| 状态 | 判定条件 | 重新生成时的行为 |
|---|---|---|
| 纯生成 | `source=generated` 且指纹未变 | 直接覆盖 |
| 生成后已改 | `source=generated` 但指纹变化 | **不覆盖**，提示「待合并」，提供差异对比 |
| 纯手工 | `source=manual` | 完全不触碰 |

UI 上分别显示为「生成」「待合并」「手工」三种胶囊。

### 4.5 三个录入入口

1. **自动生成**（主路径）：生成业务代码时顺带出套件，`testMode=全量` 默认开启。
2. **手工新建**（补业务）：表单化填写，可随时「试运行」验证。
3. **粘贴 cURL 导入**（提效）：解析为 method/path/headers/body 草稿。

## 六、执行引擎

| | 接口执行器 | UI 执行器 |
|---|---|---|
| 实现 | Java 内建，JDK `HttpClient` + 自研断言引擎 | Playwright sidecar（Node 进程） |
| 原因 | 零第三方依赖，可直接打任意环境 | Playwright 只有 Node 版，Java 无法内嵌 |
| 交互 | 同进程调用 | HTTP 提交任务，回传截图 / trace / 错误 |
| 并发 | 套件并行 + 用例串行（保 `order_no`） | 浏览器实例池，按上限排队 |
| 失败产物 | 请求 / 响应全文 + 耗时 | 截图 + trace + 控制台日志 |

**sidecar 不是微服务**：随 CodeGen 启停，单端口，健康检查失败时仅降级 UI 执行，不影响主应用。

## 七、UI 设计

不新增顶级导航层级之外的复杂结构，菜单挂「测试中心」，下设 5 页。

| 页面 | 结构要点 |
|---|---|
| 测试总览 | 今日通过率、失败 TOP5、7 日趋势、环境健康度 |
| 用例库 | 左套件树（200px，按模块分组）+ 右用例表（用例 / 来源 / 断言数 / 状态）；顶部环境选择 + 「运行选中」 |
| 用例编辑 | 左表单（方法 / 路径 / 请求头 / 请求体 / 断言表格）+ 右「试运行」面板（状态码、耗时、逐条断言结果、失败高亮） |
| 执行结果 | 批次汇总（通过 / 失败 / 跳过 / 耗时）+ 用例结果列表；失败行内联展开：断言差异 + 响应快照 + 截图 |
| 环境与调度 | 环境卡片（生产标红、只读提示）、cron 可视化选择、CI 令牌 |

**必须处理的状态**：

| 状态 | 表现 |
|---|---|
| 未配置环境 | 顶部黄条「未配置 test 环境，去配置」，「运行」按钮置灰 |
| 生成器重新生成 | 用例行显示「待合并」胶囊，点开差异对比后合并 |
| 执行中 | 批次行显示 `18 / 37` 进度 + 可中断，不阻塞其他页面 |
| cURL 解析失败 | 表单侧显示解析失败原因，保留用户已填内容不清空 |

组件只用 `el-tree` / `el-table` / `el-form` / `el-collapse` / `el-tag` / `el-dialog`，颜色沿用主题的 `success / warning / danger`，不新造语义色。

## 八、安全

| 项 | 措施 |
|---|---|
| 生产环境 | `is_prod=1` 硬拦截非 GET 用例（判 skip 并记原因），不是弹窗确认 |
| 密钥 | `test_env.secret_ref` 存引用（环境变量名 / 配置键），接口返回脱敏 |
| 权限 | 五组权限码接入现有 `sys_menu` / `sys_role_menu` |
| 审计 | 复用 `LogAspect`，记录操作人、环境、套件 |
| 限流 | 单用户同时仅 1 个 `running` 批次；sidecar 并发有硬上限 |
| 数据隔离 | 测试库与业务库分离，`CG_DB_*` 环境变量控制；`TestDatabaseGuardPostProcessor` 同款守卫 |

SET deleted=1 WHERE id=? AND deleted=0`。回归测试 `remove_usesDeleteByIdForLogicDelete` 锁定此行为。

## 十、风险

| 风险 | 级别 | 对策 |
|---|---|---|
| UI 用例脆弱（选择器漂移） | 高 | 只做关键路径；复用测试工厂版本的 `data-test` 约定 |

| 断言引擎能力不足导致误报 | 中 | 断言引擎为纯函数，先单测覆盖 5 类断言 × 6 种 op |
| 测试工厂未落地导致 T3 空转 | 中 | T3 前先落测试工厂产物，或 T3 降级为「按表结构推导」不依赖产物 |
