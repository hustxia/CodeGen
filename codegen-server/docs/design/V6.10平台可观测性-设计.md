### 3.2 application.yml 新增

```yaml
spring:
  task:
    scheduling:
      pool:
        size: 2            # 默认单线程；后续再加定时任务会互相阻塞

management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics      # 枚举放行，绝不用 *
  endpoint:
    health:
      show-details: never                 # 不吐 DB 地址 / 连接串
  metrics:
    tags:
      application: codegen-server
    web:
      server:
        max-uri-tags: 100                 # 防 URI tag 基数爆炸
    distribution:
      percentiles-histogram:
        "[http.server.requests]": true    # 带点的 key 必须加方括号，否则 yml 层级被拆开

monitor:
  sample:
    interval-ms: 5000                     # 采样周期
    buffer-size: 360                      # 30 分钟 × 12 点/分钟
```

> `percentiles-histogram` 是算 P95/P99 的前提；同时保留桶，后续接 Prometheus 不用改配置。

## 五、采样器与环形缓冲

### 5.1 类职责

```
config/MonitorConfig.java          @Configuration + @EnableScheduling
monitor/MonitorSampler.java        @Scheduled 采样，累计值→区间差分，异常吞掉只 warn
monitor/MonitorStore.java          ArrayDeque 环形缓冲 + latest() + since(ts)
monitor/MetricSnapshot.java        不可变样本（record 或 final class）
monitor/SeriesMetric.java          metric 白名单枚举（含 unit 与取值函数）
monitor/HttpStatsAggregator.java   区间汇总 + Top N + 分位数
monitor/MonitorMetrics.java        业务埋点安全包装（registry 调用全 try/catch）
monitor/MetricWindow.java          窗口取数（minutes 钳位、warmup 判定）
controller/MonitorController.java  4 个接口 + require("monitor:view")
```

### 5.2 样本结构

```java
public record MetricSnapshot(
        long timestamp,                 // 采样时刻 epoch ms
        double heapUsedMb, double heapMaxMb, double nonHeapUsedMb,
        int threadsLive,
        long gcCount, double gcPauseMs,
        double cpuUsage, double uptimeSeconds, int cpuCount,
        long httpCount, double httpTotalMs, long http4xx, long http5xx,
        Map<Double, Long> httpBucketDelta,   // 桶上界(ms) -> 本区间计数
        Map<String, Double> business         // 业务指标本区间增量/耗时
) {}
```

- **HTTP/业务全部存区间差分**，不是累计值：这样 `/monitor/series` 的曲线与 `/monitor/*?minutes=` 的窗口聚合都是同一口径。
- 差分 key 用「指标名 + tag 值」拼串（如 `pipeline.run.success`），量级固定，不会随请求增长。
- 桶差分 = 本轮所有 `http.server.requests` timer 的 `histogramCounts` 求和 − 上一轮求和；P95/P99 在区间桶上做线性插值。

### 5.3 环形缓冲与并发

- 写：调度线程单写；读：HTTP 线程多读 → `MonitorStore` 的 `add/latest/since` 全部 `synchronized`。
- 容量 360，满了 `pollFirst()` 淘汰最旧；**不扩容**。
- `since(fromTs)` 只返回 `timestamp >= fromTs` 的样本，顺序为时间升序（`ArrayDeque` 天然有序）。
- 重启后缓冲为空：`latest()` 返回 `null`，`overview` 给 `sampling=false` 与空快照，前端显示 `warmup`。

### 5.4 采样失败隔离

```java
@Scheduled(fixedDelayString = "${monitor.sample.interval-ms:5000}")
public void sampleOnce() {
    try {
        store.add(collect());
        lastSampleAt.set(System.currentTimeMillis());
    } catch (Exception e) {
        // 单轮失败不能让调度任务停摆：Spring 的 fixedDelay 任务抛异常会继续下一轮，
        // 但异常会刷日志且不记录时间，所以这里必须自己吞并打 warn
        log.warn("指标采样失败（不影响业务）：{}", e.getMessage());
    }
}
```

`collect()` 设为 `protected`，单测用子类覆盖成抛异常，断言下一轮仍能执行（AC8）。

### 5.5 指标清单

| 展示项 | 来源 | 计算 |
|---|---|---|
| 堆已用 / 上限 | `jvm.memory.used{area=heap}` / `jvm.memory.max{area=heap}` | 求和后 /1024/1024；`max=-1` 时按 0 处理 |
| 非堆已用 | `jvm.memory.used{area=nonheap}` | 求和 |
| 活跃线程 | `jvm.threads.live` | 直接取值 |
| GC 次数/耗时 | `jvm.gc.pause` | 累计 `count` / `totalTime`；面板看增量 |
| CPU 使用率 | `process.cpu.usage` | 0~1 → 百分比 |
| 启动时长 | `process.uptime` | 秒 |
| CPU 核数 | `system.cpu.count` | 整数 |
| 区间请求数/QPS | `http.server.requests` | `∑(count−prevCount)`；QPS = 请求数 / 间隔秒 |
| 平均耗时 | 同上 | `∑ΔtotalTime / ∑Δcount` |
| P95/P99 | 同上（直方图桶） | 桶差分线性插值 |
| 4xx/5xx | 同上（`status` tag） | 首字符 `4`/`5` 分类 |

## 六、接口设计（S5）

统一前缀 `/monitor`，全部 `GET`，返回 `Result<T>`，权限 `monitor:view`。
**参数校验失败返回 HTTP 400**（控制器内 `@ExceptionHandler` 映射 `BusinessException`，与 `DocController` 一致）；其余 HTTP 200 + `body.code`。

| 接口 | 入参 | 返回字段 |
|---|---|---|
| `GET /monitor/overview` | — | `sampling`（15s 内有样本）、`lastSampleAt`、`intervalMs`、`bufferSize`、`sampledPoints`、`jvm{heapUsedMb,heapMaxMb,heapUsedRatio,nonHeapUsedMb,threadsLive,gcCount,gcPauseMs,cpuUsage,cpuCount,uptimeSeconds}`、`http{qps,avgMs,p95Ms,p99Ms,requests,errors4xx,errors5xx}` |
| `GET /monitor/series` | `metric`、`minutes`（默认 30） | `metric`、`unit`、`minutes`、`warmup`、`points[{t,v}]` |
| `GET /monitor/http` | `minutes`、`topN`（默认 10） | `minutes`、`warmup`、`totalRequests`、`qps`、`avgMs`、`p95Ms`、`p99Ms`、`errors4xx`、`errors5xx`、`errorRate`、`topSlow[{uri,method,count,avgMs,maxMs}]` |
| `GET /monitor/business` | `minutes` | `minutes`、`warmup`、`gen{batches,success,failed,successRate,avgMs,writeFileTotal,writeFiles{WRITTEN,MERGED,SKIPPED,ERROR}}`、`pipeline{runs,success,failed,stopped,steps[{step,count,avgMs}]}`、`doc{hit,converted,failed,avgMs}` |

### 6.1 指标白名单

| metric | 含义 | unit | 取值 |
|---|---|---|---|
| `jvm.heap` | 堆已用 | MB | `heapUsedMb` |
| `jvm.threads` | 活跃线程 | 个 | `threadsLive` |
| `process.cpu` | 进程 CPU | % | `cpuUsage*100` |
| `http.qps` | 区间 QPS | req/s | `httpCount/intervalSec` |
| `http.p95` | 区间 P95 | ms | 桶插值 |

非法值 → `BusinessException(PARAM_ERROR, "不支持的指标：xxx")` → HTTP 400，绝不透传给 MeterRegistry。

### 6.2 钳位规则

- `minutes`：缺省 30，`Math.max(1, Math.min(30, v))`，**不报错**。
- `topN`：缺省 10，`Math.max(1, Math.min(50, v))`。
- `warmup`：`窗口内样本数 < minutes*60/intervalSec` → true；前端据此显示"数据积累中"。

## 七、业务埋点（F-08）

统一通过 `MonitorMetrics` 记录，内部所有 registry 调用包 `try/catch`，失败只 `log.debug`。

| # | 位置 | 指标 | 说明 |
|---|---|---|---|
| 1 | `GenCodeServiceImpl#writeToDisk(GenWriteDTO,String)`（L188） | `gen.write` timer（tag `result=success/fail`）+ `gen.write.files` counter（tag `status=WRITTEN/MERGED/SKIPPED/ERROR`）+ `gen.write.files` 另记 `status=total` | 方法首行 `Timer.Sample`，`try/finally` 收尾；文件数从 `results` 统计，不额外遍历磁盘 |
| 2 | `GenCodeServiceImpl#preview`（L170） | `gen.preview` timer | `try/finally` |
| 3 | `PipelineExecutor#execute`（L128）步骤收尾 | `pipeline.step` timer（tag `step=<key>`、`state=success/failed`）+ `pipeline.run` counter（tag `state=success/failed`） | 在 `mark(step, ...)` 前后计时；整线结束的分支记 `pipeline.run` |
| 4 | `GenPipelineServiceImpl#stop`（L354 附近） | `pipeline.run` counter（tag `state=stopped`） | 停止动作在 executor 之外，必须单独记，否则面板成功率失真 |
| 5 | `DocPreviewEngine#convertToPdf`（L162） | `doc.convert` timer（tag `result=hit/converted/failed`） | 缓存命中、转换成功、异常三个出口都要记；`finally` 里按结果变量记录 |

`pipeline.step` 的 `step` tag 取值来自 `PipelineExecutor.STEP_KEYS`（11 个固定值），基数可控。

## 八、前端设计（S7）

```
src/api/monitor.js              monitorOverview / monitorSeries / monitorHttp / monitorBusiness
src/views/monitor/index.vue     全部页面逻辑（本版不拆组件，单页 4 区）
```

### 8.1 页面结构

1. **顶部状态条**：采样状态（绿点/灰点）+ 最近采样时间 + "仅进程内 30 分钟"提示 + 刷新按钮；停滞时插入告警条。
2. **4 张指标卡**：堆内存使用率（含进度条）、活跃线程、区间 QPS、平均响应耗时。
3. **JVM 趋势**：堆内存（MB）+ 活跃线程，双 Y 轴折线。
4. **HTTP 区**：QPS + P95 双轴折线；下方 Top N 慢接口表格（URI / 方法 / 次数 / 平均 / 最大）。
5. **业务区**：4 个小卡（生成批次与成功率、写盘文件数、pipeline 状态分布、文档转换命中/转换/失败 + 平均耗时）。

### 8.2 轮询与生命周期

- `setInterval(fetchAll, 5000)`；`document.visibilitychange`：隐藏时 `clearInterval`，恢复时立即拉一次再重启。
- `beforeDestroy`：清定时器 + `chart.dispose()`，防止菜单切换后请求与图表实例泄漏（AC11）。
- 单次 `fetchAll` 用 `Promise.allSettled`：单个接口失败不清空其他区域，也不弹 7 个错误提示（只在状态条显示"数据刷新失败"）。

### 8.3 ECharts 按需引入（AC14）

```js
const echarts = await import(/* webpackChunkName: "echarts" */ 'echarts/core')
const { LineChart, GaugeChart } = await import(/* webpackChunkName: "echarts" */ 'echarts/charts')
const { GridComponent, TooltipComponent, LegendComponent } = await import(/* webpackChunkName: "echarts" */ 'echarts/components')
const { CanvasRenderer } = await import(/* webpackChunkName: "echarts" */ 'echarts/renderers')
echarts.use([LineChart, GaugeChart, GridComponent, TooltipComponent, LegendComponent, CanvasRenderer])
```

- 统一挂在同一个 `echarts` chunk，不整包引入。
- 加载失败时 `chartsReady=false`，趋势区显示"图表组件加载失败"，卡片与表格照常可用。

## 九、权限与安全

1. `/actuator/health` 免 token；`/actuator/metrics`、`/monitor/*` 必须 token。
2. `MonitorController#require("monitor:view")`：`permissionService.isSuperAdmin` 直通，否则 `permissionsOf(userId).contains("monitor:view")`，失败 `BusinessException(FORBIDDEN)` → 403。
3. `management.endpoints.web.exposure.include` 枚举，`env/beans/heapdump/threaddump/loggers` 不暴露。
4. `health.show-details=never`：外部只看到 `{"status":"UP"}`。
5. 面板不渲染任何连接串、JVM 参数、文件系统路径；URI 只展示 Micrometer 模板（如 `/doc/preview/{id}`）。
6. 不新增静态资源映射，ECharts 走打包产物。
