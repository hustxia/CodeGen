# 行业范式模板市场与安装机制 设计

> 关联需求：`docs/requirements/行业范式模板市场-需求.md`
> 版本：v1.0　日期：2026-11-28　对应版本 V1.30 M1.2（V9.22）

## 一、表结构

范式包本体复用 V9.7/V9.19 的 `industry-templates/*.json`（`IndustryTemplateRegistry` 已能加载 250+ 套），本期只新增两张表。

```sql
-- 1) 范式包元数据：四包的命中度/外接/边界标注（registry JSON 只存表结构）
CREATE TABLE IF NOT EXISTS gen_industry_paradigm (
    id              bigint       NOT NULL COMMENT '雪花ID',
    pack_key        varchar(64)  NOT NULL COMMENT '模板包key(对应industry-templates/*.json)',
    industry        varchar(64)  NOT NULL COMMENT '行业:村务治理/城市管理/智慧园区/智慧种植',
    category        varchar(64)  NOT NULL DEFAULT '' COMMENT '分类(与registry一致)',
    version         varchar(20)  NOT NULL DEFAULT '1.0' COMMENT '范式版本',
    hit_rate        int          NOT NULL DEFAULT 0 COMMENT '生成器命中度(0-100)',
    direct_tables   int          NOT NULL DEFAULT 0 COMMENT '直建表数',
    external_systems int         NOT NULL DEFAULT 0 COMMENT '必须外接的系统数',
    dedup_note      varchar(512) NOT NULL DEFAULT '' COMMENT '去重说明',
    boundary_note   varchar(512) NOT NULL DEFAULT '' COMMENT '不承诺边界',
    core_chain      varchar(512) NOT NULL DEFAULT '' COMMENT '业务主线',
    sort_no         int          NOT NULL DEFAULT 0 COMMENT '展示排序',
    enabled         tinyint      NOT NULL DEFAULT 1 COMMENT '0禁用 1启用',
    create_time     datetime     DEFAULT CURRENT_TIMESTAMP,
    update_time     datetime     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    create_by       bigint       DEFAULT NULL,
    update_by       bigint       DEFAULT NULL,
    deleted         tinyint      NOT NULL DEFAULT 0,
    PRIMARY KEY (id),
    UNIQUE KEY uk_paradigm_key (pack_key),
    KEY idx_paradigm_industry (industry, enabled)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '行业范式包元数据';

-- 2) 安装台账：只记录plan，不建库（保留Step2人工确认卡点）
CREATE TABLE IF NOT EXISTS gen_industry_install (
    id              bigint       NOT NULL COMMENT '雪花ID',
    project_id      bigint       NOT NULL COMMENT '项目ID',
    pack_key        varchar(64)  NOT NULL COMMENT '范式包key',
    pack_version    varchar(20)  NOT NULL DEFAULT '' COMMENT '安装时范式版本',
    scope           varchar(20)  NOT NULL DEFAULT 'new' COMMENT 'new/supplement',
    module_names    text         COMMENT '安装模块名JSON数组',
    table_count     int          NOT NULL DEFAULT 0 COMMENT 'plan表数',
    plan_summary    text         COMMENT 'plan摘要JSON',
    status          varchar(20)  NOT NULL DEFAULT 'INSTALLED' COMMENT 'INSTALLED/REMOVED',
    install_time    datetime     DEFAULT CURRENT_TIMESTAMP,
    create_time     datetime     DEFAULT CURRENT_TIMESTAMP,
    update_time     datetime     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    create_by       bigint       DEFAULT NULL,
    update_by       bigint       DEFAULT NULL,
    deleted         tinyint      NOT NULL DEFAULT 0,
    PRIMARY KEY (id),
    KEY idx_install_project (project_id, status),
    KEY idx_install_pack (pack_key, status)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COMMENT = '行业范式安装台账';
```

四包实测口径：

| key | 行业 | 命中度 | 直建表 | 外接系统 | 模块 |
|---|---|---|---|---|---|
| village_affairs | 村务治理 | 92% | 85 | 0 | 5（复用已有包） |
| cm_city | 城市管理 | 88% | 23 | 4 | 5（本期新建） |
| agr_crop | 智慧种植 | 90% | 35 | 1 | 6（复用已有包） |
| park_park | 智慧园区 | 85% | 22 | 14 | 6（本期新建） |

**关键设计决定**：村务/种植复用已有 JSON 包（85/35 表），城管/园区只造核心表（23/22 表）不造全量 1000 表——行业方案里的全量表清单是"交付范围"，不是"模板资产"；模板要的是可克隆的骨架，细节在 plan 阶段由用户编辑补齐。

## 二、功能设计

| 编号 | 功能点 | 页面/位置 | 字段与操作 | 状态流转 | 验收标准 |
|---|---|---|---|---|---|
| F-01 | 范式包列表 | 市场页/卡片网格 | 行业筛选、关键词、来源、版本、命中度、外接数 | — | 四包展示；按行业筛选生效 |
| F-02 | 范式包详情 | 详情抽屉 | 模块清单、表清单、去重说明、边界、主线 | — | key 正确返回模块与表；标注齐全 |
| F-03 | 安装向导 | 三步：选包→选项目/模块→确认 | projectId、moduleNames、scope | — | 生成 plan（source=template）；写台账 1 行 |
| F-04 | 已装包列表 | 我的安装页 | 项目、包、版本、模块、安装时间 | — | 按项目筛选；恒有演示数据 |
| F-05 | 移除安装 | 已装包行操作 | 二次确认 | INSTALLED→REMOVED | 台账状态变更；gen_table 不动 |
| F-06 | 复用导入导出 | 市场页工具栏 | V9.19 既有端点 | — | 范式包可被导出/导入 |

### 页面结构
- 查询区：行业下拉 + 关键词输入
- 卡片：行业图标、名称、版本、命中度进度条、直建表/外接系统数、边界摘要、[详情][安装] 按钮
- 详情抽屉：模块 Tab → 表清单表格 → 去重/边界/主线三段说明
- 安装向导：Step1 选包（只读）→ Step2 选项目+勾模块+scope → Step3 plan 预览（模块数/表数/排除数）+ 确认
- 表单校验：projectId 必填、moduleNames 至少 1 个

## 三、接口设计

| 接口 | 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|---|
| 范式包清单 | GET | `/gen/industry-pack/list` | `?industry=&keyword=` | `List<IndustryParadigmVO>`（含 tableCount） |
| 范式包详情 | GET | `/gen/industry-pack/detail/{key}` | — | `IndustryParadigmVO`（含 modules/tables） |
| 安装（生成plan+台账） | POST | `/gen/industry-pack/install` | `IndustryPackInstallDTO` | `IndustryInstallVO`（plan 摘要） |
| 已装包列表 | POST | `/gen/industry-pack/installed` | `{projectId}` | `List<GenIndustryInstall>` |
| 移除安装 | DELETE | `/gen/industry-pack/install/{id}` | — | `Result<Void>` |

沿用既有约定：统一响应 `{code,msg,data}`、错误 HTTP 200 + body.code、雪花 ID 字符串下发、无 `/api` 前缀、POST 分页。`install` 内部调用 `AiTableRecommendService.planFromTemplate`（V9.7 已验证的克隆+收口链路），不重复实现表克隆规则（单一实现原则）。

## 四、验证记录（S8 实测 2026-11-28）

### 第 1 层 编译
```
后端 mvn -o -q package -DskipTests  → PACKAGE_EXIT=0, jar 新鲜(11:52)
前端 npx vue-cli-service lint --no-fix (5 文件) → DONE No lint errors found! LINT_EXIT=0
```
启动日志实证：`V9.19 行业模板库已加载：预置 257 套 / 用户包 1 套，共 258 套 9000 张表（分类 22 个）` —— 从 255 增至 257，证明 cm_city/park_park 两包已被 registry 加载。

### 第 2 层 接口（9 个断言全过）
```
GET  /gen/industry-pack/list            → code 200, n=4
     四包: village_affairs 92%/85表 · cm_city 88%/23表 · agr_crop 90%/35表 · park_park 85%/22表
GET  /list?industry=城市管理             → code 200, n=1 ['cm_city']（筛选生效）
GET  /detail/cm_city                    → code 200, modules 5 tables 23, detail.modules 5, id type str
POST /install (项目1+城管2模块)           → code 200, moduleCount=2 tableCount=10 excludedCount=0
                                            planSource=template ddlReady=false installId 雪花字符串
POST /installed?projectId=1             → code 200, n=2 [cm_city v1.0 10表, village_affairs v1.0 85表]
边界1 同项目同包重复安装                  → code 400 "该项目已安装该范式包 v1.0…"
边界2 moduleNames 为空                   → code 400 "moduleNames:请至少选择一个模块"
边界3 不存在的包                         → code 404 "范式包不存在：not_exist"
DELETE /install/{id}                    → code 200
删除后 /installed                       → code 200, packs ['village_affairs']（只删目标记录，村务保留）
```
**关键证据**：install 的 plan 表数=10（选 2 模块）而非包总量 23，证明真正调用了 V9.7 `planFromTemplate` 按模块克隆，不是硬编码；`ddlReady=false` 证明守住了"只生成 plan 不建库"边界。
