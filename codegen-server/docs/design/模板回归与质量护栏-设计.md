## 一、表结构

**本版无表结构变更。** 证据：

- `git diff --stat` 中不含 `docs/sql/` 与 `src/main/resources/db/`；
- 新增的 `src/test/resources/schema-test.sql` 是**测试库**结构，用于契约测试自举，不影响生产库；
- 依赖清单 `pom.xml` 未新增运行时依赖（契约测试用已有的 `spring-boot-starter-test`）。

测试库（`gen_platform_test`）只建 6 张表：`gen_table`、`gen_table_column`、`gen_output`、`gen_template`、`gen_history`、`sys_project`。
`gen_template` 由启动时的 `GenTemplateSeeder` 从 `classpath:gen-templates/*.ftl` 自动落库，因此测试库不需要预置模板数据。

### F-04 断言的四个不变式

| 不变式 | 用例 | 断言要点 |
|---|---|---|
| 台账完整 | `ledgerMatchesDisk` | 台账行数 == 实际写入文件数；每行 md5/字节数与磁盘一致；文件必须在 `@TempDir` 沙箱内 |
| 备份可信 | `backupAndPrevMd5Trustworthy` | 覆盖后 `prev_md5` == 备份文件 md5 == 覆盖前文件 md5 |
| 回滚可逆 | `rollbackRestoresAndCanRollbackAgain`（前半） | 回滚后文件 md5 回到覆盖前 |
| 回滚可再回滚 | 同上（后半） | RBK 批次存在，对其再回滚可回到回滚前 |
| 漂移拦截 | `driftDetectedAndSkipped` | 手改 → drift=DRIFTED；`skipDrifted=true` 时该文件 SKIPPED 且内容保留 |
| 选择性回滚 | `selectiveRollbackOnlyTouchesPicked` | 只还原勾选文件，未勾选的保持覆盖后内容 |
| 差异事实 | `diffReturnsFacts` | 每行都有 `status` 与 `side`，且前后端产物都能识别 |
| 巡检 | `healthReportsCounts` | 计数非零；删文件后孤儿数 ≥1 |

## 三、接口设计

本版**不新增接口**，契约测试固化的是既有接口的行为。前端 V4.3 未新增页面，沿用 V4.2 的向导与台账页。

| 接口 | 方法 | 路径 | 请求体 | 响应（data 部分） |
|---|---|---|---|---|
| 差异 | POST | `/gen/diff` | `{ids:[], onlyChanged:false}` | `[{path,status,side,drift,lastModified,additions,deletions}]` |
| 写盘 | POST | `/gen/write` | `{ids:[], overwrite, skipDrifted}` | `[{path,status,message,backupPath,batchNo}]` |
| 漂移 | POST | `/gen/drift` | `{ids:[]}` | `{total,same,drifted,missing,unknown,items:[{absPath,relPath,status,expectedMd5,actualMd5}]}` |
| 回滚预览 | POST | `/gen/history/rollback/preview?batchNo=` | `{ledgerIds?,paths?,skipDrifted?}` | `{total,restore,remove,skip,drifted,items:[{ledgerId,op,reason,reasonPath,drifted}]}` |
| 回滚执行 | POST | `/gen/history/rollback?batchNo=` | 同上 | `{total,restore,remove,skip,rollbackBatch,problems}` |
| 台账巡检 | GET | `/gen/ledger/health` | — | `{totalRecords,uniquePaths,orphanCount,backupMissingCount,duplicateCount,driftedCount,orphan[],backupMissing[],duplicate[]}` |

约定沿用项目既有：统一 `{code,msg,data}`，错误也是 HTTP 200 + `code`；`Long` 主键以字符串下发；分页接口 POST + JSON body。

## 四、本版修复的缺陷（测试驱动发现）

契约测试 `rollbackRestoresAndCanRollbackAgain` 首次运行即变红，暴露 V4.2 遗留缺陷：

| 项 | 内容 |
|---|---|
| 现象 | 回滚一个批次后，立刻对生成的 `RBK` 批次再回滚，文件没有回到「回滚前」状态 |
| 根因 | 回滚批次号精确到**秒**（`RBKyyyyMMddHHmmss`），两次回滚落在同一秒 = 同一个批次号 = 同一个备份目录。第二次回滚的「回滚前备份」正好写进它即将读取的「还原源」路径，把还原源覆盖成当前内容，回滚退化为空操作，且备份链被破坏 |
| 修复 | ① 回滚批次号改为毫秒精度（`RBK` + `yyyyMMddHHmmssSSS`）；② `backupBeforeRollback` 增加 `avoidPath` 参数，备份目标与还原源同路径时改名为 `*.before`，双保险 |
| 影响面 | 仅回滚链路；写盘批次号（`GEN` + 秒）不变，避免影响既有台账数据 |
