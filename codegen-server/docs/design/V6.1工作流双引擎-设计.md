## 一、表结构

```sql
-- V6.1__flow_engine.sql：两个 ADD COLUMN，无新表（sys_flow_def/sys_flow_task 已存在）
ALTER TABLE sys_project
    ADD COLUMN flow_engine varchar(16) DEFAULT NULL COMMENT '产物流程引擎：null/builtin=内置简易流，activiti=Activiti 8 引擎' AFTER default_gen_print;

ALTER TABLE sys_flow_def
    ADD COLUMN bpmn_xml mediumtext NULL COMMENT 'V6.1 自动翻译的 BPMN 2.0 XML（部署审计用）' AFTER nodes;
```

## 四、关键设计决策

| 决策点 | 定案 | 理由 |
|---|---|---|
| 引擎版本 | Activiti 8.4+（Java 17+/Boot 3 线） | 7.x 是 javax；8.x 唯一兼容产物 Boot 3.2.5 |
| Alfresco 风险 | pom 内置 repositories + 自检依赖可解析项 + FlowService 接口隔离保留 Flowable 7 逃生门 | 最大交付风险前置声明 |
| 基座类策略 | F-01 先补齐 BuiltinFlowService（修真 bug），activiti 实现叠加 | 不修 bug 任何 flow 产物都编译不过，双引擎无从谈起 |
| 流程下发方式 | 产物 db 脚本带定义 INSERT + 产物启动 Runner 自动部署 | 平台不直连产物库（单向输出原则，与菜单 SQL 产物化同款思路） |
| 历史数据 | ACT_HI_* 为主，records 视图兼容 | 避免双写不一致 |
| 安全 | 排除引擎 SecurityAutoConfiguration，IdentityService 桥接 | 产物鉴权统一在 AuthContextFilter，双体系必打架 |

## 五、明确不做（P2）

可视化流程设计器、引擎独立微服务、流程版本迁移（存量实例升级）、多租户、消息通知集成。
