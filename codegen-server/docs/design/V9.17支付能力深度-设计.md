## 一、侦查结论（决定实现形态的关键事实）

| 项 | 结论 | 对设计的影响 |
|---|---|---|
| 4 个 pay 模板现状 | `payApi` / `payOrderPage` 已含 V6.3 补全的退款导出与退款弹窗；`payBizApi` 已按 `pay_code` 生成三端点（下单/查状态/退款），`payCashier` 仍是 V6.3 原版三渠道 | 本轮不重写既有能力，只做增量；退款按钮/退款申请已满足需求，仅补「退款单号幂等输入」「退款结果查询」 |
| `ScaffoldOpsWriter.java` | **不是** pay 能力的索引/开关点：只提供 `payResource()` 读 `scaffold-pay/<file>` 源码 | 侦查结论需纠正：真正的开关在 `GenTemplateModel.resolvePay`、`GenTemplateEngine.renderPayShared`、`GenScaffoldServiceImpl` |
| `renderPayShared` 的渲染模型 | 用 `Map.of()` **空模型**渲染 `payApi/payCashier/payOrderPage` | 共享模板不能依赖必填变量；新增开关必须写成 `(key!0)` 缺省关，否则空模型渲染抛异常、`catch` 成空 Map，整个能力包静默丢失 |
| `GenTemplateModel` 可用字段 | 有 `payCode`/`payCodeSafe`/`hasPayBiz`/`payBizNoColumn`/`payBizAmountColumn`（表级）；`ProjectConfig.payEnabled`（系统级）；**无** JSAPI/H5/沙箱字段 | 不新增 DTO：把 model 的 `Map<String,Object>` 作为现成扩展点传入开关键；表级已支持的 `pay_code` 直接复用 |
| 前端配置页 | `codegen-web/src/views/gen/project/index.vue` 只有 `payEnabled` 三态下拉，没有独立支付配置页；新增子开关需改 `SysProject` 实体/API（越界） | 本轮不改前端控制台，子开关先按 model Map 契约提供，界面接线列为未尽事项 |
| 测试口径 | `GenTemplateBaselineTest.sharedEmpty` 锁 5 个共享模板空模型快照；`GenTemplateContractTest` 断言空模型能渲染；`PayRefundContractTest` 断言退款/pay_code 契约；`scripts/verify.sh` 无 pay 专属步骤 | 零 diff 的第一道门禁就是「空模型产物快照」；本轮新增能力必须让空模型渲染结果与改动前逐字节一致 |

## 二、三态开关契约

所有新增能力遵循 `NULL / 缺失 / 0 = 关，1 = 开`。模板统一用 Freemarker 写法 `<#if (key!0) == 1>`：
- 变量缺失或值为 `null` → `!0` 兜底为 0 → 关；
- 值为 `0` → 关；
- 值为 `1`（Integer）→ 开。

| 开关键（渲染 model Map 的 key） | 作用域 | 打开后产物变化 |
|---|---|---|
| `payJsapiEnabled` | `payApi` / `payCashier` | 导出 `getPayConfig`、`createJsapiOrder`、`getJsapiSignature`；收银台微信内置浏览器走 `WeixinJSBridge.invoke('getBrandWCPayRequest')`，下单带 `payScene:'jsapi'` |
| `payH5Enabled` | `payApi` / `payCashier` | 导出 `createH5Order`；收银台非微信浏览器显示 H5 跳转按钮并跳 `payUrl` |
| `payRefundNoEnabled` | `payOrderPage` | 退款弹窗多「退款单号」输入，随 `refundPayOrder` 传 `refundNo`（渠道幂等键） |
| `payRefundQueryEnabled` | `payBizApi` / `payApi` / `payOrderPage` | 表级支付接口追加 `GET /{module}/pay/refund/{bizNo}/result`；全局 API 追加 `getRefundResult`；记录页追加「退款结果」按钮与弹窗 |
| `payAlipaySandboxEnabled` | `payApi` / `payCashier` | 导出 `getPayConfig`（与 JSAPI 共用，不重复导出）；收银台显示沙箱提示、沙箱扫码登录入口，`gotoAli` 优先跳后端下发的沙箱 `payUrl` |

约定：
- 五个键彼此独立，任意组合可用；全部关闭时四个产物与 V6.3 补全版**逐字节一致**。
- 键通过已有的 `Map<String,Object>` model 扩展点传入，**不新增 DTO**；表级 `payBizApi` 继续消费既有 `payCode`/`payCodeSafe`/`payBizNoColumn`/`payBizAmountColumn`。
- 当前 `renderPayShared` 仍传空 Map，因此默认生成关闭（符合「新增能力默认关闭」）；开启接线见「未尽事项」。

## 三、新增接口清单

### 3.1 前端产物 API（src/api/pay.js，全部在开关打开时才生成）

| 函数 | 方法/URL | 说明 |
|---|---|---|
| `getPayConfig()` | `GET /pay/config` | 运行时配置：`wxAppId`、`alipaySandbox`、`alipayGateway`、`alipaySandboxPayUrl`、`alipaySandboxLoginUrl` 等；appId/商户号由产物后端从 yml 读取后下发，前端零硬编码 |
| `createJsapiOrder(data)` | `POST /pay/jsapi/order` | JSAPI 下单，响应含 `prepayId` / `jsapiSign`（或签名六元组） |
| `getJsapiSignature(url)` | `GET /pay/jsapi/signature?url=...` | 按当前页面 URL 换 `jsapi_ticket` 签名，响应含 `appId/timestamp/nonceStr/package/signType/paySign` |
| `createH5Order(data)` | `POST /pay/h5/order` | H5 下单，响应含 `payUrl`（微信 H5 支付链接） |
| `getRefundResult(outTradeNo)` | `GET /pay/refund/{outTradeNo}/result` | 退款结果查询（金额单位分） |
| `refundPayOrder(outTradeNo, data)` | 既有 | V6.3 补全已提供；`payRefundNoEnabled=1` 时 `data` 多传 `refundNo` |

### 3.2 产物后端端点（需 scaffold-pay 侧接线，不在本轮文件范围）

| 端点 | 用途 | 幂等/安全要求 |
|---|---|---|
| `GET /pay/config` | 下发非敏感运行时配置（`wxAppId`、沙箱标识与跳转 URL），**不得下发商户私钥/API v3 密钥** | 只读；未配置时返回空对象，前端 catch 保持默认 |
| `POST /pay/jsapi/order` | 调微信 JSAPI 下单，落 `pay_order`，返回 prepay 参数 | 沿用 `PaymentService.create` 状态机与 `pay_code`；金额元→分单一精度来源 |
| `GET /pay/jsapi/signature` | 用服务端缓存的 `jsapi_ticket` 对 URL 签名 | 签名在服务端完成，ticket/密钥不出后端；`url` 参数做白名单/长度校验 |
| `POST /pay/h5/order` | 调微信 H5 下单，返回 `payUrl` | 同上 |
| `GET /pay/refund/{outTradeNo}/result` | 返回退款金额/时间/原因/状态 | 仅查单，不触发渠道调用 |
| `GET /{module}/pay/refund/{bizNo}/result` | 表级绑定端点（本轮已在 `payBizApi.ftl` 生成） | 用 `payNo = PAY_CODE + "_" + bizNo` 作业务侧支付单号，不硬编码 `order_no` |

## 四、pay_code 表级绑定（本轮增量）

- 既有：`GenTemplateModel` 从 `gen_table.pay_code` 读出 `payCode`/`payCodeSafe`，按命名约定推导单号列 `payBizNoColumn`（order_no/bill_no/...，无则主键 id）与金额列 `payBizAmountColumn`；`GenTemplateEngine` 在 `hasPayBiz` 为真时渲染 `{Class}PayController`。
- 本轮新增（受 `payRefundQueryEnabled` 门控）：`payNo(String bizNo)` 以 `PAY_CODE + "_" + bizNo` 生成业务侧支付单号，随退款结果返回。表名、列名、pay_code 全部生成期固化为常量，运行期只做参数绑定，无用户输入拼接。

## 五、支付宝沙箱配置示例（产物侧，需后端 yml 支持）

```yaml
pay:
  channel: alipay                 # mock | wxpay | alipay
  alipay:
    sandbox: true                 # 三态同款：缺省 false；true=沙箱网关
    gateway: https://openapi-sandbox.dl.alipaydev.com/gateway.do   # sandbox=true 时切换（示例域名以实际控制台为准）
    app-id: ${ALIPAY_APP_ID:}
    merchant-private-key: ${ALIPAY_MCH_PRIVATE_KEY:}
    alipay-public-key: ${ALIPAY_PUBLIC_KEY:}
    sandbox-login-url: ${ALIPAY_SANDBOX_LOGIN_URL:}
```

- 密钥仍走 V6.2 `${PAY_*:}` 占位符，主 yml 零明文；`alipay.sandbox=true` 由产物后端切换网关并把 `alipaySandbox=true` / `alipaySandboxLoginUrl` 通过 `GET /pay/config` 下发给收银台。
- 前端不拼网关域名、不写死 appId/商户号；沙箱扫码/登录跳转地址来自配置。`gateway` 域名仅作为配置示例，实际以支付宝开放平台沙箱环境公布的为准。

## 七、生成物示例（开关全开时节选）

`src/api/pay.js`：

```js
export function getPayConfig() {
  return request({ url: '/pay/config', method: 'get' })
}
export function createJsapiOrder(data) {
  return request({ url: '/pay/jsapi/order', method: 'post', data })

export function getJsapiSignature(url) {
  return request({ url: '/pay/jsapi/signature', method: 'get', params: { url } })
}

  return request({ url: '/pay/h5/order', method: 'post', data })
}
export function getRefundResult(outTradeNo) {
  return request({ url: '/pay/refund/' + outTradeNo + '/result', method: 'get' })

```

`views/pay/cashier.vue`（script 段节选）：

```js
const cfg = (await getPayConfig()).data || {}
this.payConfig = cfg
this.sandbox = cfg.alipaySandbox === true || cfg.alipaySandbox === 1
// JSAPI：appId 来自配置，签名来自后端
this.jsapiParams = { appId, timeStamp: String(sign.timestamp), nonceStr: sign.nonceStr,
  package: sign.package, signType: sign.signType || 'RSA', paySign: sign.paySign }

```

`{Class}PayController.java`（表级新增端点节选）：

```java
@GetMapping("/refund/{bizNo}/result")
public Result<Map<String, Object>> refundResult(@PathVariable String bizNo) {
    PayOrder latest = latestOrder(bizNo);
    if (latest == null || latest.getRefundAmount() == null || latest.getRefundAmount() <= 0) {
        throw new BusinessException(404, "该业务单没有退款记录：" + bizNo);
    }
    Map<String, Object> data = new LinkedHashMap<>();
    data.put("payNo", payNo(bizNo));   // PAY_CODE + "_" + bizNo
    data.put("outTradeNo", latest.getOutTradeNo());
    data.put("refundAmount", latest.getRefundAmount());
    return Result.ok(data);
}
```

## 八、手工验证步骤（模板无法单测时的口径）

1. **默认零 diff**：`pay_enabled` 不开的系统生成 ZIP → 与 V6.3 产物 `diff -r`，支付相关文件应完全相同（本轮默认全关）。
2. **空模型渲染**：用 `GenTemplateEngine.renderString(ftlContent, Map.of())` 渲染四个模板，均不抛异常且非空。
3. **JSAPI 分支**：开关 `payJsapiEnabled=1`，微信内打开收银台 → 下单走 `/pay/jsapi/order`，签名接口返回后按钮可点，`WeixinJSBridge` 调起支付；检查 Network 无硬编码 appId 出现在前端源码。
4. **H5 分支**：`payH5Enabled=1`，微信外打开 → 下单走 `/pay/h5/order` 并跳 `payUrl`。
5. **退款**：已支付订单显示「退款」按钮；`payRefundNoEnabled=1` 时输入同一退款单号重复提交，渠道侧不产生第二笔退款；`payRefundQueryEnabled=1` 时「退款结果」显示金额/时间/原因。
6. **沙箱**：`pay.alipay.sandbox=true` → 收银台显示沙箱提示，扫码/登录跳配置地址；抓包确认网关为沙箱域名而非生产域名。
7. **组合**：任意两两开关组合渲染后，用 `node --check`（Vue 取 `<script>` 段）确认语法，确认 import 的函数都有对应导出。

## 十、未尽事项与风险

1. **开关接线（高）**：`renderPayShared` 目前传空 Map，五个新开关在默认生成链路中都是关的。要真正启用，需由引擎负责人把配置（来自系统/项目配置）放进渲染 model；按本轮边界（`GenTemplateEngine`/`GenTemplateModel`/`SysProject` 属他人领域）未改。模板侧契约已固定，接线后即可生效，无需再改模板。
2. **产物后端端点（高）**：`/pay/config`、`/pay/jsapi/order`、`/pay/jsapi/signature`、`/pay/h5/order`、`/pay/refund/{outTradeNo}/result` 需 `scaffold-pay` 侧实现（复用 `PaymentService`/`AbstractPayService` 状态机与签名配置）。未实现前打开开关会得到 404，前端已做 try/catch 降级但功能不可用。
3. **快照基线陈旧（中）**：`src/test/resources/gen-baseline/shared-empty/*.txt` 仍是 V6.3 补全前版本，中央验证时需统一刷新（本轮不改测试资源）。
4. **沙箱域名（中）**：文档中的 `openapi-sandbox.dl.alipaydev.com` 仅作配置示例，实际网关以支付宝开放平台当前沙箱说明为准；前端不硬编码该域名。
5. **JSAPI 签名兼容性（中）**：`jsapiSign` 与 `getJsapiSignature` 两种返回形态做了兼容；后端选定一种后建议收敛为一种，避免两套签名来源。
6. **Vue 2.7 模板**：收银台/订单页是 Vue 2.7 SFC，本轮只在 `<script>` 段做可选注入；已用 `node --check` 校验脚本段，SFC 模板段的运行时行为需按第八节手工验证。
