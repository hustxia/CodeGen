## 三、关键实现设计

### 3.1 GenPathResolver（模块归属唯一实现的扩展）

- 新增 `isMicro(String)`：严格匹配 "micro"；`isMulti` 不变（避免误伤存量）。
- `moduleRelPrefix` 判定改为 `isMulti(ps) || isMicro(ps)`——micro 的产物模块归属与 multi 完全一致（entity→domain 等）。
- `moduleOfTpl` 不加 gateway：gen 模板产物永远不进 gateway 模块，gateway 只有 scaffold 产物。

### 3.2 GenScaffoldServiceImpl micro 分支

在 multi 分支内按 `micro = GenPathResolver.isMicro(...)` 增强：

| 产物 | 内容 |
|---|---|
| parent pom | multi 内容 + BOM import（spring-cloud 2023.0.1、alibaba 2023.0.1.0）+ `<module><stem>-gateway>` + openfeign 版本属性 |
| `<stem>-gateway/pom.xml` | parent 指聚合；gateway + nacos-discovery + loadbalancer + nacos-config + starter-bootstrap（shop 实测四件套） |
| gateway Application | 独立启动类 `<App>GatewayApplication`，包名 `<pkg>.gateway` |
| gateway application.yml | port=serverPort+1；routes catch-all → `lb://<stem>-bootstrap`（注释直连示例与按模块聚合示例）；CORS 全放 |
| bootstrap pom | micro 追加 nacos-discovery/nacos-config/openfeign/loadbalancer |
| bootstrap application.yml | 追加 `spring.application.name=<stem>-bootstrap`、nacos enabled=false 块、`<stem>.remote.bootstrap-url: http://localhost:<serverPort>`（Feign 直连默认值） |
| bootstrap.yml | 注释态 Nacos config import（`spring.config.import: optional:nacos:...`）+ 使用说明头注释 |
| service remote/ | `<pkg>.remote.RemoteSampleClient`：`@FeignClient(name="<stem>-bootstrap", url="${<stem>.remote.bootstrap-url:}")`，注释写明 true 模式清空 url 走 lb |
| 启动类 | micro 时加 `@EnableFeignClients(basePackages="<pkg>.remote")` |

### 3.3 版本矩阵（复用 shop 实测，不再手工验证）

Boot 3.2.5 + spring-cloud 2023.0.1 + spring-cloud-alibaba 2023.0.1.0；gateway 依赖五件套照抄 shop/shop-gateway。

### 3.4 apiBase 计算点（唯一实现 GenTemplateModel:243）

```java
m.put("apiBase", micro ? "/"+module
        : prefix.isEmpty() ? "/"+module : "/api/"+prefix+"/"+module);
```

micro 时网关按 `/{module}/**` 转发，前端不再拼 `/api/{gatewayPrefix}`；ProjectConfig 已携带 projectStructure，模板模型新增 `m.put("isMicro", ...)` 供模板分支。

### 3.5 跨系统引用拦截（loadChildren）

子表非空 projectId 与主表 projectId 不相等 → 抛 BusinessException：`主子表跨系统引用：子表[x]（系统A）与主表[y]（系统B）不一致，请修正子表的所属系统`。双侧均 null 视为存量数据放行。
