## 三、关键实现设计

### 3.1 模块归属唯一实现（GenPathResolver）

新增静态方法（单一实现原则，四个入口全调它）：

```java
/** 产物 → 模块归属。返回 null 表示单模块（沿用现有 backendBase 直落） */
public static String backendModuleOf(String templateKey, SysProject project)
```

映射表：

| templateKey 前缀 | 模块 | 落位 |
|---|---|---|
| entity / mapper | domain | `<root>/&lt;code&gt;-domain/src/main/java/...` |
| controller / service / dto / vo | service | `<root>/&lt;code&gt;-service/src/main/java/...` |
| pom / bootstrap / yml（scaffold 产物） | 各自 | 见 3.2 |
| 其他（单模块基座类） | common | `<root>/&lt;code&gt;-common/src/main/java/...` |

触发条件：`project.getProjectStructure()` 为 'multi' 才分层；否则返回 null 走原路径（单模块行为零变化）。

### 3.2 脚手架多模块化（GenScaffoldServiceImpl）

structure='multi' 时 scaffold 产物清单：

| 产物 | 落位 | 来源 |
|---|---|---|
| parent/pom.xml | backendRoot/ | pomParent.ftl（modules 聚合 + 依赖版本管理） |
| `<code>-common/pom.xml` + 基座类 | common 模块 | pomCommon.ftl + 现有基座生成逻辑（落位改 common） |
| `<code>-domain/pom.xml` | domain 模块 | pomDomain.ftl（依赖 common + mybatis-plus） |
| `<code>-service/pom.xml` | service 模块 | pomService.ftl（依赖 domain + spring-web） |
| `<code>-bootstrap/pom.xml`、`XxxApplication.java`、`application.yml` | bootstrap 模块 | pomBootstrap.ftl + 启动类模板（@MapperScan 指 domain.mapper） |

单模块时走现有逻辑不动。

### 3.3 数据流（改哪里必须同步哪里）

配置回落链不变（表级→系统→yml），`project_structure` 是**系统级唯一来源**，不进表级回落。
写盘路径两个入口（`GenTemplateModel.build` 模型侧 / `GenCodeServiceImpl` 写盘侧）都改为调 `GenPathResolver.backendModuleOf`——历史上"预览对、写盘错"的事故不允许重演（速查红线）。

### 3.4 预览与 ZIP

预览接口返回的 path 字段直接展示多模块相对路径；ZIP 按模块目录打包（现有打包逻辑以 path 为准，无需特判）。

## 四、接口设计

**无新增接口**。F-01 复用 `SysProjectController` 现有 CRUD：

| 接口 | 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|---|
| 系统列表 | GET | /sys/project/list | — | records 含 projectStructure |
| 系统详情 | GET | /sys/project/{id} | — | data 含 projectStructure |
| 新建/修改 | POST/PUT | /sys/project | {projectStructure: null\|"mono"\|"multi", ...} | code=0 |

实现要点：SysProject 实体加字段 + VO 若存在需同步加字段（V5.5 走查教训：VO 漏字段静默丢——列表 projectId 为 null 事故同根因）。
