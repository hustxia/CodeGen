## 一、表结构

`sys_project` 新增三列（`docs/sql/V6.8__app_brand.sql`，已在 `gen_platform`、`gen_platform_test` 执行）：

| 列 | 类型 | 语义 |
|---|---|---|
| app_name | varchar(64) NULL | 应用显示名（空=回落工程名） |
| app_logo | varchar(255) NULL | Logo URL（空=回落 placeholder.svg / 文字标识） |
| app_theme_color | varchar(16) NULL | 品牌主色（空/非法=回落 `#e1251b`） |

三列全可空、走三态显式 SET（`SysProjectServiceImpl.update` 对每列单独 `LambdaUpdateWrapper.set`，延续 V5.5/V6.1 模式——`updateById` 的 NOT_NULL 策略写不回 null，「清空品牌」必须生效）。

其余功能不新增表：影响面复用 `gen_output` 台账 md5 快照；multiImage 是列的 `html_type` 推导结果，不是新列。

## 二、功能设计

| 功能点 | 唯一实现位置 | 要点 |
|---|---|---|
| F-01 影响面预览 | `GenApplyServiceImpl.dryRun` 分支 + `GenImpactVO` | dryRun 回 `{total,newCount,modifiedCount,unchangedCount,protectedCount,files[]}`，files 与计数同源（都出自 `GenCodeService.diff`）；写盘后也回填同一份 |
| F-02 受保护跳过 | `GenCodeServiceImpl.writeTable` / `diffTable` | 判定：文件已存在 **且** 台账（gen_output）无该路径 md5 快照 **且** 内容有差异 → `protectedFile=true`。`overwrite=true` 默认 SKIPPED，`force=true` 才覆盖。内容一致的文件不算受保护（否则第二次 dryRun 出现无意义计数） |
| F-03 素材链路 | `GenScaffoldServiceImpl` | 恒写 `public/placeholder.svg`（前端）与 `src/main/resources/static/img/placeholder.svg`（后端，`/img/placeholder.svg` 开箱 200）；白名单常驻 `/img`、`/system/dict`、`/shop`；vue.config.js `/img` 代理不剥前缀 |
| F-04 品牌参数化 | `GenTemplateModel.resolveAppName/resolveThemeColor/resolveAppLogo` | 注入五处：index.html title+favicon+`--app-primary`、layout 品牌区、登录页、pom description、README 标题。品牌区二选一：有 Logo 用 `<img class="brand-logo">`，没有用首字 `<div class="brand-mark">` |
| F-05 字典脚手架 | `scaffold/dict.sql` + `dictControllerJava` | 恒写 `db/dict.sql`（两表 + sys_status/sys_yes_no/order_status 种子，`INSERT...WHERE NOT EXISTS` 幂等）+ `SysDictController`（JdbcTemplate，异常返回空列表）；前端字典 URL 从硬编码 `/api/system/dict/...` 改 `${apiRoot}`（全局接口不带模块段） |
| F-06 多图与尺寸 | `GenUtils.looksLikeMultiImageColumn` + `GenTemplateModel.IMAGE_LIST_SIZE/IMAGE_DETAIL_SIZE` | String 列名复数图片语义（`*_images/_pics/_photos/_gallery` 等）→ `multiImage`，判定先于单图；v-model 为 URL JSON 数组字符串，解析失败降级空数组；模板只消费 `${imageListSize}/${imageDetailSize}`（80/120），44/64/72 硬编码清零 |

测试产物归属修复（S8 实测踩出的缺陷，顺手收口）：`GenPathResolver.isBackendRelPath` 唯一实现，`src/main` 与 `src/test` 两侧都算后端——此前 `contains(backendBase + "/")` 把测试类与 schema 资源写成前端产物。详见坑库 `02-坑/测试与基线.md` #9/#10。

## 三、接口设计

| 接口 | 变更 |
|---|---|
| `POST /gen/apply` | 新增 `force`（默认 false）；`dryRun=true` 返回 `impact` 影响面（不再只有一句「不写盘」）；stage WRITE 文案 `dryRun：新增 %d，修改 %d，未变 %d，受保护跳过 %d（共 %d 个文件）` |
| `POST /gen/write` | 新增 `force`（受保护跳过的显式旁路） |
| `POST /gen/diff` | 每个 `GenDiffVO` 新增 `protectedFile` |
| `PUT /project` | 品牌三项可保存/可清空（null 写回） |
| `POST /gen/scaffold` | 新增 `appName`/`appLogo`/`appThemeColor` |

三档写盘策略与参数对应（`genStrategy.resolveWriteFlags`）：skip → `{overwrite:false,skipDrifted:false,force:false}`；safe → `{true,true,false}`；overwrite → `{true,false,true}`（唯一传 force 的档）。
