## 1. 表结构（迁移 SQL V4.4，仅 ADD COLUMN）

```sql
-- gen_platform
ALTER TABLE gen_table
  ADD COLUMN delete_cascade_mode TINYINT NOT NULL DEFAULT 1
  COMMENT '删除级联模式：0=阻止(有子行拒删) 1=级联(同删全部子表) 2=不处理(现状)';

ALTER TABLE sys_project
  ADD COLUMN default_delete_cascade_mode TINYINT NULL
  COMMENT '系统级默认删除级联模式，空=1(级联)';
```

### 2.1 保存接口的多子化语义（关键设计）

原 `save-with-children` 只有一张子表，多子化后**子表按组提交、组缺省不动**：

```
WithChildrenDTO {
  master: {主表 SaveDTO}
  {childVar}Rows: List<{child}SaveDTO>   // 每张子表一个可空字段
}
```

- 字段为 `null` → 该子表**不动**（前端只编辑某一张时不误清其他子表）
- 字段为 `[]` → 显式清空该子表
- 新增主单（id 空）时同事务先插主表再落各组；语义写进产物 readme
- 每组内部仍是全量替换（P1 增量保存另做），组内孙层沿用现有递归

### 2.2 生成的删除代码形态（按 mode 渲染）

- `mode=1`：`Map<String,Object> deleteWithChildren(Long id)` —— `@Transactional`，先 `removeById` 主行，再 `<#list children>` 逐张按外键 `delete(wrapper)`（逻辑删），返回 `{total, details:[{table, comment, rows}]}`
- `mode=0`：任一子表 `selectCount(eq fk, id) > 0` → 抛业务异常，msg=「存在明细：订单明细 3 行；操作日志 5 行，请先清空后再删除」；无行则走与 mode=1 相同的删除
- `mode=2`：维持 `removeById(id)` + `Result<Void>`，与 V4.3 产物逐字符一致

## 3. 接口设计（无新增接口，两处响应变化）

| 接口 | 方法 | 路径 | 请求 | 响应（变化点） |
|---|---|---|---|---|
| 主子详情 | GET | `/{资源}/{id}/with-children` | — | `data.children` 由 `[VO]` 改为 `[{key, tableName, comment, rows:[VO]}]`；`master` 不变 |
| 主子保存 | POST | `/{资源}/save-with-children` | `{master, {childVar}Rows?(每子表一个可空字段)}` | 原单 `children` 字段废弃，改每子表一个可空字段；null=不动、[]=清空 |
| 删除(mode=1) | DELETE | `/{资源}/{id}` | — | `Result<Void>` → `Result<{total, details:[{table, comment, rows}]}>` |
| 删除(mode=0) | DELETE | `/{资源}/{id}` | — | 有有效子行：业务异常（body.code≠0，msg 含各子表行数）；无行：同 mode=1 响应 |
| 删除(mode=2) | DELETE | `/{资源}/{id}` | — | 不变 `Result<Void>` |
| 批量删除 | DELETE | `/{资源}/batch` | `{ids:[]}` | 任一单被阻止 → 整批回滚，msg 定位到具体单据 |

约定核对：均沿用 `{code,msg,data}` 200 包装、无 `/api` 前缀、雪花 ID 字符串下发。

## 4. 契约测试（P0-5，7 → 12 例）

| 用例 | 断言不变式 |
|---|---|
| `cascadeDeleteMarksAllChildrenDeleted` | 多子表 mode=1 删主单，**每张**子表行 `deleted=1`，响应行数与库一致 |
| `cascadeDeleteReachesGrandChild` | 三级场景孙行同样 `deleted=1` |
| `blockDeleteRefusesWithActiveChildren` | mode=0 有有效子行删除失败，msg 含每张子表行数；子行 `deleted=0` |
| `mode2KeepsLegacyBehavior` | mode=2 删除后子行 `deleted=0`、响应为 Void 形态 |
| `detailWithChildrenReturnsAllChildren` | `/with-children` 返回全部子表，key/tableName/comment 齐全 |

基线：P0-1 后 36 份全绿（分道零变化）；P0-2 后新增场景 `master-multichild`（一主两子、其一含孙表）→ **48 份**，master-detail 产物随 children[] 循环化显式更新（`-Dgen.baseline.update=true`，提交说明写明）。
