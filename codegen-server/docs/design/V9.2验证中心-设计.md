# V9.2 验证中心 —— 设计文档

> 日期：2026-11-13　形态：CodeGen 控制台内嵌模块（非独立平台）
> 姊妹文档：[`V9.2测试中心-设计.md`](./V9.2测试中心-设计.md)（用例中心 `/test/*`）
> 范围：把平台**自身的验证资产**收拢成一次可追溯、可导出、可接入 CI 的运行；不写用例（那是用例中心职责）

---

## 一、定位与边界

一句话：验证中心是「平台的门禁驾驶舱」——它不创造测试，只把**已经存在**的验证脚本（单测、i18n 契约、语言键、前端构建、空库冒烟、产物断言、等价性）统一登记、一键执行、结构化留痕、报告可导出。

| 做 | 不做 |
|---|---|
| 套件注册表（S1–S9，服务端硬编码命令） | 不写用例、不写断言 DSL（那是用例中心） |
| 一键触发 / 并发单运行锁 / 取消 / 重跑 | 不做性能压测 |
| run / case / artifact 三层落库 | 不替代 CI；是 CI 的事实源之一（`codegen.testcenter/v1` 摘要） |
| 报告导出（json 契约 / html） | 不接成合并阻断门禁（V9.3 再评估） |
| 通过率趋势、残留运行收敛 | 不做缺陷跟踪 |

**与用例中心的根本区别**：

| 维度 | 用例中心 `/test/*`（test_* 七表） | 验证中心 `/tc/*`（tc_* 三表） |
|---|---|---|
| 资产归属 | 用户资产（编写/生成/执行接口&UI 用例） | 平台资产（平台自带的验证脚本） |
| 命令来源 | 用例 JSON 声明（method/path/asserts） | 注册表硬编码（仅 suiteId 可选） |
| 执行粒度 | 单用例 / 套件 | 套件（S1–S9） |
| 主要价值 | 业务链路回归 | 版本验收门禁、可追溯证据链 |

## 三、套件注册表（TcSuite 枚举，命令唯一来源）

这是执行器**唯一允许的命令来源**：请求体只能提交 `suiteId`，命令模板在服务端硬编码，因此不存在把前端字符串拼进 `ProcessBuilder` 的可能。

**设计原则（FR-01 安全红线）**：
- 统一驱动：`node scripts/testcenter-suites.mjs {suiteId}`，`WORK_DIR = serverRoot`（脚本内部自行切到 codegen-web）。
- 为何走统一驱动脚本：① Windows 上直接 spawn `mvn`/`npm` 的 `.cmd` 会踩 Node 18+ 的 `EINVAL`（坑库「测试与基线 #6」）；② shell 语法差异（`NODE_OPTIONS` 清空、路径分隔符）只在一处处理；③ CI 与本地执行器调用同一份套件定义，不产生「两套事实」。
- `argv()` 只替换 `{suiteId}`，且替换值来自枚举本身；`validate()` 对每个 argv 段拒绝 `; && | > < $` 等 shell 元字符。

## 四、功能设计

| 编号 | 功能点 | 位置 | 关键实现 | 验收标准 |
|---|---|---|---|---|
| F-V01 | 套件注册表视图 | `TestCenterService.suites()` | 返回注册表 + 最近一次运行各套件状态/耗时 | 前端看到 S1–S9 及上次结果 |
| F-V02 | 触发运行 | `trigger()` + `TestCenterExecutor.submit()` | 空 body=一键 P0 全量；`firstForbiddenKey()` 拦截 command/argv 注入字段→403；未知套件→400；全局锁占用→409 | 并发触发第二次立即 409 |
| F-V03 | 运行列表 / 详情 | `runs()` / `detail()` | 详情含 run + cases + artifacts + summary 反序列化 | 详情可展开失败套件日志 |
| F-V04 | 日志尾部轮询 | `log()` | 无 WebSocket；`TcPathGuard` 仅允许读 run 隔离目录；最多 2000 行 | 前端轮询不挂连接 |
| F-V05 | 取消 / 重跑 | `cancel()` / `rerun()` / `rerunFailed()` | 取消打断进程；单套件重跑沿用原 commit，trigger=RERUN | 取消后状态 CANCELLED |
| F-V06 | 报告导出 | `report(format)` | `json`=原始 summary；`html`=`TcReportRenderer` 渲染 | Jenkins/GitLab 可消费 |
| F-V07 | 产物下载 | `artifact()` | `TcPathGuard.resolve()` 路径白名单，越界→403 | 无法读取隔离目录外文件 |
| F-V08 | 趋势 / 概览 | `trends()` / `overview()` | `overview.activeRunId` 转字符串防雪花 ID 精度丢失 | 前端取消按钮拿到正确 ID |
| F-V09 | 启动兜底 | `recoverOnStartup()` | `ApplicationReadyEvent` 把残留 RUNNING 收敛为 TIMEOUT | 进程被杀不遗留永久转圈 |
| F-V10 | 权限与菜单 | `sys_menu` 3040 + 按钮 | 权限码 `tc:view` / `tc:run` / `tc:cancel` / `tc:export` | 无权限菜单不渲染、接口 403 |

## 五、执行引擎

| 项 | 设计 |
|---|---|
| 并发模型 | 全局单运行锁（`ReentrantLock`）；同一时刻仅一个 RUNNING，新触发立即 409 |
| 套件顺序 | 按注册表顺序**串行**；`dependsOn`（如 S5→S1）在注册表自检中约束 |
| 进程隔离 | 每个套件 spawn `node scripts/testcenter-suites.mjs {suiteId}`；超时按 `timeoutMinutes` 中断 |
| 落库 | 套件结束写 `tc_case_result` + `tc_artifact`；整次结束写 `tc_run.summary_json` |
| 路径守卫 | `TcPathGuard`：日志/产物读取只允许在 run 隔离目录内，防 `../` 穿越 |
| 残留收敛 | 启动兜底把 RUNNING 转 TIMEOUT，避免永久转圈 |
| 存储 | `TcResultStore` 接口，含 `JdbcTcResultStore`（落库）与 `InMemoryTcResultStore`（测试替身） |

## 六、Summary JSON 契约 `codegen.testcenter/v1`

本地执行器、CI 门禁脚本（`scripts/testcenter-summary.mjs`）、导出报告**共用同一份结构**，避免「本地绿、CI 红」两套判定。字段顺序固定，便于 diff：

```json
{
  "schema": "codegen.testcenter/v1",
  "runNo": "TC20261113-00101",
  "gitCommit": "v92-e2e",
  "status": "PASSED",
  "durationMs": 1884,
  "totals": { "total": 7, "passed": 7, "failed": 0, "skipped": 0 },
  "cases": [
    { "suiteId": "S1", "status": "PASSED", "durationMs": 920, "metrics": {"tests":"312/312"}, "logPath": "runs/TC20261113-00101/S1.log" }
  ]
}
```

- `TcSummary.recount()`：按 cases 重算 totals，并**保留终态语义**（人为取消=CANCELLED、超时=TIMEOUT，不一律压成 FAILED）。
- `TcSummary.validate()`：字段级合法性自检（schema 值、status 终态、totals 与 cases 一致、case 状态合法、套件已知），供单测与导出前调用。
- 新增字段必须同步改 CI 脚本与契约单测。

## 七、接口设计

统一前缀 `/tc`，响应体沿用平台 `Result{code,msg,data}`。

| 接口 | 方法 | 说明 |
|---|---|---|
| `/tc/suites` | GET | 套件注册表（含默认勾选、超时、依赖、上次结果） |
| `/tc/runs` | POST | 触发（body: suiteIds + trigger + gitCommit；空=一键 P0 全量） |
| `/tc/runs` | GET | 运行列表（分页） |
| `/tc/runs/{id}` | GET | 运行详情（run + cases + artifacts + summary） |
| `/tc/runs/{id}/log` | GET | 日志尾部轮询（caseId 可选） |
| `/tc/runs/{id}/cancel` | POST | 取消运行 |
| `/tc/runs/{id}/rerun` | POST | 单套件重跑 |
| `/tc/runs/{id}/rerun-failed` | POST | 仅失败项重跑 |
| `/tc/runs/{id}/report` | GET | 导出报告（format=json\|html） |
| `/tc/runs/{id}/artifact/{artifactId}` | GET | 产物下载（路径守卫） |
| `/tc/trends` | GET | 通过率趋势 |
| `/tc/overview` | GET | 概览（lastRun / busy / activeRunId 字符串） |

## 八、UI 设计

`src/views/verification/index.vue`，经 `require.context` 动态加载，**不改 `router/index.js`**。

| 区域 | 结构要点 |
|---|---|
| 套件卡片 | S1–S9 列表，P0/P1 胶囊标记，默认勾选 P0；显示基线、超时、上次结果 |
| 运行区 | 「一键运行 P0」/ 勾选套件运行；busy 态显示进度；取消按钮（activeRunId 字符串化） |

| 趋势 | 通过率折线、与 commit 关联 |

组件只用 `el-card` / `el-table` / `el-tag` / `el-button` / `el-drawer`，颜色沿用主题 `success/warning/danger`。

## 九、安全

| 项 | 措施 |
|---|---|
| 命令注入（FR-01） | 命令模板服务端硬编码，请求体禁止字段（command/argv 等）→ 403；argv 拒绝 shell 元字符 |
| 路径穿越 | `TcPathGuard` 白名单，日志/产物只允许读 run 隔离目录 |
| 雪花 ID 精度 | `overview.activeRunId` 与日志/产物回链均用**字符串**下发，避免 JS 截断 19 位号（坑库 spring-boot-3 #57/1653 同坑再现，已在 V9.2 补指针） |
| 权限 | 菜单 3040 + 按钮 3041/3042/3043，接入 `sys_role_menu` |
| 审计 | 触发/取消经 `@Log` 记入 `sys_oper_log` |

## 十、分期与验收

| 期 | 内容 | 状态 |
|---|---|---|
| M1 | DDL + 套件注册表 + 执行器 + REST API | ✅ 后端可 `POST /tc/runs` 跑完 S1–S7 并落库 |
| M2 | 并发锁 / 取消 / 重跑 / 日志轮询 / 产物下载 | ✅ 本机 17/17 端到端通过 |
| M3 | 门禁对齐 + 报告导出 | ✅ `verify.sh` 输出 JSON 摘要；`MIN_TESTS=312`；i18n 与语言键入 P0 |
| M4 | S8/S9 截图预览与新旧 jar 基线 diff | ⏸ 按 P1 默认不勾选，留待后续版本（如实未伪造通过） |

**已实现验收（本机）**：登录→套件视图→触发 S1–S9（P0 默认）→并发二次触发 409→安全拦截 403→雪花 ID 字符串化→三层落库→报告导出→产物下载，17/17 全通过；七步门禁 `verify.sh` RESULT PASS（6/6）。

## 十一、风险

| 风险 | 级别 | 对策 |
|---|---|---|
| S8/S9 人工链路未自动化 | 中 | P1 默认不勾选；如实记录未伪造通过，留 M4 |

| 启动残留 RUNNING | 中 | `recoverOnStartup` 收敛为 TIMEOUT |
| 命令/路径注入 | 高（已控） | FR-01 服务端硬编码 + argv 自检 + `TcPathGuard` 白名单 |
| 雪花 ID 精度丢失 | 高（已控） | 字符串下发，坑库已沉淀 |
