# V9.7 快速建表：两段式骨架生成 + 行业模板库 — 设计

> 版本：V9.7　|　日期：2026-11-16　|　状态：已实现（453 用例 0 失败，真模型实测 54s/3 表）

## 1. 背景与目标

本地 4B 模型（Qwen3-4B-Instruct，纯 CPU 5.2 tok/s）做完整建模时，每列要输出
`name/type/comment/pk` 四个字段，类型与 pk 占输出量大头，单模块 3 分钟级、
大型系统 1 小时以上。V9.7 从两条路把"出表"提速到可用级：

| 路径 | 机制 | 提速 |
|---|---|---|
| 两段式骨架生成 | AI 只列字段名+注释，类型/主键由命名语义规则补全 | 实测 3m13s → 54s（约 3.6×） |
| 行业模板库 | 预置电商/ERP/CRM/CMS 表结构包，选模块秒级克隆 | AI 0 参与秒级返回 |

## 2. 两段式骨架生成

### 2.1 第一段（AI）
- 新 prompt `SKELETON_SYSTEM_PROMPT`：输出
  `{"tables":[{"tableName","tableComment","fields":[{"name","comment"}]}]}`，
  禁止输出 type/pk/审计列。
- `AiModelService.modelSkeleton()`（纯新增方法，不改 V9.4 已有 `model()`）。
- 解析容错：`fields` 支持对象形态与纯字符串形态（`"order_no 订单号"` 自动拆名/注释）、
  `columns` 键回退。

### 2.2 第二段（规则补全，`TableSkeletonExpander`）
- 统一补 `id bigint pk` 到首位；列名归一（小写/空白转下划线/去重列）。
- 命名语义 → 类型口径表（见类注释）：`*_id→bigint`、`*_amount→decimal(12,2)`、
  `*_content→text`、`*_phone→varchar(20)`、`*_time→datetime`、`*_status→tinyint`、
  `*_num→int`、兜底 `varchar(255)`；守卫 `account` 不被 `count` 规则误判。
- 模型若自作主张给了 type，信任模型值。
- 审计列仍由建库阶段 `GenAuditColumns` 补齐，与完整模式同一约定。

### 2.3 接线
- `GenAiBuildPlanDTO.generationMode`：`skeleton`（默认）/ `full`。
- `AiTableRecommendServiceImpl.plan()` 与 `AiBuildJobServiceImpl.doModule()`（分批任务）
  均按该字段选 `modelSkeleton` / `model`——同步与分批两条路径行为一致。

## 3. 行业模板库

### 3.1 模板资产
- `resources/industry-templates/{ecommerce,erp,crm,cms}.json`，每个包若干模块，
  表结构与 AI 建模产物同形（`GenPipelineAiVO.TableModel`，含完整列定义 + pk id）。
- `IndustryTemplateRegistry`（@Component）启动时加载：单文件失败只告警；
  **key 冲突启动即失败**（资产冲突必须暴露）。

### 3.2 链路
- `GET /gen/ai-build/templates`：清单（key/name/desc/模块数/表数）。
- `POST /gen/ai-build/plan/template`：`GenAiTemplatePlanDTO`
  （templateKey/systemName/moduleNames 可选过滤/scope/projectId/scale/deploy）。
- 克隆走 **与 AI 完全相同的收口** `assemblePlan`：去重、补表差集（supplement 也支持）、
  关系视图（single/master/detail/tree）——前端第②③步零差异消费。
- 克隆是深拷贝：编辑器改表不污染常驻内存的模板资产。
- 返回 `GenAiBuildPlanVO.source = "template"`（默认 "ai"，前端可区分提示）。

## 4. 前端（`views/gen/aibuild/index.vue`）
- 第①步新增「建表方式」radio：行业模板（默认）/ AI 生成。
