# 代码生成器 V5.2 规划：流水线数据初始化（seed 步）

> 2026-10-24 起草。状态：**待确认范围后开发**。

## 二、主题与理由

**主题**：流水线新增 **seed（数据初始化）** 步——建库建表后自动为业务表灌入可用的中文示例数据。

**理由**：
1. 每个新系统都要手工造数才能演示/联调，是流水线体验的最后一块短板；
2. 平台已具备全部基础设施（AI、枚举解析、台账、重放模式），边际成本低；
3. 生成的系统「开箱即空」给演示方/验收方的观感差，有数据才算"完成交付"。

## 三、范围

### P0（本期必须）——规则引擎 + 步骤闭环

1. **seed 步接入流水线**：插在 `db` 之后、`scaffold` 之前；向导新增「数据初始化」选项：
   - `rule` 规则生成（默认）/ `sql` 自定义种子 / `off` 跳过；
   - `gen_pipeline` 加 `seed_mode` 字段（可空，回落 off）。
2. **规则生成引擎 `GenSeedGenerator`**：
   - **FK 拓扑排序**：按 information_schema 外键依赖先父后子；有环降级按台账顺序并告警；
   - **列类型驱动**：varchar/int/decimal/datetime/date/tinyint/text 各有生成策略；
   - **语义增强**：复用 enumMap 取合法枚举值；内置中文词库（人名/公司/城市/物料/部门/状态）按列注释关键词匹配（列名或注释含"姓名/联系人"→人名，"公司/供应商/客户"→公司名，"城市/地址"→地名…）；
   - **约束保证**：NOT NULL 无默认必填、唯一列加随机后缀（撞库重试 3 次）、长度截断、decimal 精度、bigint unsigned 边界；
   - **行数策略**：主数据表（mdm_*/sys_* 前缀）12 行；单据主表 8 行；**明细表跟随主表**（按指向主表的外键，每单 2~4 行）。
3. **幂等与重放**：插数前查表行数，非 0 跳过；生成结果落盘 `logs/pipeline/{no}/seed.sql`；「重新执行」时 0 行自动重放（同 db.sql 模式）。
4. **独立触发接口**：`POST /gen/pipeline/{id}/seed`——存量系统补跑（只对台账中且 0 行的表）。
5. **步骤报告**：seed 步摘要 = 每表插入行数 + 跳过原因（已有数据/无台账/失败容错表清单）；前端步骤卡片正常展示。

### P1（紧随其后）

6. **AI 语义生成**（seed_mode=ai）：按台账表结构分批（每批 3~5 表）调 AiModelService，产出 JSON 行 → 严格 schema 校验（类型/长度/枚举/必填）→ 不过的字段回退规则生成；单表失败不阻断整步。
7. **明细-主表数值一致**：明细表金额列 × 数量列 = 主表合计列（识别"合计/总额"注释）。
8. **自定义种子 SQL**：向导粘贴 INSERT（与规则生成叠加执行，先规则后自定义）。

### P2（ backlog ）

9. CSV/Excel 粘贴导入种子；
10. 列表页「再造一批」单表按钮；
11. 词库可配置（按项目维护语料）。

## 四、明确不做

- 生产数据迁移、脱敏导入（不同主题）；
- 万行级压测数据生成（性能主题）；
- 跨库/跨系统数据同步；
- 修改 AI 建模链路（seed 只消费台账，不反向影响建模）。

## 六、验收清单

- [ ] 新建流水线选「规则生成」，跑完后：主数据表 12 行、单据主表 8 行、明细行数 = 主表行数 × 2~4；
- [ ] 枚举列值全部落在注释映射内；唯一列无重复；NOT NULL 列无 NULL；
- [ ] FK 子表每行的外键值都存在于父表；
- [ ] 对跑完的系统再点「重新执行」：不重复插数（幂等）；
- [ ] DROP 库后重放：seed.sql 自动重灌（同 db.sql）；
- [ ] 存量系统（如 SCM 43 表）调独立接口补跑成功，登录后各列表页有数据；
- [ ] `mvn -o test` 全绿（新增生成器单测 + seed 契约测试）；
- [ ] seed_mode=off 的流水线行为与现在完全一致。

## 八、风险

| 风险 | 对策 |
|---|---|
| AI 生成越界（超长/错型/编造枚举） | 严格 JSON schema 校验 + 字段级回退规则生成（P1 才上） |
| FK 成环导致拓扑排序失败 | 检环降级台账顺序 + 告警，不阻断 |
| 唯一索引结构复杂（联合唯一） | 只对单列唯一做后缀策略；联合唯一失败重试 3 次后跳过该表并记入报告 |
| 明细跟随逻辑识别偏差（无外键的"伪明细"） | P0 只认真实外键；无外键表一律按普通表处理 |
| 大表量（43+）时 AI token 开销 | 分批 + 缓存；规则生成零成本兜底 |
