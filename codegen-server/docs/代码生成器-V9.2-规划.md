# 代码生成器 V9.2 规划 —— 测试中心（Test Center）

> **状态：已实现（V9.2）｜M1–M3 完成，M4 的 P1 项按计划未自动化**　｜　建立 / 更新：2026-11-13　｜　承接：V9.1（巨型类拆分）
>
> 延续「一版只做一件事」：V9.2 **只做测试中心**，不新增任何生成能力、不改模板字符串、不改平台控制台技术栈。
> V9.1 立下的**产物零 diff 契约**继续有效。

---

## 1. 为什么要做（现状证据）

平台目前**不缺验证能力，缺的是把它们收拢起来的地方**。逐项核过当前仓库：

| 验证能力 | 当前入口 | 结果去向 | 是否进统一门禁 |
| --- | --- | --- | --- |
| Java 单测 312 例 | `scripts/verify.sh` 阶段 1 + `.github/workflows/verify.yml` | `target/surefire-reports/`、`/tmp/verify-mvn.log` | ✅ |
| 测试数阈值 | `verify.sh` 的 `MIN_TESTS` | 控制台文本 | ✅ 但**阈值仍是 240**，实际已 312 |
| 生成物 JS 语法（1024 组合） | `scripts/check-generated-js.mjs` | `/tmp/verify-js.log` | ✅ |
| 控制台前端构建 | `codegen-web npm run build` | `/tmp/verify-web.log` | ✅ |
| 空库冒烟 | `scripts/smoke-fresh-db.mjs` | `/tmp/verify-smoke.log` | ⚠️ 默认关闭，仅 `--with-db` |
| i18n FTL 快照契约（9 模式 / OFF-ON 零 diff） | `scripts/i18n_snapshot/VuePageI18nContract.java` + `.github/workflows/i18n-contract.yml` | CI 日志 | ❌ 独立 workflow，未入 `verify.sh` |
| i18n-core 回落链单测（vitest） | `codegen-web/tests/i18n-core.test.mjs` | CI 日志 | ❌ 同上 |
| 206 语言键覆盖 | `scripts/check-locale-keys.mjs` | 无 | ❌ **未接任何门禁** |
| Vue3 生成物 40/40 断言、`vite build`、14 张页面截图（含 ar-SA RTL） | V9.0 人工验证链路 | 聊天记录 / 临时目录 | ❌ **未接任何门禁** |
| 新旧 jar 产物逐字节 `diff -r`（119 + 62 文件） | V9.1 人工双服务对比 | 临时目录 | ❌ **未接任何门禁** |
| 生成自检 `/gen/self-check`、`/gen/verify`、`/gen/scaffold/check` | 平台 REST API | 内存返回，不落库 | ❌ 无历史 |

`verify.sh` 头部自称「V7.4 P0-2 唯一门禁入口」，但 V8.0 / V8.1 / V9.0 / V9.1 之后新增的验证全在门外。由此产生 6 个具体痛点：

1. **门禁失真**：`verify.sh` 全绿 ≠ 版本验收通过，i18n 契约、Vue3 产物、截图、产物等价性没跑也可能显示 PASS。
2. **结果不留存**：一律写 `/tmp/verify-*.log`，换机/重启即丢；没有运行历史、趋势、责任人、与 commit 的关联。
3. **触发方式碎片化**：shell 脚本 / GitHub Actions / 手工命令 / 平台 API 四套，新人无法自助完成一次完整验收。
4. **没有用例级结构**：只有 PASS/FAIL 文本行，没有套件、耗时、失败堆栈、关联产物，排障靠翻日志。
5. **验收证据散落**：14 张截图、`diff -r` 报告、surefire XML 无法归档复现，版本评审拿不出一份完整报告。
6. **阈值过时**：`MIN_TESTS=240` 对 312 例形同虚设，少跑 72 个用例也不会失败。

> 结论：V9.2 不是"再写一批测试"，而是把**已有测试资产产品化**——统一登记、一键执行、结构化留痕、报告可导出。

## 2. 定位、目标与非目标

**一句话定位**：把散落在脚本、CI、命令行和手动截图里的验证能力，收拢成平台控制台里的一等公民「测试中心」：一个入口、一份结果模型、一条可追溯的证据链。

| 编号 | 目标 | 判据 |
| --- | --- | --- |
| G1 | 统一入口 | 控制台新增「测试中心」菜单，所有套件在同一页可见可触发 |
| G2 | 检查项可插拔 | 套件以枚举/配置注册，新增一个套件不改页面代码 |
| G3 | 一键全量 + 单项重跑 | 支持按 suiteIds 选择、失败用例单独重跑 |
| G4 | 结构化留痕 | run / case / artifact 三层落库，失败同样留日志与堆栈 |
| G5 | 报告可交付 | 一次运行可导出 HTML/JSON 报告，作为版本验收证据 |
| G6 | 本地与 CI 同一事实 | 执行器输出同一份 JSON 摘要契约，CI 不再另写一套判定 |

**非目标（V9.2 明确不做）**：

- N1 不改 `gen-templates` 任何模板字符串，不新增生成能力（产物零 diff）。
- N2 不把平台控制台 `codegen-web` 升级到 Vue3（本版仍 Vue 2.7 + Element UI）。
- N3 不引入 Quartz / Spring Batch / Jenkins / 分布式调度，不做多机并发。
- N4 不做 206 语言的自动翻译或翻译质量评分。
- N5 不改造 `GenScaffoldServiceImpl` 及 8 个 Writer，测试中心与生成链路零耦合。
- N6 不把测试结果直接接成合并阻断门禁（先观测一个版本，V9.3 再评估）。

## 3. 角色与用户故事

| 角色 | 场景 |
| --- | --- |
| 开发者 | 提交前点「全量运行」，几分钟内拿到通过率、失败套件、失败堆栈，不用记 4 套命令 |
| 维护者 | 对比最近两次运行，定位「哪个版本开始变红」，看耗时趋势与阈值漂移 |
| 评审者 | 打开一次 run 的详情页，直接看到 312/312、9/9、206/206、截图缩略图，导出报告归档 |

- US-1：作为开发者，我要一次触发全部 P0 套件，并实时看到当前跑到哪一步。
- US-2：作为开发者，某个套件失败时，我要只看它的日志与堆栈，不重跑全量。
- US-3：作为维护者，我要看最近 N 次运行的通过率/耗时趋势。
- US-4：作为评审者，我要把一次运行导出为自包含报告（含截图清单与 commit 号）。
- US-5：作为维护者，运行超时或进程被杀时，记录必须是 FAILED/TIMEOUT 而不是永远 RUNNING。

## 6. 数据模型（草案）

沿用平台约定：`bigint auto` 主键、`deleted` 逻辑删除、`create_time/update_time/create_by/update_by`、`utf8mb4`。
新增 3 张表，套件定义**不落库**（代码枚举，避免"库里的配置比代码新"的漂移）。

```sql
CREATE TABLE `tc_run` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `run_no` varchar(32) NOT NULL COMMENT 'TC+时间戳+序号，展示用',
  `trigger_type` varchar(16) NOT NULL COMMENT 'MANUAL / CI / SCHEDULE / RERUN',
  `suite_ids` varchar(512) NOT NULL COMMENT '逗号分隔，本次执行的套件',
  `status` varchar(16) NOT NULL COMMENT 'QUEUED/RUNNING/PASSED/FAILED/CANCELLED/TIMEOUT',
  `total` int NOT NULL DEFAULT 0, `passed` int NOT NULL DEFAULT 0,
  `failed` int NOT NULL DEFAULT 0, `skipped` int NOT NULL DEFAULT 0,
  `duration_ms` bigint DEFAULT NULL,
  `git_commit` varchar(64) DEFAULT NULL COMMENT '关联版本，便于追溯',
  `summary_json` longtext COMMENT '与 CI 共用的 JSON 摘要契约',
  `work_dir` varchar(512) DEFAULT NULL COMMENT '本次运行的隔离目录',
  `error_msg` varchar(1024) DEFAULT NULL,
  `deleted` tinyint NOT NULL DEFAULT 0,
  `create_time` datetime DEFAULT NULL, `update_time` datetime DEFAULT NULL,
  `create_by` varchar(64) DEFAULT NULL, `update_by` varchar(64) DEFAULT NULL,
  PRIMARY KEY (`id`), UNIQUE KEY `uk_run_no` (`run_no`), KEY `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='测试中心-运行记录';

CREATE TABLE `tc_case_result` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `run_id` bigint NOT NULL, `suite_id` varchar(32) NOT NULL,
  `status` varchar(16) NOT NULL COMMENT 'PASSED/FAILED/SKIPPED/TIMEOUT/CANCELLED',
  `duration_ms` bigint DEFAULT NULL,
  `exit_code` int DEFAULT NULL,
  `metrics_json` text COMMENT '如 312/312、9/9、206/206、1024 组合',
  `log_path` varchar(512) DEFAULT NULL,
  `error_excerpt` text COMMENT '失败堆栈尾部，便于列表直显',
  `started_at` datetime DEFAULT NULL, `finished_at` datetime DEFAULT NULL,
  `deleted` tinyint NOT NULL DEFAULT 0,
  `create_time` datetime DEFAULT NULL, `update_time` datetime DEFAULT NULL,
  `create_by` varchar(64) DEFAULT NULL, `update_by` varchar(64) DEFAULT NULL,
  PRIMARY KEY (`id`), KEY `idx_run_id` (`run_id`), UNIQUE KEY `uk_run_suite` (`run_id`,`suite_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='测试中心-套件结果';

CREATE TABLE `tc_artifact` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `run_id` bigint NOT NULL, `suite_id` varchar(32) DEFAULT NULL,
  `artifact_type` varchar(24) NOT NULL COMMENT 'LOG / REPORT / SCREENSHOT / SUREFIRE / DIFF',
  `file_name` varchar(255) NOT NULL, `file_path` varchar(1024) NOT NULL,
  `file_size` bigint DEFAULT NULL, `mime_type` varchar(64) DEFAULT NULL,
  `deleted` tinyint NOT NULL DEFAULT 0,
  `create_time` datetime DEFAULT NULL, `update_time` datetime DEFAULT NULL,
  `create_by` varchar(64) DEFAULT NULL, `update_by` varchar(64) DEFAULT NULL,
  PRIMARY KEY (`id`), KEY `idx_run_id` (`run_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='测试中心-产物索引';
```

**统一 JSON 摘要契约**（本地执行器与 CI 都输出它，避免两套事实）：

```json
{
  "schema": "codegen.testcenter/v1",
  "runNo": "TC20261113-001",
  "gitCommit": "2ffc550",
  "status": "PASSED",
  "durationMs": 412000,
  "totals": { "total": 9, "passed": 8, "failed": 0, "skipped": 1 },
  "cases": [
    { "suiteId": "S1", "status": "PASSED", "durationMs": 96000,
      "metrics": { "tests": 312, "failures": 0 }, "logPath": "runs/TC20261113-001/S1.log" }
  ]
}
```

## 7. REST 接口（草案）

统一前缀 `/tc`，返回沿用 `Result<T>` 包装，分页沿用 `PageQuery`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/tc/suites` | 套件注册表（含默认勾选、超时、依赖、上次结果） |
| POST | `/tc/runs` | 触发运行，body `{suiteIds[], trigger, gitCommit}`；已有运行进行中返回 **409** |
| GET | `/tc/runs` | 运行历史分页（status / 时间 / 触发人筛选） |
| GET | `/tc/runs/{id}` | 运行详情（含 cases 与 artifacts） |
| GET | `/tc/runs/{id}/log?caseId=&tail=200` | 日志尾部，前端轮询；不引 WebSocket |
| POST | `/tc/runs/{id}/cancel` | 取消运行（kill 子进程树，状态置 CANCELLED） |
| POST | `/tc/cases/{id}/rerun` | 单个失败套件重跑，生成新 run 并记 `trigger=RERUN` |
| GET | `/tc/runs/{id}/report?format=json\|html` | 导出报告 |
| GET | `/tc/artifacts/{id}` | 产物下载/预览（路径白名单校验，防目录穿越） |
| GET | `/tc/trends?limit=20` | 通过率与耗时趋势 |

## 8. 页面设计

**路由** `/tc/center`，菜单由 `sys_menu` 动态注册（现有 `constantRoutes` 只有 login/403/404，业务路由走 `/auth/routers`），按钮权限走 `sys_role_menu`，操作写 `sys_oper_log`。

```
┌─ 测试中心 ────────────────────────────────────────────────┐
│ 总览卡：最近一次状态 | 通过率 | 失败数 | 总耗时 | git commit │
│ [全量运行]  [仅失败项]  [导出报告]                          │
├──────────────┬────────────────────────────────────────────┤
│ 套件列表      │ 运行历史表格                                │
│ ☑ S1 单测    │ runNo / 触发 / 状态 / 通过率 / 耗时 / 操作   │
│ ☑ S2 契约    ├────────────────────────────────────────────┤
│ …            │ 详情抽屉：用例结果 · 实时日志 · 截图 · 堆栈   │
│ ☐ S8/S9 重项 │                                            │
└──────────────┴────────────────────────────────────────────┘
```

**状态机**：`QUEUED → RUNNING → PASSED | FAILED | CANCELLED | TIMEOUT`；单套件另有 `SKIPPED`（如无 MySQL 的 S7）。
**兜底**：服务重启时把残留 `RUNNING` 的运行置为 `TIMEOUT` 并补 `error_msg`，杜绝"永远转圈"。

## 9. 技术方案与硬约束

- **后端**：Java 21 / Spring Boot 3.2.5 / MyBatis-Plus 3.5.5；新增 `controller/TestCenterController` + `service/TestCenterService` + `TestCenterExecutor`，不与生成链路共享 Bean。
- **执行器**：`ProcessBuilder` 调本地脚本，工作目录 `${app.test-center.workdir}` 默认 `~/.codegen/test-center/runs/{runNo}`；单线程 + `ReentrantLock` 保证全局一次只跑一个 run；超时 kill 进程树。
- **安全红线**：命令只能来自服务端 `TcSuite` 白名单，**任何来自请求体的 command / path 参数一律拒绝并记审计**；产物读取做路径白名单，防目录穿越与 RCE。
- **环境坑复用**：Windows 下清空 `NODE_OPTIONS`（`verify.sh` 已踩过 fs shim 坑）；`/tmp` 路径不跨平台，日志一律落到 workdir；`mvn clean` 被 IDE 锁 `target/classes` 时降级为只清 surefire 报告。
- **前端**：Vue 2.7 + Element UI（沿用现状），页面放 `codegen-web/src/views/test-center/`；不引新 UI 库、不引 WebSocket，日志用 2s 轮询。
- **不引入**：Quartz、Spring Batch、消息队列、ElasticSearch；结果检索靠 MySQL 索引即可。
- **产物零 diff**：V9.2 不碰 `src/main/resources/gen-templates/`，`gen-baseline` 23 个快照不应产生任何变化。

## 10. 验收标准（可量化）

1. 一键 P0 全量运行全绿：**312/312** 单测、**9/9** i18n 快照契约、**9 passed** i18n-core、**206/206** 语言键、**1024 组合 0 坏**、前端 build 成功。
2. 结果落库率 **100%**：含失败、超时、取消的运行都有 run/case/log 记录，无残留 RUNNING。
3. 同一 run 的 JSON 摘要在本地与 CI 字段级一致（`schema=codegen.testcenter/v1`）。
4. **产物零 diff**：V9.2 合并前后，同一 DTO 生成的产物 `diff -r` 为空；`gen-baseline` 快照 23 个文件不变。
5. 单运行锁生效：并發第二次 `POST /tc/runs` 返回 409，且不会启动第二个子进程。
6. 安全：传入自定义 `command`、`filePath=../../` 均被拒绝且写审计日志。
7. 新增单测 **≥ 20**（执行器状态机、超时/取消、JSON 契约、白名单、残留运行恢复）。
8. 报告可导出：单次 run 的 HTML 报告包含摘要、用例表、日志尾部与截图清单，可离线打开。
