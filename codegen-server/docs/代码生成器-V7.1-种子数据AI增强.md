# 代码生成器 V7.1 —— 种子数据 AI 增强：AI 管语义，规则管结构

> 日期：2026-11-04　状态：已实现
> 依赖：`AiModelService`（OpenAI 兼容通道）、`GenSeedGenerator`（V5.2 规则引擎）、pipeline seed 步。

## 一、问题

V5.2 种子数据的词库是写死的通用值（人名"张伟"、公司"华信科技"、商品"不锈钢板材"），
不管目标系统是商城、医院还是物流，灌出来的示例数据都一样——"不符合实际业务"。

## 二、方案：AI 只换取值来源，不产出行数据

- **AI 负责**：根据系统名/描述 + 表/列注释，生成业务贴合的语义值池：
  - 九个类别池：persons / companies / cities / streets / depts / products / titles / remarks / specs；
  - 列级覆盖：`{"表名.列名": [候选值...]}`，只给核心业务列（品名/标题类）。
- **规则引擎继续负责**（不变）：外键取父表实际 id 区间、唯一列序号后缀、注释枚举解析、
  varchar 按字符截断、金额/时间/手机号格式、行数策略（主数据 12 / 单据 8 / 明细跟随）。
- 由此保证：AI 输出再离谱也只会影响"值好不好看"，SQL 永远合法、外键永远不悬空。

## 三、实现要点

| 项 | 说明 |
|---|---|
| `SeedValuePools` | 值池载体；`defaults()` 与 V5.2 词库逐字一致（降级基线零行为差）；`of()` 清洗：去空白/去重/单值≤100 字/单池≤24 项/覆盖≤200 条，非法项回落默认词库 |
| `AiModelService.seedPools` | 分批（15 表/次）调用，各类别合并去重；JSON 模式（response_format=json_object）+ temperature 0.6（同既有坑：0.2 会重复循环）+ `/no_think` 尾置 |
| `GenSeedGenerator` | `seedPipeline/seedFor/valueFor/textFor` 增加 pools 重载；列级覆盖只对文本列生效，且**先按列长预留后缀空间截断再拼唯一后缀**（顺序反了后缀会被截掉，单测抓过） |
| `PipelineExecutor.stepSeed` | seedMode=ai 时：`loadTableMeta(dbName)` → `seedPools(...)` → 传池生成；任何异常回落 `defaults()` 并在步骤消息注明"AI 增强失败已回落规则词库"，seed 步永不因 AI 中断 |
| 白名单 | `GenPipelineCreateDTO.seedMode` 支持 rule / ai / off；`GenPipelineServiceImpl` 落库放行 ai |
| 前端 | pipeline 向导加「AI 增强（贴合业务）」单选项，注明需配置 pipeline.ai |

## 四、验收（对应测试 `GenSeedGeneratorTest` 21 例全绿）

- 列级覆盖生效且大小写不敏感；覆盖值按 varchar 截断且唯一后缀保留
- 语义类取 AI 池；defaults() 基线与 V5.2 词库逐字一致
- 非法 AI 输出被清洗/回落；单池上限 24 生效

## 五、明确不做

- AI 直接生成 INSERT 语句（结构约束失守，弃）
- AI 生成数值/时间/手机号（规则格式化更可靠）
- seed 步 AI 失败重试（降级原则：回落即成功，不阻断流水线）
- 存量补跑 `/seed`（V5.2 接口）接 AI（保持规则语义，幂等补数）
