# 代码生成器 V6.1 规划 —— 集成 Activiti 工作流引擎

> 日期：2026-10-25　状态：规划待过目
> 与 V6.0（微服务设施）无代码耦合，可先可后。编号顺延为 V6.1。
> 前置：无硬性前置；若与 V6.0 同期实施，建议先本版（工作流是业务功能，微服务是设施，用户感知优先级更高）。

## 一、现状核对（2026-10-25 实测）

| 项 | 现状 | 位置 |
|---|---|---|
| 自研审批流 | **状态机式**：`sys_flow_def` 节点 JSON 定义 from→to 流转、角色校验、`rejectTo` 驳回（缺省回草稿）、`FlowRecord` 审批记录 | `FlowServiceImpl`（298 行）、`common/flow/FlowRecord` |
| 产物侧端点 | 绑定 `flow_code` 的表自动生成 `/flow/submit/{id}`、`/flow/approve/{id}`、`/flow/reject/{id}`、records/state | `controller.ftl:557-580` |
| 绑定入口 | `gen_table.flow_code`（V2.2），表配置可挂流程编码，空为不启用 | `V2.2__flow_code.sql` |
| 流程管理 | `sys_flow_def` / `sys_flow_node` 管理页已有（流程编码、节点 JSON 手工维护） | V2.0 建表 |
| 引擎能力缺口 | 无会签/或签、无并行网关、无委派/转办/加签、无待办中心、无 BPMN 流程图、历史查询弱（只有线性 FlowRecord） | — |
| 产物技术栈 | Spring Boot 3.2.5 / Java 21（Jakarta 命名空间） | 产物 pom |
| **引擎兼容线** | **Activiti 7.x 是 javax 时代（Boot 2.x），Boot 3 必须用 Activiti 8.x**（8.x 要求 Java 17+，与产物 Java 21 兼容） | 官方开发者指南 |
| **仓库风险** | **Activiti 自 7.1.x 起不再发布 Maven 中央仓库**，仅发布 Alfresco 私有仓库（artifacts.alfresco.com）——产物 pom 须额外加 `<repositories>`，离线/内网编译会断 | 官方开发者指南、社区实测 |
| Flowable 备选 | Flowable 7.x 在中央仓库、原生 Boot 3 支持，是 Activiti 原班团队的 fork，国内生态与文档更广 | — |

**问题**：V2.2 简易流只能表达「一条直线状态机」。真实审批诉求（多人会签、按条件走不同审批人、审批人转办、我的待办/已办、流程图查看、完整历史）全部没有，且 `sys_flow_node` 手工写 JSON 的维护方式对非开发者不友好。

## 二、主题与理由

**主题：`flow_engine` 双引擎——表绑定流程后可切换「内置简易流 / Activiti 引擎」两种实现，产物接口不变；M1 由流程节点定义自动生成 BPMN 流程并部署，交付待办中心与完整审批历史。**

理由：

1. V2.2 的 `flow_code` 绑定钩子已就位、产物三端点契约已稳定——缺的只是引擎实现，接口零改动可平滑切换；
2. 节点 JSON（from/to/roleCode/rejectTo）与 BPMN UserTask/ExclusiveGateway 语义同构，**自动翻译成 BPMN 可行**，用户无需学 BPMN 建模就能吃到引擎能力；
3. 用户明确点名 Activiti；8.x 兼容线已查实（Boot 3 → Activiti 8），不是纸面规划。

## 三、范围

### P0-1 引擎依赖与双实现骨架（产物侧）

- 产物 pom 增加 `activiti-spring-boot-starter:8.x`（BOM 统一管理），pom 模板追加 Alfresco `<repositories>`；`db` 步建表时附带执行 ACT_ 建表 SQL（从引擎 jar 提取，幂等可重放，模式照搬 `seedSql`）
- `sys_project` 增加 `flow_engine` 配置（`builtin` 缺省 / `activiti`），产物脚手架按值装配 `FlowService` 实现：`BuiltinFlowService`（现有逻辑抽接口保留）/ `ActivitiFlowService`（新实现，内部走 RuntimeService/TaskService/HistoryService）
- **产物对外端点契约不变**：controller.ftl 零改动，切换引擎对前端透明
- 安全对接：Activiti 8 内置 Spring Security 集成须关闭/替换，统一走产物现有 AuthContextFilter token 体系（`activiti.spring-boot.security` 自动配置排除 + 身份桥接 `Authentication`→引擎 `IdentityService`）

### P0-2 流程定义自动翻译与部署

- `sys_flow_def` 节点 JSON → BPMN 2.0 XML 翻译器（单一实现 `GenBpmnBuilder`）：顺序 UserTask 链 + ExclusiveGateway 条件分支（节点配了 `condition` 时）+ 驳回边界事件/回退网关；`candidateGroups` 映射 `roleCode`
- 部署时机：流水线 `db` 步后新增子步（或并入 scaffold 前置）——翻译 + `RepositoryService.deploy`，幂等（按 flow_code+版本 key 去重）；平台侧提供 `POST /gen/flow/{id}/deploy-bpmn` 手工重部署
- BPMN XML 落台账（`sys_flow_def.bpmn_xml` 列），可导出、可审计「生成的流程长什么样」

### P0-3 待办中心与审批历史（产物侧）

- 新增产物端点：`GET /flow/todo`（我的待办，TaskService 按候选人/候选组查询）、`GET /flow/done`（我已办，HistoryService）、`GET /flow/task/{taskId}`（任务详情+业务单据聚合）
- 审批历史升级：引擎 `ACT_HI_TASKINST`/`ACT_HI_ACTINST` 为主，`FlowRecord` 保留为兼容视图（双写或视图查询，M1 选视图查询避免双写不一致）
- 前端新增「待办中心」菜单页：待办/已办两个 tab、审批弹窗（通过/驳回/意见）、审批记录时间线组件（复用 V4.5 打印页的样式体系）

### P0-4 流水线与自检接线

- 自检增加引擎健康项：流程部署数、引擎表存在性；`lint` 报告展示「N 个流程已部署」
- 人事系统作为验收样板：`leave_request` 绑定流程切换 activiti 引擎端到端走通

### P1（本版尽力，不做门禁）

- 流程图只读渲染（bpmn-js CDN 或静态导出 SVG + 当前节点高亮）
- 会签/或签：BPMN 多实例（multi-instance）配置项，节点 JSON 加 `countersign: all|any`
- 委派/转办端点（`taskService.delegate`/`setAssignee`）+ 前端按钮
- 超时自动处理：BoundaryTimer + yml 配置默认超时策略

### P2（明确不做，下版再说）

- 可视化流程设计器（bpmn-js 编辑态）——M1 用「JSON 定义自动翻译」覆盖 90% 直线流程，设计器等真实诉求
- 引擎独立微服务部署（流程中心集中化）——等 V6.0 微服务设施落地后再评估
- 流程版本迁移（存量实例升级到新版本定义）
- 多租户、消息中心集成（站内信/邮件/企微通知）

## 四、关键设计决策

| 决策点 | 定案 | 理由 |
|---|---|---|
| 引擎版本 | **Activiti 8.x**（8.4+，Java 17+/Boot 3 线） | 用户点名 Activiti；7.x 是 javax 不兼容产物 Boot 3.2.5，8.x 是唯一兼容线 |
| Alfresco 仓库风险 | pom 模板内置 `<repositories>` + 平台 `.m2` 预拉全量依赖进私仓/本地；自检加「依赖可解析」检查项 | Activiti 制品不在中央仓库是最大交付风险；产物必须保证离线可编译（与 V4.2 产物可信化原则一致）。**备选逃生门：若 Alfresco 仓库稳定性差，切换 Flowable 7.x（中央仓库直供，API 同源 fork，改造成本集中在 import 包名）——本版不改引擎，只在设计上保持 FlowService 接口隔离使切换可行** |
| 双引擎 vs 替换 | 双实现并存，`flow_engine` 系统级开关，缺省 `builtin` | 简易流零依赖、够用场景不强制引擎；已有产物行为不回退（V4.4 级联模式三态的同款决策模式） |
| 流程定义来源 | M1 不做设计器，`sys_flow_def` 节点 JSON 自动翻译 BPMN | 节点 JSON 与 BPMN 语义同构，翻译器是单一实现；用户零学习成本吃到引擎能力；设计器 P2 再说 |
| 引擎嵌入位置 | 引擎内嵌产物（每系统自带） | 与「产物独立交付」原则一致；集中式流程中心是 P2 话题，等 V6.0 |
| 安全对接 | 排除 Activiti 自动装配的 Spring Security，身份经 IdentityService 桥接 | 产物鉴权已统一在 AuthContextFilter，双安全体系必然打架 |
| 历史数据 | 引擎 ACT_HI_* 为主，FlowRecord 视图兼容 | 避免双写不一致；旧数据仍可读 |

## 五、验收标准

1. 新建系统选 `flow_engine=activiti`，`leave_request` 绑定 `hr_leave_flow`（3 节点：主管审批→人事复核→结束）→ 流水线跑通，日志可见 BPMN 部署成功
2. 提交请假单 → 待办中心出现该任务（主管角色登录可见）→ 通过 → 流转到人事复核节点 → 驳回 → 状态回草稿，全程状态流转与 `sys_flow_def` 定义一致
3. `ACT_HI_TASKINST` 可查完整审批历史；旧 `/flow/records` 接口返回兼容视图数据
4. 同一系统切回 `flow_engine=builtin` 重新生成 → 行为与 V2.2 完全一致（回归零 diff）
5. 产物拷贝到无网环境 `mvn clean package` 成功（Alfresco 依赖已落本地库）
