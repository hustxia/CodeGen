## 二、V3.1 范围（建议）

主题：**多系统闭环 + 第一次有自动化测试**。

选这个主题的理由：V3.0 把「系统」这层对象建起来了，但一半链路没接上。现在做新功能（如逆向生成、CI）只会把未接的洞越挖越深。而缺口 2、3 都属于「同一份代码两个系统互相覆盖页面」这类静默错误，比功能缺失严重。

### P0-1 写盘回落验证（0.5 人日）

缺口 1 已改代码，但没验证。要做：

- 建第二个系统 `mkt`，`backendRoot` 指向另一个空目录
- 表挂到 `mkt`、表级清空，执行**真实写盘**（不是预览）
- 断言文件落在 `mkt` 的目录，不在 `demo-target`
- 覆盖四种组合：表级有值 / 系统有值 / 模块有值 / 全空

验收标准：预览路径集合与落盘路径集合必须完全一致。这条以前没人验过，是同类 bug 的根。

### P0-2 菜单路径与前端工程按系统隔离（1.5 人日）

改动点：

- `joinPath(parentPath, module, leaf)` → 传入系统编码参与拼装，形如 `/{projectCode}/{module}/list`
- `webBase()` → 改为 `webBase(GenTable)`，回落链：系统 `frontendRoot` + `frontendPath` → 全局
- `viewsRoot()` 同步改造，路由同步按系统定位 `src/views/`
- `componentOf(table)` 同步带系统前缀，否则组件路径还是撞

兼容策略（关键）：**存量菜单不动**。库里 7 张表目前 `menu_id` 全为 NULL，尚未注册过菜单，所以这次改动实际零迁移成本。但代码里仍要写兼容——已注册的表（`menu_id` 非空）跳过路径推导，直接沿用库里路径，避免以后有人升级时页面 404。

验收标准：

- 两个系统各挂一张 `demo_goods`，注册后菜单 path 分别为 `/default/demo_goods/list`、`/mkt/demo_goods/list`
- 路由同步各写进自己的前端工程 `src/views/` 与 `router/`
- 已注册菜单重复注册时不被改写路径

### P0-3 系统级生成开关默认值（1 人日）

`sys_project` 加 16 个 `default_gen_*` 列（或用一张 `sys_project_gen_default` 子表，倾向于加列——16 列固定不变，子表反而多一次 join）。

回落链：表级 → 系统 → 硬编码 1。

为什么要这个：现在 `gen_log` 全库默认 1，意味着每张表都生成操作日志代码。新系统若不需要，得逐表取消勾选。反过来说某系统要求全量生成时也一样。

实现要点：

- 「从数据库导入」时按系统默认值填表，而不是一律填 1
- 前端表配置弹窗要能看出「这个值是系统给的默认，还是我改过」，建议用 placeholder 提示 + 「恢复系统默认」小按钮

### P1-1 第一次自动化测试（2 人日）

现状：`src/test` 下 0 个 java 文件，全靠 `TplRenderCheck.java` 这个手写 main 方法跑 63 条断言。

要做的最小集：

1. **把 `TplRenderCheck` 转成 JUnit 5 测试**（`@ParameterizedTest` 跑多套 ProjectConfig），纳入 `mvn test`，不再靠手动 `java -cp`
2. **回落链单测**：`GenCodeServiceImpl` 的四个 `*Of(table)` 方法，参数化覆盖「表级有/系统有/模块有/全空」×4 个字段 = 至少 12 个用例
3. **权限点/字典编码一致性测试**：断言 `GenMenuServiceImpl.permsPrefix`、模板渲染结果、`GenSelfCheckServiceImpl.permsPrefixOf` 三者对同一张表输出相同字符串。这三处一旦不同步就是静默 bug（V2.0 已经踩过一次）

先做这 3 组，不追求覆盖率数字。理由：代码生成器的 bug 类型高度集中，就是「回落顺序错」和「三处规则不一致」，这两类用参数化测试能一次锁死。

### P1-2 模板集按系统绑定（1.5 人日）

`gen_template` 加 `project_id`（NULL = 全局默认集）。

回落：表级 → 系统 → 全局。

风险提示：这会让「改模板」的语义变复杂——用户改的是全局模板还是本系统模板？前端模板管理页需要明确的作用域切换器（Tab：全局 / 某系统）。如果暂时没有「两个系统规范不同」的真实需求，**建议降级到 P2**，先不做。

### P2-1 系统配置复制（0.5 人日）

新建系统时可选「从某系统复制」，只复制路径类字段，不复制编码和名称。

价值不高但成本极低，顺手做。

## 三、明确不做的事

| 项 | 不做理由 |
|---|---|
| 系统级独立模板语法 | FreeMarker 模板一套足够，多套维护成本远超收益 |
| 跨系统表迁移向导 | 改 `project_id` 一个 UPDATE 的事，做个向导反而绕 |
| 系统级权限隔离（谁能看哪个系统） | 当前是单团队内部工具，`sys_role` 维度已够；真要多租户得重做鉴权，不该塞进 V3.1 |
| 逆向生成（从代码反推配置） | 独立主题，且依赖本次测试基建先落地 |

## 六、V3.1 交付记录（2026-10-22）

### 代码改动

| 项 | 落点 |
|---|---|
| P0-1 路径回落收敛 | 新增 `support/GenPathResolver`：四级回落只有一个实现，预览/写盘/差异/ZIP/路由同步全部调它；`applyOutputDefaults` 不再回填 backendRoot/frontendRoot（那是藏 bug 的地方） |
| P0-2 菜单与前端工程隔离 | `GenMenuServiceImpl`：`joinPath` 加系统编码段 → `/mkttest/dict_data/list`；`fillRoute` 按「前端工程根」分组重建，每套系统写自己的 `gen-routes.js`；`webBase` 改走 `GenPathResolver`，与写盘共用同一份解析 |
| P0-3 系统级开关默认值 | `V4.1__project_gen_defaults.sql`（17 列）；`support/GenSwitchDefaults`；导入/新建按「系统 → 1」补空值；`POST /gen/table/{id}/switch-defaults/reset`；详情带回 `projectGenDefaults`；前端表配置弹窗「默认」标记 + 恢复按钮，系统管理页可直接编辑 17 个默认值 |
| P1-1 自动化测试 | `src/test` 下 4 组共 **37 个用例**（GenPathResolver / GenSwitchDefaults / GenNamingConsistency / TplRenderTest），`mvn test` 可跑；`TplRenderCheck.java` 已删除（功能并入 TplRenderTest）。surefire 去掉硬编码 skipTests，`package -DskipTests` 流程不变 |
| P2-1 配置复制 | `POST /project?copyFrom=`：只复制路径类字段 + 17 个开关默认值，编码/名称/根包名/网关前缀不复制 |
| 三方命名收敛 | 权限点/字典编码规则统一到 `support/GenNaming`，菜单、模板模型、自检、字典识别四处全部改为调用它（模板模型原来没有 toLowerCase，正是隐患） |

### 实机验证（gen_platform 库 + 临时系统 mkttest，验证后已清理）

- 真实写盘：8 个后端文件全部落在 `mkttest` 系统的 backendRoot，无一写进 demo-target
- 预览路径集合 == 落盘路径集合（8 == 8，逐条比对）
- 菜单 dryRun：path = `/mkttest/dict_data/list`（系统编码前缀生效）
- 路由同步：`mkttest-web/src/router/gen-routes.js` 生成且只含本系统页面；demo-web 的路由文件未被波及
- 导入表：`default_gen_frontend=0` 正确落进 gen_table.gen_frontend，其余开关为 1
- 恢复系统默认：17 开关按系统默认值重写，project_id 保持不变

### 验证抓出的真 bug（已修）

`GenTable.projectId` 是 `FieldStrategy.IGNORED`（为了支持解绑系统），导致**任何部分更新都会把 null 写进库**：
批量套预设一次就把整批表的系统归属清空，生成路径当场回落到全局——正是「文件写进别的仓库」的另一个入口。
修复：`batchUpdate` / `resetSwitchDefaults` 部分更新时显式带回原 projectId。

### 顺手的小改进

- 表配置弹窗补上一直缺失的「操作日志」开关（实体有 genLog 但 UI 从未暴露）
- 系统管理页支持 `/gen/project?create=1` 深链直接打开新增弹窗

### 未做（按计划延后）

- P1-2 模板集按系统绑定：等出现「两套系统模板规范不同」的真实需求再做
