# 开源协议与商业授权边界说明

> 建立日期：2026-11-26　｜　适用仓库：`codegen-server` / `codegen-web`　｜　权威源：仓库根目录 `LICENSE`
>
> **一句话结论：本项目唯一开源协议是 MulanPSL-2.0（木兰宽松许可证第 2 版），商业授权书引用 MulanPSL-2.0 作为核心代码许可 + 单独一份商业模块授权协议；任何材料不得再出现 Apache-2.0。**

## 一、为什么必须统一

历史遗留：`LICENSE` 文件自始是 MulanPSL-2.0，但 README 徽章、HelloGitHub 投稿文档写的是 Apache-2.0。
两者都是宽松协议，但**不是同一份文本**，授权条款、专利条款、分发声明义务都不同。
客户法务做尽职调查时，发现 `LICENSE` 与 README 徽章不一致，会直接要求解释或退回合同。

**2026-11-26 已修正：**

| 文件 | 原表述 | 现表述 |
| --- | --- | --- |
| `README.md` 第 5 行徽章 | `License: Apache-2.0` | `License: MulanPSL-2.0` |
| `README_ZH.md` 第 5 行徽章 | `License: Apache-2.0` | `License: MulanPSL-2.0` |
| `docs/marketing/hellogithub-submission.md` | 两处 `Apache-2.0` | `MulanPSL-2.0（木兰宽松许可证第 2 版，宽松许可，可商用）` |
| `codegen-server/LICENSE` | MulanPSL-2.0 | 未改（本来就是权威源） |
| `codegen-web/LICENSE` | MulanPSL-2.0 | 未改（与后端一致） |

校验命令（应在任何发布前跑一次，期望输出为空）：

```bash
grep -rn 'Apache-2.0\|Apache 2.0\|Apache License' \
  README.md README_ZH.md docs/marketing src/main/resources docs/ \
  --exclude='*.html'
```

> 注：`package-lock.json` 里的 `Apache-2.0` 是第三方依赖自身的协议，**不属于本项目声明**，不要改。

## 二、MulanPSL-2.0 对商业化意味着什么

按 `LICENSE` 原文逐条对照：

| 条款 | 原文要点 | 商业含义 |
| --- | --- | --- |
| 第 1 条 | 永久性、全球性、免费、非独占、**不可撤销**的版权许可 | 已开源的核心代码收不回来。任何人都可合法商用、修改、闭源衍生。**不能对已公开的核心代码再收授权费** |
| 第 2 条 | 同等范围的专利许可；发起专利诉讼则终止 | 专利有"反制条款"。商业合同不要附加"不得起诉专利"之类的额外限制，会与开源许可冲突 |
| 第 3 条 | **不提供商标许可** | "码匠 CodeGen"名称、Logo、演示站品牌不受开源许可覆盖。这是可保留、可授权的商业资产，建议尽早注册商标 |
| 第 4 条 | 分发须附许可证副本，保留版权/商标/专利/免责声明 | 商业版若打包分发开源核心，必须原样保留 LICENSE 和声明头，不能删 |
| 第 6 条 | 中英文冲突以**中文版**为准 | 授权书引用协议时写"木兰宽松许可证第 2 版（MulanPSL-2.0，中文版为准）" |

## 三、三层货架的授权边界

| 层级 | 内容 | 许可 | 能否收费 |
| --- | --- | --- | --- |
| **开源核心** | `codegen-server` / `codegen-web` 已公开全部代码、12 步流水线、能力包模板、254 套行业模板 JSON | MulanPSL-2.0 | ❌ 不能再收授权费。免费、可商用、可闭源衍生 |
| **商业模块（新增）** | 独立目录/独立仓库的闭源模块：工作流设计器高级版、数据权限配置台、AI 私有化建模、模板市场全量包、审计与 SSO 等 | 独立商业授权协议 | ✅ 按席位/年订阅或买断 |
| **服务与内容** | 1v1 技术支持、私有化部署实施、定制交付、培训、行业模板定制 | 服务合同 | ✅ 按人天/项目收费 |

**红线：**

1. **不要把核心代码"重新授权"收费。** 已经按 MulanPSL-2.0 放出去的代码，永久免费不可撤销，再收费在法律上站不住，在社区会被反噬。
2. **商业模块必须在物理上可区分。** 独立目录/独立仓库、独立 LICENSE 文件、独立构建产物。不要把闭源文件混进 `src/main/java/com/codegen`，否则边界说不清。
3. **模板包要分清"已开源"和"新增"。** 254 套行业模板 JSON 已在 `src/main/resources/industry-templates/` 公开，属于开源核心，**不能拿出来单独卖**。可售卖的是新增的、未公开的行业包，或是基于模板的定制服务。
4. **品牌/商标单独保护。** 开源许可不覆盖名称与 Logo，商业版可用品牌做差异化，但要在商标局注册才有排他权。

## 四、商业授权书怎么引用

推荐口径（写进授权书/订单/合同首部）：

> 本产品由两部分组成：
> （1）**开源核心**：依据木兰宽松许可证第 2 版（MulanPSL-2.0，中文版为准）授权，永久、全球、免费、不可撤销；
> （2）**商业模块**：由著作权人另行授权，依据本商业授权协议及订单约定使用。
>
> 开源核心的完整许可文本见随附 `LICENSE` 文件；商业模块的授权范围、期限与席位以订单为准。

**禁止出现的表述：**

- ❌ "本项目采用 Apache-2.0 协议"（与 LICENSE 冲突）
- ❌ "商业版包含开源核心的商业授权"（核心本来就免费，不存在这种授权）
- ❌ "购买后获得全部代码所有权"（实际只获得商业模块使用权 + 核心的开源许可）
- ❌ "永久闭源"（无法对已开源核心做到）
